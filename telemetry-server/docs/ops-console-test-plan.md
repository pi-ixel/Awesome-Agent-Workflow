# 运营后台测试用例（联调环境）

面向 `telemetry-server` 运营后台与 portal 的手工/GUI 验收用例。目标是把
"能用"与"好用"分开看：功能是否闭合、易用性是否顺手、界面文案是否说人话。

## 一、环境与数据准备

| 项 | 值 |
| --- | --- |
| 应用地址 | `http://<host>:18081/admin`（运营后台）、`/portal/`（看板） |
| 后端 | `aaw-telemetry`（uvicorn:18080），MySQL 5.7，归因 mock 引擎:8010 |
| 管理员密码 | `AAW_TELEMETRY_ADMIN_PASSWORD`（联调默认 `123456`） |
| 数据预置 | `telemetry-server/tools/seed_integration_demo.py` |
| 数据清理 | `telemetry-server/tools/clean_integration_demo.py` |

预置脚本按真实工作流"生长"数据：一条 SR 从 `sr-init` 走到 `task-dev`，
每条 AR 挂真实 task-dev 产出，人员—仓库—组件—AI Master—时间线互相对应。
归因引擎是 mock（恒返回 80% 采纳），故"低采纳/重试中/失败"三种状态由脚本在
真实归因行上定点修正，其余全部走真实上报与归因链路。

```bash
cd /opt/aaw-telemetry && set -a && . /etc/aaw-telemetry.env && set +a
.venv/bin/python tools/seed_integration_demo.py http://127.0.0.1:18080
```

预置后应命中 11 条内置检测规则（可用脚本末尾的评估输出核对）。

## 二、用例清单

### A. 功能（闭环类）

| 编号 | 前置 | 步骤 | 期望 |
| --- | --- | --- | --- |
| F01 | 已登录管理员 | 异常管理 → 规则管理 → 一键全部启用 → 立即检测 | 11 条规则全部"检测中"，评估结果各规则命中数非零 |
| F02 | 有命中异常 | 异常总览选某 AI Master 范围 | 卡片合计 = 各分类之和；表格仅列该范围事件 |
| F03 | F02 | 切换"异常类型"到某分类 | 表格与卡片同步过滤；无命中时显示空态 |
| F04 | 有事件 | 事件行"查看详情" | 抽屉展示影响对象/仓库/当前数值/判定阈值/证据，底部链接可跳对应业务页 |
| F05 | 有事件 | "申请屏蔽"→填理由→确定 | 行变为"屏蔽待审"；审核列表出现待审记录 |
| F06 | F05 | 异常管理 → 屏蔽审核 → 通过 | 目标数据被归档（工作流软删/产出屏蔽），事件转 recovered，下一轮检测不再出现 |
| F07 | 有工作流 | 工作流页"申请屏蔽"→填理由 | 审核列表出现"业务页发起"记录（source=admin_console，无关联事件） |
| F08 | 有事件 | 事件行"提问题"图标 | 新标签页打开问题许愿池，提出人预填为该事件所属 AI Master 名 |
| F09 | 规则管理 | 任一规则"编辑"→改参数→试算影响 | 试算返回预计命中对象数；保存后版本号+1 且审计留痕 |
| F10 | 规则管理 | 新建与内置同检测类型的规则 | 平台级范围应被唯一约束拒绝（409），不产生重复规则 |
| F11 | 组件页 | "查工作流"下钻 | 跳到工作流页并带上该组件/时间窗筛选 |
| F12 | 归因页 | 积压体检色块点击 | 跳到归因记录并套用对应状态筛选 |

### B. 易用性

| 编号 | 步骤 | 期望 |
| --- | --- | --- |
| U01 | 仓库归属搜索框输入一个排在第二页的仓库名 | 能搜到（应为全量搜索，不是当页搜索） |
| U02 | 异常总览选范围后刷新页面 | 查看范围被记住，无需重选 |
| U03 | 未选查看范围直接进异常总览 | 提示"还没选择查看范围"，不默认顶一个别人的范围 |
| U04 | 任一列表切页 | 分页文案、总数、空态一致 |
| U05 | 各页面"用户"列 | 展示口径一致（姓名+邮箱，或至少姓名），不混用裸邮箱 |
| U06 | 屏蔽审核列表 | "屏蔽对象"可辨识（带仓库/SR 等上下文），而非裸 UUID |
| U07 | 异常列表"持续时间" | 新鲜异常显示到分钟/小时可读；不应出现"0 小时"这类无信息展示 |
| U08 | 所有时间列 | 与浏览器本地时区一致（与工作流页/看板同源） |

### C. 界面描述与文案

| 编号 | 步骤 | 期望 |
| --- | --- | --- |
| C01 | 逐页读标题、说明、空态、提示 | 无开发注释、无内部术语、无自述实现方式的句子 |
| C02 | 规则页/详情/编辑的"判定条件" | 参数单位齐全、无裸参数名（如 `window_days`）、无重复量词 |
| C03 | 空态文案 | 区分"没选范围"与"范围内无异常"，不可复用同一句 |
| C04 | 全站术语 | 同一概念用词一致（如"屏蔽/归档""AI Master/负责人"） |

## 三、本轮执行结果

首轮发现 7 个问题，均已修复并在联调环境复验通过（commit `a7634a2`、`9a1ffd1`）：

| 级别 | 编号 | 位置 | 现象 | 修复 |
| --- | --- | --- | --- | --- |
| 高 | BUG-1 | `services/anomalies.py` | 异常模块时间字段返回无时区 UTC，前端按本地时间解析，全部时间/时长偏差一个时区（东八区差 8h） | payload 时间统一走 `_iso()` 输出 `+00:00`；测试断言时区 |
| 中 | BUG-2 | `AN_PARAM_META` | "近 30 内" 缺单位 | `window_days` 补进参数元数据 |
| 中 | BUG-3 | `AN_PARAM_META` | 规则详情/编辑表单显示裸参数名 `window_days` | 同 BUG-2，同源修复 |
| 中 | BUG-4 | `DetectorSpec.adoption_drop.sentence` | "60 行 行有效代码" 量词重复 | 句尾改为 `{min_lines} 有效代码` |
| 中 | UX-1 | 异常总览"用户"列 | 显示裸邮箱，与其他页面口径不一致 | payload 补 `user_name`（邮箱反查最近上报姓名），列表/详情按"姓名 + 邮箱"显示 |
| 低 | UX-2 | 屏蔽审核"屏蔽对象" | 裸 UUID | payload 补 `target_context`（仓库 · SR），UUID 缩为辅助小字 |
| 低 | UX-3 | `anDuration` | 取整到小时，新异常显示"0 小时" | 不满 1 小时显示分钟 |

复验要点：异常详情"最近一次检测"、审核列表时间均为正确本地时区；新检出的异常时长以分钟显示；规则详情参数显示"统计窗口 30天"；审核对象显示"工作流 / awesome-agent-workflow · SR-9112"。
