# 组件采纳率统计范围调整

**关联 Issue**：#131  
**状态**：已实现

## 目标

页面采纳率只统计已纳入 `projects.yaml` 的组件，同时在概览页“组件明细”中保留所有实际上报组件。未纳入配置的组件按真实名称逐行展示，并标注“未纳入统计”。

## 统计口径

组件是否纳入统计，以其上报的仓库名能否在 `ProjectRegistry` 中精确匹配为准。配置项的 `enabled` 状态不影响该判断。

| 页面数据 | 处理方式 |
|---|---|
| 总览采纳率、趋势、人员采纳率 | 只聚合已纳入统计组件的有效代码行和归因行 |
| 测试看板 MR 采纳率 | `mr_commit_lines`、归因行只聚合已纳入统计组件 |
| 组件构成图 | 只使用已纳入统计的组件 |
| 概览页“组件明细” | 保留全部实际上报组件 |
| 未纳入统计组件的采纳率 | 返回空值，前端显示 `—` |

工作流次数等非采纳率指标保持现有口径，不因组件未纳入统计而丢失原始上报记录。

## 后端改动

在 `/dashboard/projects` 返回的每个组件记录中增加：

```json
{
  "included_in_statistics": true
}
```

未匹配 `projects.yaml` 时该字段为 `false`。这类记录继续返回真实的 `project_key`、使用次数和代码量，但 `attribution_rate_80`、`attribution_rate_90` 设为 `null`。

总览、趋势、人员汇总和测试看板计算采纳率前，先按 `included_in_statistics` 对对应的开发记录进行过滤。组件明细列表不做该过滤。

## 前端改动

概览页“组件明细”读取 `included_in_statistics`：

- 已纳入统计：保持现有展示。
- 未纳入统计：保留真实组件名称，在名称旁显示橙色标签“未纳入统计”。
- 未纳入统计行使用浅色提示背景，两个采纳率单元格显示 `—`。
- 排序、分页以及使用次数、生成代码量、合入代码量继续正常展示。

页面不增加顶部汇总提示，不使用“未归类组件”或“未纳入 projects.yaml”文案。

## 不改范围

- 不阻止未配置组件继续上报遥测数据。
- 不自动修改 `projects.yaml`。
- 不修改独立“组件使用情况”页面的 `__unassigned__` 汇总逻辑。

## 验收标准

1. 同时存在已配置和未配置组件时，总览与趋势采纳率只由已配置组件的数据决定。
2. 未配置组件仍出现在概览页“组件明细”中，并显示“未纳入统计”标签。
3. 未配置组件的采纳率显示 `—`，原始使用次数和代码量仍可查看。
4. 人员及测试看板的采纳率不包含未配置组件的数据。
5. 页面不出现额外的顶部提示，组件名称不被替换为“未归类组件”。
