# Desktop 诊断与日志

从顶栏帮助菜单选择“打开诊断”，或在输入框执行 `/diagnostics`。诊断在独立系统窗口中打开，可拖到其他显示器；重复打开会聚焦已有窗口。关闭诊断不停止主窗口的日志采集，退出主窗口时诊断窗口一起关闭。

## 日常定位

1. 打开诊断，在主窗口复现问题。
2. 用级别、模块、关键词和起始时间筛选。`session` 记录会话打开，`acp` 记录请求，`acp-native` 记录原生进程，`host` 记录文件/终端等原生调用，`desktop-update` 记录后台更新状态。
3. “日志”合并运行日志和 ACP 事件；消息右侧的详情列直接显示上下文，单行省略、不自动换行。鼠标悬停或键盘聚焦详情可在浮窗查看、选择和复制完整字段；点击“关联操作”将操作 ID 填入统一关键词搜索框，查找同一操作的开始、结果与耗时。ACP 请求同时提供连接标识、请求编号和可用的会话编号，原生进程提供句柄和 PID。
4. “暂停跟随”冻结当前显示，后台仍采集并落盘。暂停后可加载更早记录；恢复实时跟随后返回最新记录。实时列表最多显示 2000 条，历史浏览最多显示 5000 条；导出不受界面条数限制。
5. 点击“导出匹配日志”，选择新的 `.jsonl` 文件。导出使用当前筛选，包含保留期内的匹配记录，而非仅导出屏幕上的行。为防止覆盖文件，目标已存在时会报告错误，请换一个文件名。

“性能”和“运行时”展示主窗口的快照，每 2 秒刷新。超过 10 秒未更新会提示数据过期；诊断窗口不会创建 Agent、加载项目或运行归档调度。性能展示主窗口最近的 JS 堆内存采样，环境不支持读数时明确提示。

## 详细日志与保留

- 默认持续采集 debug/info/warn/error，包括高频原生读写及 ACP 协议事件；关闭诊断窗口和重启均不会关闭详细采集。重要操作记录开始、结束、失败和耗时。
- 无需开启临时详细模式。协议事件记录方向、方法、请求编号等元信息；详细日志可记录截断并脱敏的 Agent stderr 摘要。ACP 收发报文行另以 `acp-raw` 记录原文，按原文保存，不重新序列化或进行正文脱敏；保留的是传输层分帧后的文本，不包含行终止符。
- 日志由原生进程统一写入 `app_log_dir()/diagnostics/` 下的 JSONL 分段文件。按大小与日期滚动，自动清理超过 7 天的旧分段，总量上限 100MB。导出文件由用户自行管理，不计入运行日志配额。
- 前端每 250ms 批量提交增量，使用有界队列。原生后台线程写盘；诊断按游标增量查询，避免跨窗口反复复制完整日志缓冲。查询关键词有短暂防抖。写入队列拥塞或磁盘失败会在诊断中显示，日志异常不应中断业务操作。
- 正常退出和更新安装前会尝试排空日志队列；系统强杀或进程崩溃时，最后尚未提交的少量日志可能丢失。重启可读取已落盘历史，损坏的未完成末行会被跳过。

## 内容边界

普通结构化日志的采集入口和原生写入端处理敏感字段、Bearer 凭据及 URL 查询参数。ACP 原文是明确的例外：完整保留消息、工具参数、图片 Base64 及报文内可能出现的凭据。字符串、嵌套深度、上下文大小和批量大小均有上限。导出包含匹配记录的 ACP 原文，普通日志仍使用脱敏记录；诊断日志不会自动上传到服务器。

日志中仍可能包含项目路径、会话编号和系统错误信息，向他人分享前可通过关键词与时间范围缩小导出范围。

## Git 悬浮卡与审查页

- 在日志中筛选 `git-native`：程序发现记录实际 Git 可执行路径和版本；失败记录包含 `stage`、`cwd`、命令、退出码和错误，命令失败还记录耗时。仓库路径解析、状态解析、统计降级和单文件差异失败分别记录。
- Git 子进程清理 `GIT_DIR`、`GIT_WORK_TREE`、`GIT_INDEX_FILE` 等仓库环境变量，保持查询与所选项目一致。发现顺序为绝对路径环境变量 `AAW_GIT_BINARY`、PATH、Windows 常见安装目录；不可启动、版本检测失败或超时的候选会被跳过。修改路径后重启 Desktop 生效。
- 暂存或未暂存行数统计失败时，文件列表继续显示；对应行和汇总显示“统计暂不可用”，不以零代替未知值。文件差异独立加载，成功刷新后恢复正常统计。
- 原生回归：`cargo test --locked --lib panel_git -- --test-threads=1`。可只为测试进程设置 `AAW_GIT_BINARY` 指向待验证的 Git；覆盖环境污染、候选回退、子目录、中文路径、worktree、统计失败与恢复。

## 开发验证

- 前端：`tests/plugins/diagnostics/diagnosticsCapture.test.ts`、`tests/shared/logPrivacy.test.ts`、`tests/plugins/diagnostics/DiagnosticsWindow.test.tsx`，以及 ACP、宿主调用与更新相关回归用例。
- 原生：`cargo test --locked --lib diagnostics::tests`，覆盖历史读取、过滤分页、重启序号、脱敏、损坏末行、滚动及容量/日期清理。
- 手动验收：同时操作主窗口与诊断窗口；重复打开、关闭再打开；暂停显示期间触发操作后恢复；重启后查询历史；确认默认显示 debug 日志且超过 30 分钟仍持续采集；悬停详情并复制；验证导出内容与当前筛选一致。

## ACP 原文查看

- 收发报文在协议解析/归一化前记录；未知字段、原有空格、字段顺序和非法 JSON 输出也保留。发出的报文在 transport 写入成功后记录。
- 在「日志」按模块 `acp-raw` 筛选；详情包含连接、方向、请求编号、会话编号（报文提供时）、采集时间和字节数。带请求编号的记录可按关联操作查找请求日志。
- 点击「查看原文」按需加载并可复制；不恢复旧 ACP 流量页签。列表查询不携带报文正文；正文超过保留期被清理时显示明确错误。
- 原文与日志一起按 7 天/100MB 轮转清理，导出匹配 JSONL 时包含 `raw` 字段。前端待写队列限制为 2000 条/64MB，原生原文待写也限制为 64MB；拥塞会报告未保存/重试，强杀前尚未提交的报文可能丢失。
- 接收协议行原有 16MB 上限仍生效；原文保存单条上限为 32MB，以容纳发送时多图 Base64 报文；正文不再受旧内存流量缓冲 16K 字符的截断限制。保留额度不足时清理旧分段。
