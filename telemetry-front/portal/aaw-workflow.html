01 / 工作流的价值

效率损耗，往往不发生在写代码时。
它发生在信息传递时。

代码越来越容易生成，准确传递意图却仍然昂贵。AAW 让信息不靠人的记忆和转述，而靠连续、可核验的工作流资产传递。

信息在哪里失真AAW 如何保真最终得到什么

不是把文档交给开发，

REPOSITORY BASELINE

仓库级长期基线

架构、规范与 AI 编码约束由所有需求共享，保证每次设计和开发都站在同一事实基础上。

architecture · spec · guidelines
02
SYSTEM REQUIREMENT

SR 级需求资产

原始需求原文、系统设计、门禁结论与流程状态共同保留，任何人都能回到需求起点核验。

source → design → gate → state
03
CHANGE & MODULE DESIGN

AR 与模块设计资产

变更边界、模块责任、详细设计、测试设计和门禁证据在同一 AR 目录中连续继承。

clarify → boundary → detail → test
04
DEVELOPMENT UNITS

开发任务资产

通过门禁的设计被拆成可验收任务；开发从代码仓恢复完整上下文，再提交实现与验证证据。

overview → T01 → T02 → code
原始意图→SR 设计→AR 澄清→模块详设→开发任务→代码与证据共同入库
