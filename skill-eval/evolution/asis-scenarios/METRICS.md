# 指标定义与阈值

所有指标由 `assets/lib/common.py` 的 `measure(sr, anchor_prefixes)` 计算，随每次执行写进
`NOTES` 行的 `metrics` 字段。它们不是平台维度分，而是场景判据的输入——每个场景挑其中若干项设阈值。

## 结构与编号

| 指标 | 计算方式 | 为什么重要 |
|---|---|---|
| `skeleton_rate` | C1–C8 八个固定章节同时出现标题关键词的比例 | skill 要求先把骨架落到文件上，再逐阶段填充。骨架缺失等于把「边查边写」退化成「最后一次性生成」 |
| `substantive_rate` | 非空且非占位（不含「待补充/未完成」）的章节比例 | 只有标题没有内容是最常见的应付形态 |
| `conclusions` / `evidences` | `A\d+` / `E\d+` 去重计数 | 稳定编号是 TOBE 与门禁复用 ASIS 的接口 |
| `traceable_rate` | 同一结论编号在文中出现 ≥2 次的比例 | 编号只在表里出现一次，说明映射是摆设 |
| `mapping_rate` | C3 事实表中，同一行同时含 A 与 E 编号的行占比 | 结论与证据必须同行绑定，否则无法反查 |

## 证据可定位性

| 指标 | 计算方式 | 为什么重要 |
|---|---|---|
| `anchors_valid` | `path#Symbol` 中 Symbol 真的出现在该文件，或 `path:line` 落在文件行数内，且去重后的个数 | 「查过代码」与「编得像」的分界线 |
| `anchor_rate` | 有效锚点 / 全部锚点 | 一个无效锚点就意味着一条无法复核的结论 |
| `c7_density` | C7 证据表中**可定位**的行占比（文件锚点或带结论输出的命令证据） | 证据表常常退化成文件名清单 |
| `c7_file_density` | 其中只靠文件锚点定位的行占比 | 区分「读过代码」与「跑过命令」 |
| `c7_command_density` | 靠命令输出（`go test` / 探针 / `git log`）定位的行占比 | 行为实测同样是可复核证据 |
| `c8_coverage` | C8 追溯矩阵中，带明确覆盖状态（已覆盖/部分覆盖/待确认/不涉及）的**需求行**占比 | 没有状态就只是需求复述 |

### 三类会误伤合法证据的写法（均已处理）

真实产物比夹具灵活得多，直接按正则匹配会稳定误判。这一轮在真实产物上暴露了三类：

1. **细分区间写法**：`manager.go:1-325`（`Session` 21-27、`Load` 50-64、`Save` 66-73）。
   主区间后面括号里的行号区间属于同一文件，必须一并计入锚点，否则一份 300 行的实现
   只被算成 1 个锚点。
2. **裸文件名**：`manager.go:114-120`。文档已声明被分析模块时，裸文件名指向本模块文件。
   解析顺序：全库唯一同名 → 按产物目录反推的模块目录 → 无法消歧则忽略（既不算有效也不
   算无效，避免把合理的写法判成幻觉）。
3. **命令证据**：`go test ./pkg/sessionmanager/ -count=1` → `ok opscopilot/pkg/sessionmanager 1.220s`。
   行为探针与测试输出是 ASIS 最有力的证据形式之一，`c7_density` 必须承认这类行。
4. **C8 附表的行**：C8 章常带 C8.1「覆盖统计」与 C8.2「未纳入范围」两张附表（首列是
   `已覆盖`/`区域`，不是 `R<n>`）。它们本来就没有覆盖状态列，算进分母会把一份完整追溯
   矩阵判成覆盖不足。只统计 `R<n>` 需求行。

## 路径真实性

| 指标 | 计算方式 | 为什么重要 |
|---|---|---|
| `path_truth` | 产物中引用的 `pkg/` `frontend/` `docs/` 路径里，真实存在于工作区的比例 | 虚构路径是最容易发生也最容易被读出来的幻觉 |

豁免规则：整行出现「不存在 / 已删除 / 缺失 / 未实现」时跳过该行（这是有价值的陈旧引用发现）；
某路径前后 16 字符内出现「临时 / 副本 / 探针 / 自建」时豁免该路径（这是自建验证文件）。
早期版本按整行豁免，导致「文档说 Save 用临时文件 + rename」把同行的真实路径一起放过，已修正。
产物里以仓库根为锚的 `/pkg/...` 会在计数前规范化为 `pkg/...`。

## 漂移与职责

| 指标 | 计算方式 | 为什么重要 |
|---|---|---|
| `drift_items` | C6 的表格行数，与漂移类关键词出现次数取较大值 | 只在 S4 使用，要求 ≥3（文档有三处反向承诺） |
| `formal_docs` | `.sdd/**/模块详细设计说明书.md` 的份数 | ASIS 不得创建正式说明书，必须为 0 |
| `extra_files` | 产物目录下除 context / requirement / `.context/reviews/` 外的文件数 | 顺手多写几份文档也是越界；`reviews/` 是平台独立评审工具的落盘位置，不算越界 |
| 代码区未改动 | `file_unchanged(path)` 对比 HEAD 字节 | 只读分析的过程约束，无法判定时不计失败 |

## 冗余诊断（不定阈值）

| 指标 | 计算方式 |
|---|---|
| `prose_repeat` | 去掉表格与围栏代码后，正文 30-gram 重复覆盖率 |
| `sentence_dup` | 长度 ≥24 的重复句占正文比例 |
| `meta_mentions` | 「本 skill / 阶段产出 / SubAgent / 固定目录 / 工作流程 / 模板 / 检查清单」出现次数 |

这三项在场景矩阵里只作诊断输出，不设阈值——经济性由 `evolution/asis-slim/` 的 C 套专门度量，
避免两套判据互相牵制。场景矩阵要的是「能力边界」，不是「成本」。

## 防误判的四条规则

真实产物比合成夹具灵活得多，直接词面匹配会稳定误伤。这一轮在真实产物上暴露并修掉了：

1. **固定目录标题不是结论**。`### C6.2 ASIS 阻塞项` 是模板的一部分，下面写「不适用」
   才是结论。判定阻塞时标题行要看下一句，不能只看标题本身。
2. **假设语气不是现状**。「改变返回值形态（如返回副本）会同时影响 Wails 序列化」是在
   描述契约变更影响，不是声称现在返回副本。`如/改为/若改/例如` 开头的短语整体跳过。
3. **豁免必须贴着对象**。见上节路径豁免。
4. **阻塞不等于越界**。S2 允许模型因需求口径缺口（导出是否带凭据、去重键是什么）写
   `部分完成` + 阻塞项，这是 skill 明确要求的降级出口；只有「因为找不到对象所以阻塞」
   才是失效模式，用 `blocked_on_missing()` 要求同一行同时出现「阻塞 + 该对象 + 不存在」。

同理，`wrong_claim()` 逐行扫描而不是整篇匹配，并跳过含 `决策输入|TOBE|可选|待确认|是否|建议`
的行——决策点表格不是现状断言。

## 阈值的取法

阈值都是相对于本地合成的合格样本定的：合格样本必须 ≥85（实际均为 100），定向失真样本必须 ≤65。
`smoke_test.py` 就是这条规则的执行器，每次改断言都必须跑通，否则不能建套。
合格样本与失真样本都是人写的，因此它们只能证明「断言能区分这两类写法」，
不能证明「真实模型一定会被区分」——后者要靠真实执行结果来验证。
