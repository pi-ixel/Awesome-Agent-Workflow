# task-dev

## 定位

根据 `overview.md` 中一个明确的 `T[N]` 任务完成开发和交付。任务计划只提供目标、范围、权威引用、依赖和状态，不承载技术设计。

每次开发必须直接读取：

- 已通过门禁的模块详细设计说明书；
- 模块测试用例设计；
- 模块设计门禁结果；
- 当前模块组的 `overview.md`；
- 软件架构，以及仓库存在时的 Spec 和 AICodingGuidelines。

详细设计是实现设计的唯一事实来源，测试设计是验证规格的唯一事实来源。不得以任务标题、overview 摘要、前置任务总结或模型推断替代权威文档原文。

每次调用只处理工作单指定的一个 Task；完成后停止，由 AAW Workflow/CLI 在新上下文中调度下一个 Task。

## 输入

标准输入目录：

```text
.sdd/{SR}/{AR}/
├── {AR}-{需求短名}-{模块组名}模块详细设计说明书.md
├── {AR}-{需求短名}-{模块组名}模块测试用例设计.md
├── {AR}-{需求短名}-{模块组名}模块设计门禁结果.md
└── {模块组名}_tasks/
    └── overview.md
```

附加输入：

- `.sdd/software_architecture.md`：必需；
- `.sdd/spec.md`：存在时必读；
- `.sdd/AICodingGuidelines.md`：存在时按其中研发流程执行。

### 旧格式兼容

旧工作流可能仍把 `T[N]-[任务标题].md` 作为输入。兼容期内允许读取它来识别旧任务范围，但必须同时定位并完整读取详细设计、测试设计和门禁结果；发生冲突时始终以权威文档和当前 `overview.md` 为准。旧任务文件不得继续作为设计事实来源，也不得写回实现总结。

## 单 Task 执行纪律

- **锁定当前 Task**：只实现、验证和总结工作单传入的 T 编号，不选择或启动其他任务。
- **overview 管计划**：从 overview 校验任务目标、范围、引用、串行位置、前置任务、状态和挂账用例。
- **权威文档管设计**：完整阅读详细设计和测试设计，再使用当前任务的引用聚焦相关设计点和用例。
- **门禁不通过则停止**：门禁结论不是“通过”时不得开发。
- **前置条件不满足则停止**：当前任务不是应执行任务、真实前置任务未完成、关键引用缺失或相互冲突时不得开发。
- **设计变化回流**：发现权威设计需要修改时，停止实现并返回 TOBE、测试设计和门禁阶段；不得在 overview 或代码中擅自改写设计。
- **核心验证必须通过**：不得把当前任务主要实现或全部主要验收挂账给后续任务。
- **完成后停止**：更新 overview 并回调 AAW 后结束，不读取或开发下一个任务。

## 开发流程

### 1. 开工检查

1. 完整读取 `overview.md`，按工作单的序号和标题定位当前任务。
2. 确认计划格式、任务编号、标题、状态、串行位置和前置任务一致。
3. 当前任务状态必须为 `Pending` 或 `In Progress`，并且是串行顺序中当前应执行的任务。
4. 所有真实前置任务必须为 `Completed`；读取其执行记录中的实际变更、设计偏差和后续须知。
5. 完整读取模块设计门禁结果，确认结论为“通过”，且对应同一 SR、AR、需求和模块组。
6. 完整读取模块详细设计说明书和模块测试用例设计，不得只读取 overview 引用的小节。
7. 使用任务的设计引用和测试引用核对目标及范围；每个引用必须能在权威文档中定位。
8. 检查 Open Questions 和与当前任务相关的挂账项；存在阻塞问题时停止并向用户报告。
9. 将 overview 中当前任务状态更新为 `In Progress`。用户只要求预览时不更新。

### 2. 加载研发规范

检查 `.sdd/AICodingGuidelines.md`：

- 不存在：使用本 Skill 的内置开发流程。
- 存在：完整读取 `# AI 研发规范` 下的 `## 代码开发流程` 并执行。
- 自定义流程可以补充工程步骤，但不能取消设计实现、测试落地、核心验证、自审、修改后重新验证和交付记录。

### 3. 对照权威设计实现

1. 根据当前任务目标、实现范围和设计引用，从完整详细设计中确定相关决策、契约、流程、异常处理、配置、风险和非功能约束。
2. 根据详细设计中的工程落点定位实现代码、测试位置和直接依赖；只对当前范围进行必要探索。
3. 对照当前代码事实实施，不重新命名契约、不丢字段、不简化流程、不改变异常语义。
4. 不提前实现后续 Task，不做无关重构。
5. 如果设计与代码事实冲突且无法按设计实现，暂停并报告；不得用代码现状静默覆盖已评审设计。

### 4. 落实测试设计

1. 从完整测试设计中定位当前任务负责的全部测试用例和覆盖目标。
2. 将用例的前置条件、步骤、输入、预期结果、断言和后置条件落成自动化测试。
3. 项目无测试框架或用例不适合自动化时，生成可执行的手动验证清单。
4. 只有补充性验证且明确记录依赖、当前不可执行原因和最终责任 Task 时才可挂账；核心验证不得挂账。
5. 执行当前任务测试并逐项核对权威测试设计中的预期结果。
6. 测试失败时优先修复实现；确认测试设计与代码事实冲突时停止并回流，不得修改测试迁就错误实现。
7. 清理测试数据并恢复环境状态。

### 5. 约束自审和工程检查

正确性验证通过后，对本次实际变更定向检查：

1. 读取 `.sdd/software_architecture.md` 中当前模块、直接依赖和相关边界，检查职责和依赖方向。
2. 读取 `.sdd/spec.md` 中与本次语言、代码类型和测试相关的条款；文件不存在时记录跳过。
3. 执行 AICodingGuidelines、仓库脚本或项目说明要求的 CodeCheck、lint、静态分析、类型检查和构建。
4. 审查正确性、可读性、职责划分、重复代码、错误处理、日志、指标/追踪和可维护性。
5. 仅在设计存在明确性能目标或实现出现明显性能问题时优化性能。
6. 修复不能改变已评审设计；需要改变设计时停止并回流。

### 6. 修改后重新验证

自审、优化或修复改变代码后，重新执行：

- 当前任务的所有非挂账测试或手动验证；
- 受影响的 CodeCheck、lint、静态分析和类型检查；
- 研发流程要求的构建或专项检查。

任何核心测试或必需检查失败时不得完成任务。

### 7. 完成判定

当前任务只有满足以下条件才可标记 `Completed`：

- 实现符合详细设计中当前任务引用及其相关上下文；
- 当前任务负责的非挂账测试用例均已落地并通过；
- 相关架构、Spec、研发规范和工程检查通过；
- 修改后重新验证通过；
- 不存在未经批准的设计偏差；
- 挂账项满足限制条件并有最终责任 Task；
- overview 的状态、挂账登记和执行记录已更新。

### 8. 更新 overview

在 `## 执行记录` 中按模板追加或更新当前任务记录：

```markdown
### T[N]：[任务标题]

- 状态：Completed / Blocked
- 修改文件：[文件列表；阻塞时写“无”]
- 核心实现：[实际完成的实现摘要；不得复制设计正文]
- 验证结果：[测试用例、命令和结果]
- 工程检查：[CodeCheck、静态检查、构建等]
- 设计偏差：无 / [冲突说明；存在未批准偏差时不得标记 Completed]
- 遗留与后续任务须知：[仅记录后续任务需要消费的信息]
```

同时更新：

- 任务计划表中的当前状态；
- 当前任务新增或已回归的挂账用例；
- 与当前任务相关且已解决的 Open Questions；
- 阻塞时的原因和需要回流的阶段。

不创建或更新 `T[N]-*.md` 文件，不另造过程文档。

### 9. 收尾：回填 overview 并回调工作流（不可跳过）

代码开发、测试和自审完成后，本任务还没有结束。**当前任务处于 aaw-workflow 串行调度中，必须完成以下三步收尾，缺一不可**——只做完代码和测试就回复，任务不会被调度推进：

1. **回填 overview**（步骤 8 的内容）——更新任务状态、执行记录、挂账项。
2. **构造完成数据**——按工作单 `data_schema` 字段（`task_id`、`workflow_source`、`implementation`、`tests`、`review_and_optimization`、`revalidation`、`checks`）填写当前任务的完成证据。
3. **执行工作流回调**——执行工作单的 `commands.done` 提交完成数据。执行成功才算任务真正完成；`deliverables_exist: true` 只表示文件存在，不能替代完成证据。

回调提交后本任务即结束，后续的放行、等待确认或触发下一个任务由工作流调度决定，不在本 skill 职责内。

**容易遗漏的原因与对策**：开发量大时注意力集中在代码上，容易忘记收尾。对策是强制顺序——回填 → 构造数据 → 回调，一步都不能少。完成检查清单中「overview 已更新」和「CLI 回调已执行」是两项独立的硬检查，缺一不得回复完成。

## 输出规则

- 代码遵循项目现有风格、详细设计和相关 Spec。
- 设计和测试事实只引用权威文档，不复制到 overview 执行记录。
- 用户只要求预览时，不修改代码、overview 状态，也不执行 AAW 完成回调。
- 最终回复聚焦当前任务的实现、验证、挂账和风险，不自动开始下一任务。
