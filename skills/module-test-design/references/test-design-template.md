# 模块测试用例设计模板

使用本模板创建或更新模块目录下的《模块测试用例设计.md》。本文件是独立测试设计成果物，基于同目录正式《模块详细设计说明书.md》中的 TOBE 设计和可测试性输入生成；不得替 TOBE 补设计，不得拆分 AICoding 任务。

正式测试设计只输出验证结论，不记录目标抽取、风险分级、候选用例、用例合并、淘汰理由等推导过程。Gate 会基于本文件的最小充分测试集、覆盖矩阵和缺口反查测试设计质量。

## 排版约定

第 3 节「最小充分测试用例集」是用例正文，**不得使用任何表格**——每条用例必须是一个独立的列表条目（`##### TCn`），用列表逐项列出字段。表格只允许在第 2 节（用例总览）、第 4 节（覆盖矩阵）和第 5 节（缺口）中使用。

第 3 节的分层结构：

- `### 3.x <测试层级>`：顶层按测试层级分组（单元 / 模块内功能集成 / 契约 / 兼容回归 / 数据迁移 / 配置开关 / 观测性 / 风险专项 / 人工验证等）。**只建立本次设计能支撑的层级**，不强求把每个层级都列出来；能做模块内功能集成甚至端到端的，就建对应层级分组，没有就省略。
- `#### 3.x.y <功能点 / 场景标题>`：层级下按功能点或场景分组，标题自定。
- `##### TCn <用例简述>`：场景下每个用例一个条目，用列表逐项列出字段。

## 2. 用例总览

按验证场景分组的树状概览。评审者扫一眼就能判断覆盖全不全——每个场景大类下有哪些用例、有没有明显漏测的场景。场景大类应反映设计的主要验证维度（正常路径、失败路径、边界条件、兼容回归、并发安全等），不强求固定分类。同一大类下相关用例紧挨在一起。

**正常路径**
- TC7：SetTags 设置标签后落盘并可读回
- TC15：match=any 任一命中返回匹配脚本
- TC16：match=all 全部命中才返回

**失败路径**
- TC8：脚本不存在返回 error 且无文件副作用
- TC18：存储目录不存在返回空列表不报错

**边界条件**
- TC2：normalizeTags 空输入返回 nil
- TC9：标签 Trim/去空/去重后落盘
- TC10：覆盖式更新（整体替换非追加）
- TC11：清空标签后文件不写 tags 字段
- TC17：空/全空白入参 → 返回全量脚本

**兼容回归**
- TC5：NewScript/CreateScript 构造产出 Tags=nil
- TC19：旧脚本加载 Tags=nil，重写不新增 tags
- TC22：旧文件无 tags 字段加载成功

**并发安全**
- TC24：并发 SetTags/GetScriptsByTags 在 -race 下无竞态
