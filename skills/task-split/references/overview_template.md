## 执行规则

- 详细设计文档是实现设计的唯一事实来源，测试用例设计文档是验证规格的唯一事实来源。
- 本计划只定义任务目标、范围、权威引用、依赖和状态，不承载或改写技术设计。
- 开发每个任务前必须完整读取详细设计、测试设计和门禁结果；任务引用只用于定位当前关注范围。
- 按串行执行顺序逐个执行，编号与顺序一致；同一时刻只开发一个任务。
- 当前任务的核心实现和核心验证通过后才可完成；补充性挂账用例不阻断后续任务，但必须由最终责任任务完成回归。
- 详细设计或测试设计发生变化时，停止开发，返回设计门禁并重新生成、确认任务计划。

## 执行记录

本节由 `task-dev` 在每个任务完成或阻塞时更新。`task-split` 只保留本说明，不预填实现结论。

每个任务使用以下结构追加一次：

```markdown
### T[N]：[任务标题]

- 状态：Completed / Blocked
- 修改文件：[文件列表；阻塞时写“无”]
- 核心实现：[实际完成的实现摘要；不得复制设计正文]
- 验证结果：[测试用例、命令和结果]
- 工程检查：[CodeCheck、静态检查、构建等]
- 设计偏差：无 / [冲突说明；存在未批准偏差时不得标记 Completed]
- 遗留与后续任务须知：[仅记录后续任务需要消费的信息]
```
