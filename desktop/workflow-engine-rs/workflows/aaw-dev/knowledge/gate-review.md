# 轻量设计门禁

独立、只读地检查设计和测试设计是否足以进入任务拆分。以当前被检查的产物版本为准；必要时对照需求及可访问的项目事实，不修改两份产物。

逐项判定：

1. 决策已收敛：目标、范围、不做事项和选定方案清楚，没有影响实现或验证的未决问题。
2. 代码论断可追溯：有关现有代码的关键论断有文件行号或等价定位，影响面经过查证。
3. 契约与验收可执行：变更契约足够完整，测试设计覆盖每条验收和每项契约，关键缺口没有被掩盖。

输出 `decision`、`report`、`issues` 和 `safe`：`pass` 表示三项达标且无阻断；`revise` 仅用于所有问题均能在既有授权内明确修复，此时 `safe` 为 `true`。需要事实、取舍或权限时在当前会话提问并等待答复，之后继续检查。报告和问题说明使用文本，注明证据、影响、整改对象和修复方向。输入或证据无法确认时应如实说明，不得虚构通过结论。

门禁检查设计和测试之间的交付闭环；不重复审查设计阶段是否按规定发问等过程细节。报告写结论、三项判定、未达标项和阻塞，不复述两份设计。
