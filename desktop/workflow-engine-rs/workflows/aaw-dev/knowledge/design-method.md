# 轻量设计方法

## 目标与边界

将需求收敛成一份足够下游测试设计、任务拆分和开发使用的设计。设计深度随需求复杂度变化；不要为追求篇幅而遗漏必要细节。唯一设计产物通过宿主提供的产物能力交付，存储位置由宿主决定。

设计时在当前可访问的项目环境和上下文中查找与需求相关的已有设计和架构信息；存在已有设计时，先评估并复用仍有效的信息和用户已确认的答案，再按本次需求完整执行。无法访问或无法确认的信息如实说明，不得凭空补齐。工作流入口与调用方式由宿主负责。

## 问题池与设计

使用本次工作流的问题池记录和查询待查问题、用户提问与回答；取证、用户问答与方案推导根据发现交替进行。先查询已有记录，避免重复提问；在设计中引用相关决策和取证证据。不得把用户尚未同意的推荐答案当作决定。

1. 读取可用的需求和架构信息；架构缺失不阻断，结合需求与代码结构推断探索边界，并在设计中记录没有架构基线。形成初始问题池，将需求直接关联的代码位置纳入第一批取证。
2. 将能从代码确认的问题纳入取证队列，将需用户决策的问题纳入提问队列。两类问题随证据和回答动态补充，不强制先查完代码再问人。
3. 将相关代码问题按清单批量取证。宿主支持只读 SubAgent 时可委托；否则由当前 Agent 按清单只读取证。关键结论附文件与行号或等价定位，无法确认的内容明确标记，不做无关范围的漫游。
4. 根据问题依赖整理当前可问的决策，一轮提出全部当前前沿，每题给出推荐答案及依据，等待用户逐题明确表态；用户明确授权自行决定时，选择最简单可行的方案并记录理由。回答和证据可能引出下一轮问题。
5. 两个队列稳定收敛后，按模板完成设计：目标与范围、必要的现状摘要、明确选定的方案、契约变更、经查证的影响面、可判定的需求验收标准和必要的存疑。代码现状论断就近附定位；不编造路径和结论，不写完整实现或无关的全量取证附录。

## 提交前检查

- 只有一份设计产物；未生成额外设计文档；模板占位提示已移除。
- 问题池无待查代码问题、无可问用户决策；取证有批次和问题清单；用户问题按轮提出且未默认采纳推荐。
- 涉及代码改动时有现状摘要；没有架构基线时已说明。方案作出明确选择并给出理由，不留未决备选。
- 方案、契约和影响面中的代码现状论断有明确定位；影响路径已查证。契约逐项写明名称、位置、签名或字段、类型、调用方、错误语义和兼容策略。
- 验收标准覆盖需求目标，每条能判断验证方式和预期结果；工程测试用例交给下游测试设计。
- 没有阻断实现的未决问题；其他存疑如实记录并告知用户。用户已确认设计方向，或设计明确标为草案。

交付设计产物引用，以及问题池状态、用户决策和取证的可用证据引用；没有可验证的过程证据时应明确标记，而不是编造。
