# 轻量测试设计方法

## 输入和边界

已交接的轻量设计是权威输入：方案与契约变更决定验证的行为，验收标准给出需求侧口径。结合任务在可访问的项目环境和上下文中查找相关架构、历史门禁、已有测试设计与项目测试组织；已有成果先评估并复用有效部分，无法访问或确认的内容如实说明。轻量流程不要求严格模式的详细设计三件套。

测试设计是独立成果，不修改设计正文，不拆分开发任务。引用设计中的契约名称、章节或验收标准，不重复维护设计事实。所有重要目标可追溯到设计；不自行发明错误语义、字段、状态、兼容策略或验收阈值。

## 工作方法

1. 核对设计是否可读，方案、适用的契约和验收标准是否足以确定输入、预期和断言。调查项目现有测试目录、框架、Fixture、Mock 和运行方式；新增对象没有旧测试本身不构成缺口，参考相邻组织方式。
2. 从行为闭环、状态和副作用、失败与回退、兼容回归以及设计触发的安全、并发、数据、配置和观测等风险出发，形成最小充分验证集。主路径、关键失败和边界优先；共享前置和观察面的等价输入可合并。一条用例可以覆盖多个目标，行为或隔离边界不同才拆开。
3. 每条用例给出编号、关联的验收或契约、优先级、场景、建议位置、自动化方式、前置、输入、预期和精确的行为断言。不可定位位置时说明原因；只能人工验证时说明理由、操作和通过标准。断言不增加设计未定义的次级排序或其他契约，也不写完整测试实现代码。生产者/消费者兼容验证使用真实生产输出或由生产者生成的 fixture。
4. 用例按项目可支持的测试层级组织；先给按场景归类的用例总览。覆盖矩阵中每条验收标准和每项契约变更至少一行，包含用例、状态、未覆盖原因及「首次可验证阶段」。该列留空，由任务拆分回填；只有端到端才能验证的条目标为「端到端（末阶段）」。
5. 影响测试范围、验收阈值、人工验证边界或回流阶段的未决事项，通过 ACP 当前会话询问；没有确认时记录为待确认，不能自行补齐。设计缺少行为、契约、异常、观察信号或验收口径时，登记缺口并回流设计。无法判断现有测试能力时说明证据缺失和影响；没有框架但能执行人工验证时说明步骤及通过标准。

## 交付与自检

按模板交付范围策略、场景总览、用例、覆盖矩阵和缺口。正式成果只呈现验证结论，不记录候选用例的筛选推导。用例正文使用列表而非表格。测试集是设计阶段的下限，实现阶段发现的新验证面由后续开发环节补充。

对关键需求或契约无法设计有效验证、用户或上游验收互相矛盾、关键风险缺少可观察设计等情况，标记阻塞或部分完成，说明原因、影响目标、回补输入、可继续范围、不得定稿的用例及对门禁的影响。缺口没有消除时不能将测试设计报告为完整通过；保留实际成果供回流和审阅。
