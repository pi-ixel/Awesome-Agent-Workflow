# 轻量任务规划

以通过门禁的设计作为实现事实来源，以对应测试设计的用例为验证规格。按可人工 review 的业务改动拆出有序任务；预计总改动足够小时优先一个完整任务，避免机械按函数、配置或技术层拆成多个难以独立验收的薄任务。300–500 行核心业务代码只是原工作流的审阅参考，不是必须凑满的阈值，复杂度高时取小范围。

生成薄任务计划：每个任务只保留稳定标识、目标、范围、设计与测试引用、依赖、负责的用例编号、出口标准及交接位置。通过引用关联权威设计与测试规格，不把每条用例的输入、预期、断言或设计正文复制到计划中。串行顺序明确；本任务圈定用例通过，且此前任务的用例回归通过。全部验收标准和测试用例都有责任任务；只在端到端才能验证的项目保留末阶段标识。

将测试设计覆盖矩阵中的首次可验证阶段回填为对应任务，输出更新后的测试设计版本及计划引用。测试设计的用例和契约不因此改写；如有无法分配或影响拆分的未决问题，说明并停止回流，不伪造任务列表或自行修改上游设计。无须建立每任务独立文件。任务清单须是非空的有序结构化列表，足以让 Runtime 逐个调度；计划文档保留最终执行记录位置。
