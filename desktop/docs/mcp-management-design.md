# Desktop MCP 管理设计

状态为已确认的实现基线。首版落地 iCode，CodeAgent 兼容方案在首版实现和验收完成后单独评审。

## 1. 页面和操作

「插件管理 → MCP」使用已确认的小卡片设计。当前 Agent 的原生服务、Desktop 保存的服务和 AAW 内置浏览器在同一张网格里展示。普通卡片显示图标、名称、传输方式和操作，重名时用提示替代传输方式。工具栏提供名称搜索、全部状态／已启用／已停用筛选，以及一个「新增 MCP」按钮。筛选依据是配置开关，服务是否已在会话中加载由 Agent 运行时决定。

| 卡片               | 可用操作                                                         | 修改目标                        |
| ------------------ | ---------------------------------------------------------------- | ------------------------------- |
| Agent 原生服务     | 直接启停，点名称或「··· → 编辑」打开浮框，「··· → 删除」二次确认 | 当前 Profile 的原生配置         |
| Desktop 保存的服务 | 直接启停，点名称或「··· → 编辑」打开浮框，「··· → 删除」二次确认 | 当前 Agent 的 Desktop 全局配置  |
| AAW 内置浏览器     | 固定卡片，仅提供启停                                             | 与设置页共用的 Desktop 全局开关 |

新增统一写入 Desktop，默认启用。新增和编辑浮框按传输方式呈现相应字段，HTTP 的手动连接测试也在浮框里完成。已有会话的浏览器重连入口仍在浏览器面板。

## 2. 配置范围和归属

- **Agent 原生配置。** 页面跟随设置中选中的 Agent。有归属于该 Agent 的活动会话时使用其 Profile，否则使用适配器声明的默认 Profile。iCode 在用户配置目录读取当前 Profile 的 `tools.mcp`，默认 Profile 为 Code。管理页的原生卡片以现有用户配置文件为准。
- **Desktop 配置。** 按 Agent 标识存入应用数据目录。同一 Agent 的配置跨项目生效，切换 Agent 后读取对应配置。已有开发版项目级记录保留在磁盘，旧条目停止加载。新增服务使用 Streamable HTTP。
- **内置浏览器。** 设置页和 MCP 页使用同一个持久化开关。关闭立即撤销已有浏览器授权，开启后在新建或重连会话时注册。正在使用的会话通过浏览器面板确认重连。

MCP 插件负责汇总配置和表单操作。普通卡片内部携带来源、目标配置身份和读取版本，编辑、开关和删除按这些信息定位原配置。同名条目的选择和变更也以该身份为准。页面按 Agent 和 Profile 合并并发读取，已读结果在内存复用 3 秒。手动重读和写入前的校验直接读取本地配置。临时 ACP 连接在手动测试时启动。

Agent 的原生读取和修改、ACP 注入能力、HTTP 测试能力由适配器声明。Desktop 配置写入、版本检查和凭据解析复用 Host 原生接口。Project 负责建立会话并调用 MCP 工具提供方。iCode 专属 Profile 字段和测试协议留在 iCode 适配器。

## 3. 保存和冲突

**名称。** 保存前去掉首尾空白，比较时区分大小写，`Docs` 和 `docs` 可以并存。在当前 Agent 和 Profile 的可读配置范围内检查 Agent 原生与 Desktop 条目。已有同名的两张卡片都保留，并标注「名称重复，请修改名称」。新增或改名命中同名时拒绝保存。AAW 内置服务的保留名称规则继续有效。批量预览和提交接口复用同一名称校验。

**部分读取失败。** 保留成功读取的列表。原生配置暂时无法读取时，Desktop 仍可新增或改名，并校验可读范围内的名称。原生配置恢复读取后，重新计算同名提示。

**外部编辑。** 保存前重新校验目标版本和可读取的名称。目标配置在浮框打开期间被外部修改时，拒绝本次写入，保留用户输入，提示重新读取配置。重新读取后由用户核对并再次保存。开关和删除也基于读取版本执行。Agent 或 Profile 切换不会把已打开的编辑提交到新的配置对象。

**传输切换。** Agent 原生服务允许在 HTTP 和 stdio 之间切换。保存时写入新传输的字段，清理旧传输的专用字段。stdio 转 HTTP 时清理命令、参数、工作目录和环境变量，HTTP 转 stdio 时清理地址、HTTP 请求头及 HTTP 专用选项。服务启用状态、通用设置和 Profile 其他内容保留。

## 4. 连接测试和运行时生效

### 浮框内测试

按下「测试连接」时，测试当前输入的 HTTP 草稿，支持新增前和编辑中测试。Desktop 请求头只存环境变量或系统凭据引用，测试时解析。编辑原生服务时，在内存合并原配置和草稿，保持原传输方式时沿用未修改的原生选项。需要的凭据无法从原配置取得时，提示补充。

复用临时 ACP 诊断连接和适配器的 HTTP 测试接口，连接在测试结束后释放。敏感请求、响应和错误信息按现有规则脱敏。测试只改变浮框内的结果，保存仍由用户触发。测试失败可以保存有效配置，格式和命名错误仍需修正。stdio 不提供手动连接测试。

### 会话注入

Agent 声明支持 HTTP MCP 时，Desktop 配置通过 ACP 注入手动会话、工作流节点和定时任务。修改在下次实际建立、加载或重新连接该会话时读取。已连接或复用连接的会话继续使用其连接时的配置。

运行时针对目标会话实际采用的 Profile 核对名称。已知原生同名时，Agent 原生配置优先，跳过该条 Desktop 注入。若原生名称核对失败，仍将 Desktop 的配置交给 Agent 处理冲突，并在诊断中记录核对结果。会话上报的加载状态与管理页的启停状态分别维护。

## 5. 实现和验收

1. **配置和会话层。** 复用原生与 Desktop 持久化，补齐跨来源查重、原生传输切换、HTTP 草稿测试，以及原生名称核对失败时仍提交 ACP 注入的分支。
2. **工作台。** 合并成同一套卡片、筛选、编辑浮框和删除确认，复用浏览器全局开关。按配置身份隔离切换 Agent 或 Profile 前后的异步结果。
3. **验收。** 验证普通卡片的新增、编辑、启停、筛选和删除，内置浏览器的双入口同步和重启保留，原生／Desktop 同名的重复提示与保存拒绝，以及大小写不同的名称可以并存。
4. **边界验收。** 覆盖原生配置读取失败后新增并恢复查重、外部修改时保护草稿、两种传输互切的字段清理、HTTP 测试失败仍可保存，以及手动会话、工作流和定时任务在建立连接时获取正确配置。

CodeAgent 后续评审以实机确认其原生配置位置、启停语义、ACP 注入能力和测试接口为依据。本期通过独立适配器能力承接扩展，沿用统一列表和表单操作边界。
