## 1. 项目定位与当前状态

通过 ACP（Agent Client Protocol，JSON-RPC over stdio）连接本机 chrys
（`icode acp`，原 `chrys acp`）的桌面工作台，承载 AAW 工作流的开发交互。核心流程是
「指定项目 → 创建会话 → 通过 ACP 与 Agent 交互」——AAW 是挂在这条骨架
上的增强（状态显示、入口向导、命令下发），不是必经的强制流程。

- 技术栈：Tauri 2 + React + TypeScript(strict) + Vite + zustand + vitest；
- 质量门：`npm run typecheck / lint / test / build` + `cargo check`
  当前全绿（**494/494 测试**，52 个文件）；
- 已真机验收：ACP 握手、真实模型对话、结构化提问、文件写入、
  会话快照恢复、健康检查、连接失败提示；
- **未 commit**：`desktop/` 整目录处于未跟踪状态，验收后应尽快提交。

## 2. 快速上手

| 依赖                    | 说明                                                           |
| ----------------------- | -------------------------------------------------------------- |
| Node ≥ 24 / Rust ≥ 1.93 | 工具链                                                         |
| chrys 本机安装          | 设置页可指定路径；空路径时应用自动探测（PATH → 常见位置）      |
| uv + AAW skills         | 健康检查会指路；skills 经设置页安装到 `%APPDATA%/chrys/skills` |

```
desktop/dev-web.cmd  # 双击一键启动（= npm run dev:web + 就绪后自动开浏览器）
npm run tauri dev    # 桌面应用（Rust 变更后需重启进程，HMR 只覆盖前端）
npm run dev:web      # 浏览器开发运行时（推荐 UI 迭代与验证的入口，见下）
npm run dev          # 仅前端（无宿主：布局可看，agent/CLI 为内存假数据）
npm run acp:smoke    # 无模型冒烟：握手 → 会话生命周期
```

### dev:web 浏览器开发运行时（2026-10）

`npm run dev:web` 用**浏览器**跑完整应用，数据全部是真的：agent 子进程、
`aaw status/plan` CLI、文件读写、skills 安装、历史会话树、@ 文件提及、
原生目录选择对话框（经 bridge 调 PowerShell）都可用；前端改动 HMR
秒级生效，Playwright 直接打 `http://localhost:1420` 做真机验证。原理：
vite dev server 本身是 Node，内嵌的 dev bridge 插件
（`scripts/devBridgePlugin.ts`，仅 `AAW_DEV_BRIDGE=1` 且 dev server
时生效）把桌面宿主的命令面暴露在同源 `/dev-bridge/*`（HTTP + SSE），
前端在 `HostRuntime` / `ProcessRunner` / `AcpTransport` 三条既有缝后面
换成 bridge 适配器（`src/plugins/host/dev/bridgeClient.ts`）。

边界与纪律：

- **不进产品**：插件 `apply:"serve"` + env 门控；前端分支以
  `import.meta.env.DEV` 折叠，生产构建会把 bridgeClient 整棵摇出产物
  （dist 已验证零残留）。窗口三键 / 关闭守卫在浏览器里自动隐藏或旁路。
- **孤儿防护**：浏览器断开 SSE 10s 内无人回连，bridge 杀掉全部在跑
  agent 进程树（taskkill /T /F），vite 退出同样收口——与桌面端同一
  纪律，防止残留 icode 抱锁拖慢下次启动。整页刷新（F5）会触发杀树，
  会话状态靠重新打开恢复，这是 dev 运行时的已知取舍。
- 进程语义复用 `nodeStdioTransport` / `nodeProcessRunner`（有测试的
  Node 实现），不另写一套；文件列举/chrys 目录解析按 Rust 命令语义
  复刻。

**注意两个 dev 态现象**（打包版不存在）：① exe 偶发早于 Vite 就绪导致
webview 空白，Ctrl+R 即恢复；② HMR 偶发把编辑中间态推给页面并停留
错误覆盖层，touch 一下被报错的文件即可恢复。

## 3. 界面结构（当前定稿）

```
顶栏（上下文条=自绘标题栏，窗口装饰已关）：空白可拖窗 · 右端 [─ ▢ ✕] 自绘窗口控制；会话态：标题 · 连接徽标 ···· [SR-xxx·步骤n] [✕关闭会话]（设置/诊断入口在图标窄栏）
┌──┬────────────────┬─────────────────────────┐
│图│ 项目树侧边栏       │ 内容区（上下文条随形态切换）      │
│标│ · 项目/会话双视角   │ · 会话视图：消息流 + 悬浮输入框    │
│栏│ · 项目挂会话（树）   │ · （可选）AAW 面板：进度 / 启动   │
│  │ · 【+】面板        │ · 项目总览：健康检查+工作流+新建会话 │
└──┴────────────────┴─────────────────────────┘
```

- 会话是骨架，AAW 是挂在骨架上的增强：
  - 新建会话 = 一条空对话直接开聊（`openRealWorkspace(path, { forceNew })`
    跳过历史恢复），不先过 AAW 入口向导；向导在会话内 AAW 面板的「启动」
    分段里，想用时才拉起。「新建会话」与「打开历史会话」是两个动词，
    结果不同，不得合并（合并过的那版里「＋ 新会话」实际打开的是旧对话）；
  - 树里的会话子节点有**两个数据来源**：已连接项目以 ACP `session/list`
    为权威；未连接项目由 agent 会话索引补充（`src/agents/chrysSessions.ts`
    读 `.cache/session_catalog.json`）。因此冷启动就能看到历史，不必先连上
    ——曾经「连上之后突然冒出一大堆会话」的观感来自只挂了一条来源；
  - 有历史的项目默认展开；**无历史的项目也能展开**，子区域里常驻一行
    「＋ 新会话」。空项目在树上必须有起步入口；
  - 会话内 AAW 面板默认收起：上下文条的 AAW 开关（有工作流数据时标签即
    `SR-xxx · 步骤 n`）开合，对话始终占主区；
  - `done` 是 skill 派给 agent 的动作（SKILL.md 里就写着让 agent 调它），
    面板默认不露命令行原文，只在「执行详情」里按需展开。全流程里唯一需要
    人拍板的是**放行**，它有一个按人话说的动作按钮（「放行进入下一步」），
    交给会话的是一条自然语言请求而不是 argv；
- 主行动按钮的文案是「新建会话」，不点名具体 agent：用户的心智是「在这个
  项目里开始一条会话」，不是「建立 ACP 长连接」。agent 是谁、连没连上，
  由行尾连接徽标与设置页承载。接入第二个 agent 时，写死的 `chrys` 会散落
  成一批需要逐个找出来的硬编码，所以界面文案与错误提示统一走
  `registry.ts` 的 `defaultAgentLabel()` 或不点名；
- 图标窄栏 48px 是唯一常驻 icon 列；侧边栏可收起（收起后只剩它）；
- 点会话子节点：项目未连接时**自动重连**再进入；恢复了历史会话则自动
  切到会话视图（重启后一步回到上次对话）；
- 状态权威纪律：**`.sdd/` 目录 + aaw CLI 是工作流状态的唯一权威**，
  桌面端对工作流状态只读渲染（aaw status / next --json），一切写操作
  经 agent 的 skill 流程走 CLI——这条纪律是「桌面端永远不引入第二权威」
  的底线，打磨 UI 时不要破坏。**会话历史的权威同理**：连接的项目的
  `session/list` 优先，磁盘索引只补空缺（它有节流写入，会落后）。索引读
  不到时绝不写空数组——「这次没读到」不等于「这个项目没有会话」。

## 5. 踩坑记录（后来者必读）

1. **审批反向请求的响应形状**（最重要）：ACP 的
   `RequestPermissionResponse.outcome` 是**嵌套对象**
   `{ outcome: "selected", optionId }`，扁平回传会被 chrys 的
   pydantic union 解析拒绝，agent 侧报「failed or was cancelled」
   ——表现是「点了允许却失败」。且该 SDK 的响应 union 只认
   `selected` 形状，连 `cancelled` 都不认：取消已改写为「选中拒绝
   选项」（`session.ts coerceCancelledOutcome`）。
   **教训：反向请求的响应形状必须与真实 agent 的 SDK 校验对齐，
   单测 mock 发现不了。**
2. **Windows npm 是 npm.cmd**：脚本/工具直接 spawn `npm` 会
   ENOENT，走 `node npm-cli.js` 或 shell。
3. **chrys 侧会话模式（manual/auto/bypass）与设置的「审批默认模式」
   （ask/auto-allow/auto-reject）是两个独立概念**——前者是 chrys
   会话模式，后者是客户端应答策略，别混用文案。
4. **Tauri CloseRequested 需 prevent_close + 前端裁决**：关闭守卫
   在 Rust 侧统一转交 `aaw://close-requested` 事件，不复制前端会话
   状态进 Rust。
5. **会话列表标题/快照的卫生**：system 条目不进快照（过期报错不
   回放）；标题永不露出 UUID（首条消息前 24 字 / 时间兜底）。
6. **loadSession 失败静默降级是不对的**：回落 newSession 必须写
   用户公告（`pushNotice`）——「进度都在 .sdd/ 里」的宣传经不起
   静默清空。

## 6. 已知问题（未修，按建议优先级）

### P1 · 状态与流程一致性

- **连接中状态归属错位**：`isConnecting` 是全局单例，连项目 B 时
  项目 A 的树行显示「连接中」（应引入 connectingPath）；
- **移除已连接项目不停连接**：树行 ✕ 只清列表，进程与会话残留
  （「幽灵项目」）——移除 activePath 项目应先断开或提示；
- **切换历史会话失败静默**：loadSession 失败只回滚，无用户提示；
- **重复点击同一项目清空健康报告**且不自动重查（selectWorkspace
  无条件清 health）；
- **顶栏 ＋ 行为**：空态点击隐式落入上次项目（AAW 面板打开时点＋
  无反馈）。

一遍 wire。
