## 冻结状态与依赖

- BrowserSpace 增加真实 agentActive 活动状态；manualTakeover 只表示用户已显式打断，不再承担静态开关 UI。
- 新 ACP 轮次开始时清理上次打断状态；首次真实浏览器活动开始显示玻璃；当前轮结束自动撤去。
- 用户接管在本地立即完成，旧请求与审批立即失效；原生事件到工作台后再后台调用 ACP 取消。
- 只有当前会话且真实运行中的轮次可被接管；后台/旧代次事件不得取消其他工作。
- 玻璃按钮只响应真实用户动作，取消不阻塞原生返回；取消失败不自动夺回权限。

依赖方向：原生 BrowserHost → 原生事件 → Browser 工作台 → Project 公共会话取消入口；不得让原生模块依赖 React，也不得让 Project 依赖 Browser UI。

## P1 公开入口与状态契约

- `BrowserSpace.agentActive` 是原生公开快照字段；只在真实 Browser MCP 活动与 ACP 轮次生命周期的交叉状态中改变。
- `BrowserRuntime.begin_turn` 仅在新 ACP 轮次开始时清除上次显式打断，初始仍归用户；`begin_agent_activity` 在首个真实 MCP 调用时进入 Agent 活动；`end_turn` 在正常结束、失败或取消时撤去活动；`user_takeover` 校验会话、标签、控制代次和活动状态后立即归用户。
- `BrowserHost.beginWork` 对应原生 `browser_begin_work`；既有 `cancelWork` 在 ACP 取消或终态时结束浏览器活动。ACP 增加通用 `onPromptStart` 生命周期通知，在发出 `session/prompt` 前调用。
- 原生 `aaw://browser-activity` 携带公开 `BrowserSpace` 快照，供面板按真实状态更新；`aaw://browser-user-takeover` 仅在原生即时接管成功后发出，工作台据此调用 `ProjectConversation.cancel`，不得反向等待取消才完成原生接管。
- 原生玻璃仅在 `agentActive && !manualTakeover` 时存在，包含“Agent 正在操作”和“我来接管”；按钮只处理 `isTrusted` 点击并携带会话、标签及控制代次，原生再次校验。静态人工接管开关及公开静态切换入口移除。
- 轮次开始和即时接管都使旧请求与旧审批失效；轮次结束只结束活动并取消仍挂起的本体会话请求，不关闭页面、不清空历史。
