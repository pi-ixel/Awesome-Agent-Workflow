## 根因证据

- HEAD 与当前 `select` 均为 `post(selected); cleanup();`，证明单击退出早于 037。
- `BrowserPanel.onElement` 在收到元素事件时 `setPicking(false)`。
- 既有用例只验证启动拾取，没有单击后的持有断言。

## P1 红色证据

- 真实窗口红色：`audit/shots/039-before-click-exits.png`，单击 cell 后「正在拾取」提示与高亮消失。
- jsdom 点击用例两次尝试均因环境无法构造 `isTrusted=true` 事件而失败（`Cannot redefine property: isTrusted`、prototype 无该属性）。该红色属于测试环境限制，不计入缺陷证据；单击行为改由真实窗口验收，脚本层不新增不可信事件断言。
- 面板 TD-039-U03 在修改前会因 `onElement` 把 picking 置 false 而失败。

## P3 与实盘证据

实现：

- `select` 保留 `preventDefault`、`stopImmediatePropagation` 与 `post(selected)`，不再 `cleanup()`；单击后清空当前目标与高亮、断开 ResizeObserver，保持 `status=active` 与全部监听。
- BrowserPanel 移除 `onElement` 订阅，元素事件不再退出 picking；Esc、`browser_pick_cancel`、导航 Started 和会话切换的退出路径不变。
