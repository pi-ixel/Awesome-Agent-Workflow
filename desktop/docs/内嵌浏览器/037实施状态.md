## 根因证据

- `hover` 在目标未变时仍执行 `update()`：`src-tauri/src/browser/enhancements.rs` 的 hover 分支。
- `update()` 写样式后读 `offsetWidth/offsetHeight`，再写再读 `getBoundingClientRect()`，形成强制同步布局。
- `MutationObserver` 观察 `document.documentElement` 的 `childList+subtree`，回调直接 `update()`。
- `selectorFor` 每次 update 重算，逐层 `Array.from(parent.children).filter(...)`。
- 前端面板无轮询：`BrowserPanel.tsx` 仅 picking 状态与 pickStart/pickCancel。
- `scripts/browserPickerCdp.ts` 在 hover 后等待 100ms 读取公开状态，帧内合并兼容现有时序。

## P3 第二轮与实盘验收

起因：第一轮仅 rAF 调度时，在 CDP 创建的隐藏标签页里 `rafProbe=raf-timeout`，高亮不再出现。隐藏页面没有帧回调，属于本单引入的回归风险，因此增加 TD-037-U09 并做第二轮实现：

- `schedule()` 同时登记 rAF 与 32ms 定时器，任一先触发即取消另一个；可见页面仍每帧至多一次，隐藏页面由定时器兜底。
- cleanup 同时取消 rAF 与定时器。
- `npm run test:browser:picker` 首次失败在 `hover` 后固定 100ms 等待：隐藏页面定时器被节流，属于测试等待方式不再成立。已把黑盒改为等待公开状态（`waitFor` / `settleFrom`），所有几何与行为断言保持不变，未放宽任何断言。
- TD-037-U09：rAF 不触发时由定时器完成高亮更新，自动化 9/9 通过。

原生实例实盘（新构建 `cargo run --no-default-features`，3000 按钮页面 `http://127.0.0.1:8766/heavy.html`）：
