## 1. 根因与证据边界

### 1.1 机制层结论

Vite 客户端在处理 `vite:ws:disconnect` 时会轮询开发服务器，连接恢复后直接执行 `location.reload()`，见 `desktop/node_modules/vite/dist/client/client.mjs:1081-1089`。

在隔离端口 1422 的真实复现中：

1. 页面初始 `generation=1`。
2. 停止并恢复隔离 Vite 服务，不修改页面业务代码。
3. 页面变为 `generation=2`，并重新初始化应用。

这证明“开发服务器断线恢复 → 主页面自动 reload → ACP 恢复历史会话 → 用户感到应用崩溃”的完整机制。

### 1.2 与事故证据的对应

| 事故证据                            | 机制解释                                                      |
| ----------------------------------- | ------------------------------------------------------------- |
| 原生 desktop.exe 未退出             | Vite 只刷新 WebView，不重启原生进程                           |
| navigation type=reload              | Vite 客户端直接调用 location.reload                           |
| ACP 恢复多个历史会话                | 新文档启动后执行既有初始化流程                                |
| 无更新安装                          | 与更新器无关                                                  |
| 无原生崩溃事件                      | 不是原生进程崩溃                                              |
| 无文件变化或 full-reload 服务端日志 | 断线路径发生在客户端，不需要文件变化或服务端 full-reload 日志 |

事故当次断线前的客户端日志没有跨重载完整保留，因此不能补造具体断线原因。当前结论只确认该自动重载机制和全部证据吻合，不声称已还原断线的网络/系统原因。

## 2. 整改方案

### 2.1 推荐改法

在 `desktop/vite.config.ts` 中按运行模式禁用 Tauri 原生开发的 HMR 自动刷新：

- Tauri 原生开发：`server.hmr=false`，不再由 Vite 文件更新或断线重连强制刷新主页面。
- `dev:web` 的 `AAW_DEV_BRIDGE=1`：保留现有开发策略，不为本问题扩大修改范围。
- 显式 `TAURI_DEV_HOST` 的远程配置：保留现有协议、主机和端口设置。
- 生产构建：`server` 配置不参与运行，行为不变。

Tauri 原生开发中，前端源码变化后改为由开发者显式刷新；Rust 的既有监听重建不属于本单修改范围。

### 2.2 为什么不修改第三方客户端

Vite 没有为“保留 HMR 更新但禁止断线自动刷新”提供独立配置。修改 `node_modules` 不可维护，也会掩盖后续升级风险。按宿主运行模式关闭自动刷新是范围最小、可长期维护的方案。

### 2.3 代价与边界

- Tauri 前端开发失去自动 HMR，需要显式刷新才能看到前端变化；这是为避免用户工作上下文被突然重置而接受的开发体验取舍。
- 不解决原生进程真实崩溃、用户主动刷新或其他系统故障；这些场景必须单独记录，不能混入本单。
- 不把禁用 HMR 当作 ACP 恢复正确性的替代验证，仍需检查重载后资源代次和用户状态。

## 3. 测试设计

### 3.1 维度说明

- 单元：直接读取 Vite 配置，验证不同开发模式的 HMR 设置，断言配置对象直接产出。
- 黑盒/手工：在隔离端口启动、停止并恢复真实 Vite 服务，从浏览器 generation、navigation 和控制台观察是否重载，不引用业务源码。
- 真实 AAW 手工：验证断线后当前会话、消息草稿和 Browser 状态不被开发服务器强制重置。
- 集成：没有数据库或落盘数据链路，不标记 Integration。

## 7. 最终整改与验收补充（0.2）

### 7.1 最终实施

- 使用 `aaw-disable-dev-client` 插件包装 `/@vite/client` 的开发响应，仅将 `location.reload()` 替换为无副作用表达式。
- 不再采用全面禁用 HMR、删除客户端注入或自定义客户端模块。Vite 自己继续负责常量注入、依赖解析和 `createHotContext`。
- 插件仅在未设置 `TAURI_DEV_HOST` 且未设置 `AAW_DEV_BRIDGE` 时加载。
- 使用 `Cache-Control: no-store`，避免旧客户端缓存。
