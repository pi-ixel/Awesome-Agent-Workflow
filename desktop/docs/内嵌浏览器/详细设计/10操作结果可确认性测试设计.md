## 1. 测试策略

- 单元测试只调用详设公开纯函数 `parse_expectation`、`evaluate_expectation`、`decide_confirmation`，可使用受控事实数据，断言函数返回值或异常。
- 黑盒测试通过真实原生 BrowserHost、真实 MCP HTTP 端点和真实页面驱动，断言原始 JSON-RPC 响应与页面公开事实，不引用业务实现。
- 手工测试使用真实 Agent 会话，验证 Agent 在 `confirmed` 时直接继续、在 `changed` 时使用快照的行为。
- P1 先证明当前响应没有确认等级和必要后置事实，且当前填表、点击、提交、上传无法支持对应成功判断；新用例必须精确红在缺失行为上。

断言值只来自公开函数返回、原始 MCP 响应、页面公开状态和真实会话消息。任何中间转换、相似性猜测和私有状态读取均不允许。

## 8.1 明确不覆盖及理由

| 不覆盖内容                     | 理由与后续边界                                                   |
| ------------------------------ | ---------------------------------------------------------------- |
| 下载完成证明                   | 本期只证明下载事件发生，文件落盘与完整性属于后续数据管理验收     |
| 上传网络完成证明               | 本期只澄清绑定语义，不伪造上传完成；需要时另行观察页面或网络证据 |
| 任意脚本、正则和多条件组合期望 | 为避免注入与组合歧义，详设明确拒绝，不静默降级                   |
| 完整业务结论与视觉语义理解     | 保留给快照、截图和后续专门能力，不在结果确认中硬编码业务规则     |
| 跨源 frame 内部完整事实        | 采集不可用时只承诺未观察与降级，不伪造跨源读取                   |
| macOS / Linux 实机             | 本期与内嵌浏览器首发范围一致，仅 Windows 10/11 x64               |

必须保存原始 MCP 响应、页面公开事实、性能采样、审批日志和真实会话截图。任何把执行完成冒充成功、上传绑定冒充上传完成、未观察冒充无变化、或等待失效后继续返回成功的情况均为阻断失败。
