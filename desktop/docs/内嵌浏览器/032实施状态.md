## 重开 P1/P2 记录

- A06 红：组件卸载期间发生关闭→开启，重建后旧 browser_open 仍被误判为健康，未显示恢复提示。
- U03 红：`session_status` 在已绑定端点上仍返回 not_bound；要求 active→revoked→新端点 active 均由注册表原始字段直出。
- P2 契约：`BrowserHost.mcpStatus(sessionId)` 是只读查询，返回 active/revoked/not_bound；原生命令 `browser_mcp_status` 与前端适配同名语义。UI 在挂载、开关事件、运行时更新后查询；ACP 每轮发送前查询。断言只使用公开状态返回、原始 ACP 和 DOM，不引入健康猜测或伪造工具列表。
- 交叉面：同会话可有多个历史端点，任一未撤销即为 active；全部撤销为 revoked；无绑定为 not_bound。组件卸载、迟到事件、重连和旧端点回收不得影响新端点状态。

## 冻结契约

### 默认与关闭

- BrowserHost 新实例默认 `agent_control=true`；用户主动关闭仍立即撤销全部现有端点、浏览器授权和待处理动作。
- 默认允许是用户明确批准的产品决策，不恢复为默认关闭，也不在本单新增敏感授权持久化。

### 开关事件与工具状态

- 原生 `browser_set_agent_control` 成功后发出 `aaw://browser-agent-control`，载荷只含真实 `enabled`。
- 前端 `BrowserHost.onAgentControl` 订阅该事件；设置页与恢复提示读取真实状态。
- 当前运行时的 `toolNames` 是工具是否真实可用的依据；开启开关但无 browser_* 工具时必须显示待恢复状态。

### 恢复入口

- 开关关闭时显示“Agent 浏览器控制已关闭”，提供显式开启动作。
- 已开启但当前真实会话缺工具时显示“当前会话尚未注册浏览器工具”，提供“重连并恢复浏览器工具”。
- 点击恢复后先显示风险确认；只有点击“确认重连”才调用当前会话公开 `recoverSession`。
- 重连会停止同一连接上的任务，未完成消息不自动重发；成功提示的消失只能来自重连后的真实运行时，不在本地伪造工具列表。

### Agent 行为约束

- 开关关闭或已知运行时缺 browser_* 工具时，`onPromptContext` 追加明确提示：不得改用系统默认浏览器，应指导用户在 AAW 开启控制并恢复会话。
- 该提示是 AAW 侧的可见约束，不能替代真实工具注册，也不能阻止模型回答之外的其他工作。
