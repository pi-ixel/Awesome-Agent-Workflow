## 1. 问题现象

1. 用户点击“拾取元素”后，鼠标没有拾取态变化，页面也没有正在拾取的提示。
2. 悬停页面元素时没有高亮或有界信息提示，用户无法确认将选择哪个元素。
3. 单击元素后，浏览器底部只出现一段“已选择”文本，当前会话输入区没有元素引用。
4. 拾取结果没有进入会话草稿；发送消息后 Agent 也不会获得该引用。
5. 因此当前按钮只完成“页面点击 → 原生事件 → BrowserPanel 局部文本”，没有完成设计要求的“显式拾取 → 当前会话引用 → 用户发送 → Agent 可见”。

实盘证据：

- `C:/tools/deskpilot/audit/026-picker-hover.png`：悬停时无高亮或拾取反馈。
- `C:/tools/deskpilot/audit/026-picker-selected.png`：选择结果只显示在浏览器底部，会话输入区仍为空。

## 2. 问题根因

### 2.1 原生拾取脚本只实现了单击采集

`desktop/src-tauri/src/browser/enhancements.rs:68-85` 仅注册 `click` 监听，生成 selector/text 后发送 WebMessage。脚本没有拾取光标、hover 高亮、提示层、Esc 取消、导航退出和选择模式状态投影。

### 2.2 选中结果停留在 BrowserPanel 局部状态

`desktop/src/plugins/browser/ui/BrowserPanel.tsx:258-275` 收到事件后只写入 `selectedElement`；同文件 `:942-945` 仅渲染“已选择”文本。没有调用 ProjectComposer、AnnotationDraftService 或其他会话草稿公共入口。

### 2.3 Agent 上下文没有元素引用

`desktop/src/plugins/project/sessions/sessionCoordinator.ts:1291-1303` 的 `onPromptContext` 只附加 URL 和页面生命周期状态。当前不存在从 `selectedElement` 到消息草稿、用户正文附件或 ACP 提示块的链路。

### 2.4 采集字段也未达到 FR-UI-009

当前 `BrowserElement` 只有 sessionId、tabId、selector、text 和空 framePath；设计要求的 role、XPath、位置、有界样式摘要以及真实 frame 路径没有实现。敏感输入不采集、旧代次失效和同会话跨标签隔离也没有完整闭环。

## 3. 问题引入轨迹

1. M6 开发计划把“元素拾取器”列入交付，但实现优先完成了按钮、WebMessage 和本地状态展示。
2. 组件测试 TD-08-M04 被缩减为“调用 pickStart 的参数正确”，没有覆盖同名手工设计中的 hover、选择和 Esc。
3. 原生综合黑盒使用 MCP 点击页面，只断言原生事件的 selector/sessionId；它能证明事件桥存在，不能证明真实用户界面和 AI 消息链路正确。
4. DD08 虽有 TD-08-B04/U06 标题，但没有形成对应的可执行测试；全量绿色因此不能证明 FR-UI-009 和 AC-103 已交付。
5. 后续 008、023、024、025 的回归主要检查图标、权限、玻璃和布局，没有补齐该端到端缺口。

## 5. 测试设计为何遗漏

这不是简单的“写了设计但忘了运行”，还包含以下设计缺口：

1. TD-08-M04 把权限分离、hover、选择和 Esc 混在一条场景，没有为每个可观察结果定义独立断言。
2. 没有明确验证拾取光标和“正在拾取”状态，导致用户无法发现模式是否启动。
3. TD-08-B04 只描述引用边界，没有断言输入区出现可见引用、原用户草稿不被覆盖、发送前不产生 ACP 请求。
4. 没有直接断言原始 `session/prompt` 同时保留用户正文和元素引用，也没有断言引用仅在用户发送后提供给 Agent。
5. 没有覆盖发送失败后的引用恢复、同会话跨标签迟到事件、导航/页面代次失效和普通点击不采集。
6. 没有验证拾取高亮层不会进入 Agent 业务快照，也没有验证拾取点击不会触发页面原业务动作。
7. 测试实现缺少“基线用例 → 实际测试 → 原始证据”的阻断检查，使 TD-08-M04 名义存在但内容缩水后仍能全量通过。

## 6. 已批准整改方向与实施结果

- 按现有 FR-UI-009/AC-103 完成原生选择模式、视觉反馈、取消和失效规则，不新增第二套权限模型。
- 参考用户提供的 Kimi 界面，选择模式使用**唯一动态元素框**：框的 `x/y/width/height` 直接来自当前目标元素的实际矩形；鼠标移向新目标时，同一框移动并调整尺寸，不保留旧框，也不能用鼠标位置加固定宽高代替。
- 框附近显示有界定位标签（如 role/selector 摘要），标签随目标移动并避免越出视口；框与标签 `pointer-events=none`，不触发页面布局偏移、不拦截选择点击、不进入 Agent 业务快照。
- 页面滚动、窗口/右栏尺寸、页面缩放、预览缩放和 DPI 改变时重新读取目标矩形；目标被移除、导航或代次失效时立即隐藏或退出，不显示陈旧框。
- 复用 AAW 当前 ProjectComposer/会话草稿能力，在当前输入区形成可识别、可删除的会话级元素引用；不得只把 selector 拼接进用户正文。
- BrowserPanel 只保留正在拾取模式提示；选中结果由输入区芯片承载，不重复显示“已选择”selector/text 调试条。
- 用户发送时才把引用随本轮消息提供给 Agent；原始用户正文保持可辨识，发送失败按现有草稿规则保留。
- 元素引用采用有界、脱敏结构；原生侧继续校验会话、标签和代次，页面内容不构成授权。
- 详设需先冻结元素引用公开结构和草稿公共入口，再进入 P1；禁止通过测试私有方法绕过该契约。
