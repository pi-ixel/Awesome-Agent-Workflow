## 1. 问题现象

### 1.1 实际结果与预期结果

- 实际结果：测试通过 `browser_open` 创建验证页后，旧会话恢复失败、Agent 重连失败或会话被替换时，原生子 WebView 仍停留在桌面上，遮挡后续窗口操作。用户看到“AAW 内嵌浏览器实盘验证”页面持续存在。
- 预期结果：会话进入销毁、恢复失败终态或被替换时，该会话的原生页面和请求应按规则回收；不应留下失控页面或遮挡其他工作。
- 临时现象：显式调用 `browser_close_tab` 后残留页面立即消失，证明原生子 WebView 确实存在且未被销毁。

### 1.2 复现步骤

1. 启动 AAW Desktop 和真实 ACP 会话，调用 `browser_open` 打开本地验证页。
2. 让会话进入恢复失败或旧 Agent 进程无法确认退出的状态。
3. 尝试重连、切换 Agent 或创建新会话。
4. 观察原验证页仍然存在并遮挡操作；通过 `browser_snapshot` 可看到对应会话和标签对象。
5. 显式调用 `browser_close_tab`，页面消失。

### 1.3 影响与风险

- 原生子 WebView 和请求可能越过其所属 ACP 会话继续存在，形成资源泄漏和不可见操作面。
- 残留页面遮挡真实输入，导致 Computer Use 将后续操作误判为窗口遮挡。
- 会话切换或失败后，用户无法确认页面是否仍属于旧会话，存在误操作和归属混淆风险。

## 2. 问题根因

### 2.1 直接原因

`onSessionDisposed` 只调用 `revokeMcpEndpoint`，没有调用原生子 WebView 的关闭入口。端点撤销内部只增加会话代次、取消未决请求并失效审批，没有执行 `browser_close_tab`。

因此，ACP 会话与原生页面的生命周期没有统一的销毁协调：MCP 连接被撤销了，但页面仍然存活。

### 2.2 机制层根因

当前实现把“端点失效”误当成“会话资源已经清理”：

- `desktop/src/plugins/project/sessions/sessionCoordinator.ts:1268` 的销毁回调只撤销 MCP 端点。
- `desktop/src-tauri/src/browser/mcp.rs:224` 的撤销逻辑只做代次失效、请求取消和审批失效。
- 真正的原生页面关闭位于 `desktop/src-tauri/src/browser/host.rs:371` 的 `browser_close_tab`，但销毁回调没有进入该路径。

当 ACP `session/load` 或旧 Agent 退出确认失败时，前端放弃旧会话恢复，却没有一个兜底清理动作关闭旧页面。页面因此越过会话生命周期继续存在。

### 2.3 证据与排除项

| 结论                 | 支撑证据                                                    | 已排除的其他解释              |
| -------------------- | ----------------------------------------------------------- | ----------------------------- |
| 原生页面未被回收     | 页面持续可见并遮挡操作，调用 `browser_close_tab` 后立即消失 | 不是截图缓存或 DeskPilot 误报 |
| 销毁链路只有端点撤销 | 上述会话协调与 MCP 源码                                     | 不是 iCode 主动保留页面       |

| 当前工作树引入       | 浏览器原生模块为未跟踪新文件；HEAD 中没有对应销毁接入       | 不归因于历史发布版本          |

### 2.4 未确认事项

- 会话正常切换、普通关闭、恢复失败、Agent 切换、窗口关闭和应用退出是否需要共享同一个强制清理入口，需在详设评审时逐一确认，不能用一个行为覆盖全部生命周期。
- 哪些逻辑标签和站点数据应保留用于历史恢复，哪些原生页面必须销毁，需要与 AC-011 和 P1 恢复语义保持一致。

## 7. 解决方案

### 7.1 推荐方案

1. 建立会话级原生资源清理公共入口，按会话枚举并关闭其原生标签和未决请求，保持原生事实、逻辑标签和只读投影一致。
2. 在会话销毁、恢复失败终态和 Agent 替换路径调用该入口，不只撤销 MCP 端点。失败必须显式返回并记录，不能静默留下页面。
3. 清理只作用于目标会话，不关闭其他会话页面，不删除其他会话站点数据或工作区状态。
4. 保留逻辑历史和站点数据的既定策略；P1 恢复只允许恢复声明的 URL 和显示偏好，不恢复旧 WebView、DOM、审批或控制租约。
5. 严格复用现有原生关闭能力和宿主公共端口，避免前端直接持有或操作内部 WebView，避免 MCP 与 ACP 相互导入。

### 7.2 方案比较与决策

| 方案                             | 收益                               | 成本与风险                             | 验证结果 | 决策       |
| -------------------------------- | ---------------------------------- | -------------------------------------- | -------- | ---------- |

| 会话级统一清理并复用原生关闭入口 | 页面、请求和投影一致，A/B 会话隔离 | 需要逐一确认各生命周期语义和并发清理   | 推荐     | 待人类评审 |

## 附录 A：测试用例执行发现与测试设计缺口

### A.1 是否由测试用例执行发现

**是，由真实 Computer Use 手工联调发现，不是仅靠静态代码审查推测。**

执行中先出现 `session/load` 恢复失败和旧 Agent 进程退出确认失败，随后发现原验证页持续遮挡操作。源码与 Git 历史用于进一步确认根因，显式调用 `browser_close_tab` 用于验证原生关闭能力。该问题证明现有测试环境能够暴露真实缺陷，但当前测试设计没有形成对应门禁。

### A.2 现有测试覆盖与未覆盖边界

| 已有覆盖                                                      | 不能证明的内容                                                       |
| ------------------------------------------------------------- | -------------------------------------------------------------------- |
| TD-02-M06 覆盖正常关闭标签、窗口和应用后的请求及进程回收      | 未覆盖 ACP 恢复失败、旧 Agent 退出确认失败和切换失败时的原生页面清理 |
| TD-04-I05 覆盖会话关闭后端点失效、未决请求取消和新调用拒绝    | 只验证端点与请求状态，没有断言原生子 WebView 已关闭                  |
