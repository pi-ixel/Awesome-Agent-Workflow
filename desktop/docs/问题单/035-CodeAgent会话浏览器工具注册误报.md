## 1. 问题现象

### 1.1 用户可观察现象

CodeAgent 会话中浏览器工具实际注册并成功执行 `browser_open`，但：

- 浏览器面板仍显示“当前会话尚未注册浏览器工具”；
- 每轮 prompt 被注入“AAW 内嵌浏览器工具当前不可用，不得改用系统默认浏览器”；
- Agent 按注入内容反复要求用户开启总开关并重连。

新建 CodeAgent 会话和既有 CodeAgent 会话均可出现，重连后仍复现。

- 实际结果：工具可用但 UI 与 Agent 上下文都声称不可用。
- 预期结果：只有端点未绑定、已撤销，或当前 Agent 明确上报“浏览器工具缺失”时才提示不可用。
- 出现频率：CodeAgent 会话必现。
- 首次发现版本：`62f8dee6`。
- 最近复现版本：同上。

### 1.2 复现步骤

1. 使用 CodeAgent 打开项目并创建会话。
2. 确认全局“Agent 浏览器控制”开启，且浏览器端点已绑定。
3. 让 Agent 执行 `browser_open`，确认真实工具调用成功。
4. 观察浏览器面板横幅和下一轮原始 `session/prompt`。
5. 点击“重连并恢复浏览器工具”后再次观察。

### 1.3 影响与风险

- 用户被错误引导反复重连，正常浏览器工具被认为不可用。
- Agent 每轮收到错误约束，答复与真实能力矛盾。
- 不影响页面数据、安全权限或端点绑定本身；不涉及越权。

## 2. 问题根因

### 2.1 直接原因

工具是否注册的判断错误地把“缺少工具清单”当成“没有浏览器工具”。CodeAgent 走标准 ACP，不发送 chrys 的 `_chrys/runtime_update`，因此 Desktop 从未获得它的工具清单。

### 2.2 机制层根因

1. `runtime.toolNames` 只由 `agent_runtime` 事件写入，见 `runtimeStatusStore.ts:158`。
2. 当前只有 chrys 方言把 `_chrys/runtime_update` 翻译成 `agent_runtime`；CodeAgent 没有该事件。
3. CodeAgent 首条消息或思考后，`lastSessionId` 被写入，`runtimeKnown` 变真，但 `toolNames` 仍为空。
4. 浏览器恢复横幅把 `runtimeKnown && !hasBrowserTools` 判为缺工具，见 `BrowserToolRecovery.tsx:92-99`。
5. 同一判断复制到 `sessionCoordinator.ts:1770-1786`，每轮 prompt 注入不可用文本。
6. CodeAgent 的真实工具名带 `mcp__aaw-browser-<hash>__browser_*` 前缀，现有 `startsWith("browser_")` 即使将来有清单也匹配不上。
7. 重连只改变端点绑定状态，不会生成 CodeAgent 永远不提供的工具清单，因此横幅和注入会立即回归。

### 2.3 证据与排除项

| 结论                                      | 支撑证据                                                          | 已排除的其他解释           |
| ----------------------------------------- | ----------------------------------------------------------------- | -------------------------- |
| CodeAgent 实际已注册并可调用浏览器工具    | issue #416 的真实 `browser_open` 成功与带前缀工具名               | 不是端点未绑定或工具不可用 |

## 6. 解决方案

### 6.1 推荐方案

采用“工具清单能力感知”：

- `RuntimeSnapshot` 增加“工具清单已知”事实，仅当 Agent 方言确实上报权威工具清单时置真。
- chrys 继续使用工具清单校验；CodeAgent 等未知清单 Agent 不因空清单被判定缺工具。
- `mcpStatus` 继续作为端点事实：`revoked` 和 `not_bound` 仍必须提示恢复。
- 标准 ACP 在端点 active 且工具清单未知时，不显示恢复横幅，不注入不可用文本。
- 抽出共享判断函数，UI 与每轮 prompt 共用；工具名匹配同时兼容 `browser_*` 和 `mcp__aaw-browser-*__browser_*`，不使用过宽的包含匹配。
- `mcpStatus=active` 仅代表 AAW 端点已绑定，不宣称 Agent 侧 MCP 已连接；不新增伪造注册证明。

### 6.2 方案比较与决策

| 方案                                      | 收益                          | 成本与风险                                           | 决策 |
| ----------------------------------------- | ----------------------------- | ---------------------------------------------------- | ---- |
| A. 能力感知 + 共享判断                    | 消除误报，保留 chrys 严格校验 | 需要新增工具清单已知事实和测试                       | 采用 |
| B. 一律以 `mcpStatus=active` 作为工具可用 | 改动最小                      | 端点绑定不等于 Agent 连上 MCP，会掩盖真实失败        | 放弃 |
| C. 仅把前缀改为 `includes("browser_")`    | 可兼容 CodeAgent 名称形态     | CodeAgent 根本无工具清单，不能修复当前误报；匹配过宽 | 放弃 |
| D. 等 CodeAgent 提供工具清单后再修        | 判据最真实                    | 永久阻塞当前已知误报                                 | 放弃 |

### 6.3 实施范围
