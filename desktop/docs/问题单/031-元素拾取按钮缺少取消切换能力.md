## 1. 问题现象

1. 用户第一次点击“拾取元素”后，动态框和拾取状态正常启动。
2. 用户再次点击同一按钮，按钮和页面仍保持拾取状态。
3. 用户无法通过启动入口退出模式，只能依赖 Esc 或显式取消命令。

## 2. 根因与引入轨迹

`desktop/src/plugins/browser/ui/BrowserPanel.tsx` 的按钮 `onClick` 只调用 `host.pickStart`，并在成功后把 `picking` 设为 true；没有读取当前 `picking` 状态切换为 `host.pickCancel`。

原 026 的公开契约只覆盖按钮启动、Esc 和显式取消命令，没有定义按钮 toggle。为避免借 026 擅自扩大交互范围，本单独立冻结按钮行为、测试和验收标准。

## 3. 与 026 的关系和边界

- 两单共享 `picking`、`pickStart`、`pickCancel` 和 BrowserPanel，但根因不同：026 是主窗口 RightPanel 重复消费 Esc；031 是按钮没有状态切换。
- 026 先修复 Esc 的捕获守卫，使取消不再关闭右栏；031 复用该取消语义，不重新实现 Esc 逻辑。
- 本单不修改 RightPanel、024 控制权限、元素引用结构、ACP 消息格式或原生选择脚本。
- 本单只改变按钮启动/取消行为；已有芯片、正文、页面、标签和 Agent 轮次均不得受影响。

## 4. 已批准整改方向

1. 非拾取且用户可控制时，按钮调用 `pickStart`，成功后才进入 picking。
2. picking 时按钮提供明确的“取消拾取”名称和状态，点击调用 `pickCancel`，成功后退出 picking。
3. 启动或取消失败不得伪造状态变化，错误沿用面板现有错误展示。
4. Esc 行为遵循 026 的捕获守卫；非拾取时 RightPanel 的既有 Esc 行为不变。
5. 不自动发送引用，不删除已有芯片，不改变页面和 Agent 轮次。
