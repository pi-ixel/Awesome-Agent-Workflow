## 1. 问题现象

### 1.1 实际结果与预期结果

- 原设计允许子 Agent 使用浏览器，但要求其必须经父运行时登记，并在子 Agent 结束时撤销登记及未决请求。AAW 已据此实现参与者登记、运行时身份解析、按参与者取消和兄弟子 Agent 隔离。
- 真实 iCode 主 Agent 可以通过 ACP 会话注入的 Browser MCP 完成打开页面、快照和截图；真实子 Agent 虽然能发出带有不同 `invocationId` 的生命周期事件，却没有 `browser_open`、`browser_wait` 等浏览器工具，无法完成原子 Agent 联调。
- 原设计把“子 Agent 复用父会话 MCP 端点”误当成“子 Agent 会自动获得工具”，工具分发链路与身份设计之间缺少真实能力验证。
- 为实现子 Agent 级可信身份而进行的 iCode 上游注入实验需要修改非本项目源码，不符合项目边界；该实验已经全部撤回。
- 用户现已明确采用顶层会话级平权模型。旧设计与代码要求主子身份隔离、子结束失效和选择性取消，与新产品语义直接冲突；相关实现和测试不能继续作为交付依据。

### 1.2 复现步骤

1. 启动真实 AAW Desktop 和 iCode 0.28.0 ACP 会话，并注入每会话 HTTP Browser MCP。
2. 要求主 Agent 并行派发两个子 Agent，分别执行浏览器打开和等待操作。
3. 观察主子 Agent 工具清单、生命周期事件、页面和 MCP 调用结果。
4. 主 Agent 能完成浏览器闭环；两个子 Agent 都返回工具不存在，未产生对应浏览器调用。

### 1.3 影响与风险

- 旧测试会强制保留已被新决策取消的子 Agent 身份语义，阻碍正确整改。
- 若继续依赖模型自报身份或共享连接推测调用者，存在伪造身份和跨会话误操作风险。
- 若通过修改 iCode 解决，会将本项目能力绑定到不可修改的上游源码。
- 若只修改授权文档而不验证工具分发，会形成“界面宣称支持、实际子 Agent 无工具”的假能力。

## 2. 问题根因

### 2.1 直接原因

原设计选择了子 Agent 级身份隔离，但当前产品只需要顶层会话级授权与隔离；同时，现有 iCode 接入只把动态 Browser MCP 提供给主 Agent，没有建立子 Agent 工具分发链路。

### 2.2 机制层根因

#### 安全边界与调用身份被混为一谈

浏览器的实际安全边界是顶层 ACP 会话、端点令牌、标签页归属和数据分区。原设计额外引入子 Agent 身份边界，把审计归因、选择性取消和授权隔离混成同一个问题，导致在没有对应产品收益的情况下增加身份注册表、运行时元数据和父子生命周期耦合。

#### 对工具继承机制作了未经验证的假设

ACP `session/new` 的动态 MCP 配置只进入 iCode 主 Agent。iCode 子 Agent 从自身 profile 的 `tools.mcp` 构建工具，内置 General profile 不包含 AAW Browser MCP。因此，“共享父会话端点”只描述预期归属，并不能建立子 Agent 的工具入口。

#### 协议元数据不能承担可信身份

真实 MCP 调用的 `_meta` 没有可信任的主子身份；共享底层连接也不能提供调用者身份。依靠模型自报、时间相关性或共享连接推测身份会形成伪造和串会话风险；为补足该信息而修改 iCode，又会把 AAW 浏览器核心绑定到非本项目实现。

#### 错误产品假设已传导到测试基线

测试设计把“未登记子 Agent 拒绝”“子结束后登记失效”“一个子 Agent 取消而兄弟请求不受影响”写成固定断言，使旧假设不仅是文字偏差，也成为实现和验收门禁。只修改生产实现而不修订这些断言，会造成测试与新产品语义冲突。

### 2.3 证据与排除项

| 结论                               | 支撑证据                                          | 已排除的其他解释                                    |
| ---------------------------------- | ------------------------------------------------- | --------------------------------------------------- |
| 主子工具可用性不同源于工具构建边界 | iCode 主子真实运行结果及子 Agent profile 构建逻辑 | 不是模型不知道工具名称；子 Agent 明确报告工具未注册 |
| 共享连接不能提供可信身份           | 既有共享 MCP 连接实测及空调用元数据               | 不是简单增加连接缓存即可解决                        |
| 会话级平权足以满足当前产品目标     | 用户批准的 C-22 及同会话共享场景分析              | 不再需要以子 Agent 隔离作为安全前提                 |
| 旧测试必须随模型变更               | TD-01、TD-04 中旧登记、失效和兄弟隔离断言         | 不能只改实现并保留旧验收                            |

### 2.4 未确认事项

- 各目标 Agent 通过何种公开能力把当前会话 Browser MCP 分发给子 Agent，仍需逐 Agent 验证。
- 不自动继承 MCP 的 Agent 只有在真实子 Agent 调用成功后才能标记支持；当前不能预设所有 ACP Agent 均支持。

## 4. 问题属类分析

- 主要属类：需求模型与设计语义冲突。
- 次要属类：工具分发能力假设未经验证、过度设计、设计与测试追踪不一致。
- 是否涉及安全或隐私：是。错误身份映射可能导致跨会话误操作；新方案继续以端点、令牌和顶层会话 fail-closed。
- 是否破坏既有兼容或基线：是。C-22 明确取代 C-03 的旧身份规则，需要同步修订关联设计、测试和实现。
- 是否属于相邻但独立的问题：否。D2 的历史会话恢复、question-tracker 环境警告等问题不纳入本问题单。

该问题不是 Browser MCP 协议本身的缺陷，也不是要求 ACP 标准补充主子身份字段；核心问题是 AAW 原设计选择了超出实际需要的隔离粒度，并遗漏了真实工具分发验证。

## 7. 解决方案

### 7.1 推荐方案

1. 以顶层 ACP 会话作为唯一浏览器授权、归属和审计边界。同会话主、子 Agent 平权共享 MCP 端点、标签页、站点数据和动作权限。
2. 会话身份继续由 AAW 实际端点和高随机性令牌确定；模型参数、角色名称、子 Agent 名称和 `_meta` 不参与授权。
3. 删除子 Agent 强制登记、结束失效、独立身份映射和选择性取消语义。子 Agent 结束不影响会话页面、端点或其他同会话调用。
4. 取消统一按请求、标签、顶层轮次、会话或全局执行；审计只承诺会话级归属，不伪造子 Agent 身份。
5. AAW 只通过通用 ACP/MCP 契约被动开放浏览器接口，不主动适配、探测或修改任何 Agent 的主子配置，不为 iCode、Claude、OpenCode 或其他 Agent 增加专用分支。
6. 运行时允许子 Agent 使用同会话 MCP 时，AAW 按同一会话处理；运行时不允许时，接口仍保持开放，AAW 不主动补齐、不修改 Agent 配置，也不制造专用降级路径。
7. 移除旧参与者注册表、参与者请求字段、父子生命周期命令及相关测试，保留标准工具结果和普通子 Agent 展示。
8. 保留历史穿刺和撤回记录作为证据，不删除历史事实，不把实验结果冒充当前产品能力。

### 7.2 方案比较与决策

| 方案                           | 收益                                     | 成本与风险                                                    | 验证结果                        | 决策         |
| ------------------------------ | ---------------------------------------- | ------------------------------------------------------------- | ------------------------------- | ------------ |
| 修改 iCode 注入运行时身份      | 技术上可实现子 Agent 身份传递            | 修改非本项目源码，形成上游依赖                                | 实验可行但已撤回                | 放弃         |
| 逐 Agent 主动适配子 Agent 工具 | 理论上能覆盖更多运行时                   | 每个 Agent 都需要专用配置、生命周期和维护成本，不符合通用目标 | 已被人类明确否决                | 放弃         |
| 通用被动开放与会话级平权       | 无专用适配，符合实际安全边界和运行时能力 | 不提供子 Agent 级审计和选择性取消；不保证运行时继承工具       | 已完成实现、回归和主 Agent 验证 | 采用，已闭环 |
