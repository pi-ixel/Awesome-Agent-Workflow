## 1. 问题现象

### 1.1 用户可观察现象

- 实际结果：从包含 `TAB_NOT_FOUND` 错误和“已选择：#result CLICK_OK”的旧会话切换到新建空会话后，Browser 仍显示旧错误和旧元素选择；新会话明明“未打开页面”，却保留上一会话的页面相关信息。
- 预期结果：新会话只显示其自身投影；旧会话错误、元素引用和选择提示不出现在新会话。旧会话状态可在切回时按真实记录恢复，但不能串入其他会话。
- 出现频率：本次真实 A→新 B 切换即复现。
- 首次及最近复现版本：当前开发工作树。

### 1.2 复现步骤

1. 在会话 A 打开页面并使用元素拾取，生成“已选择：#result CLICK_OK”。
2. 关闭页面并产生 `TAB_NOT_FOUND` 错误。
3. 切换到新建空会话 B，未创建任何标签。
4. 观察 Browser：仍显示 `TAB_NOT_FOUND` 和“已选择：#result CLICK_OK”。

### 1.3 影响与风险

- 用户无法区分错误或元素引用属于哪个会话，可能把旧页面元素带入新会话上下文。
- 跨会话投影隔离失效，破坏元素引用仅当前会话有效的基线。
- 当前证据显示 UI 状态串话；尚无证据表明原生页面或 MCP 端点跨会话开放，二者不能混同。

## 2. 问题根因

### 2.1 直接原因

`BrowserPanel` 的 `error` 和 `selectedElement` 是组件局部状态。`sessionId` 改变时组件实例继续复用，但没有对应的重置逻辑，因此旧会话状态直接显示在新会话中。

### 2.2 机制层根因

组件对空间、审批、权限等数据通过带 `sessionId` 的订阅和快照更新，但对错误与元素选择只执行“收到时设置”，没有在会话切换点清理或按会话存储。局部 UI 状态的所有权没有跟随会话边界，导致同一个 React 实例把 A 的状态投影到 B。

### 2.3 证据与排除项

| 结论                       | 支撑证据                                                                                                           | 已排除的其他解释                 |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------ | -------------------------------- |
| 新会话残留旧错误和元素选择 | 新会话截图同时显示“未打开页面”、`TAB_NOT_FOUND`、旧 `#result CLICK_OK`                                             | 不是新会话自己产生了这些页面事实 |
| 组件没有在会话切换时重置   | `BrowserPanel.tsx:44-74` 定义局部状态；现有 `setError(null)` 仅在特定操作成功路径，未见 `setSelectedElement(null)` | 不是旧事件单次迟到造成的唯一解释 |
| 其他状态按会话订阅         | 同文件审批、权限、元素事件按 `sessionId` 过滤，但过滤只影响新事件，不清空已保存旧值                                | 不是 MCP 身份路由证据            |

### 2.4 未确认事项

- `draft`、`navigation`、`approvals`、`dialogs`、`downloads`、`evidenceUrl` 和清理任务状态是否也有同类残留，需要逐一交叉复核。
- 切回旧会话时应保留哪些合法投影，需要按既有设计区分“按会话保存”与“直接清空”，不能简单全部重置造成另一缺陷。

## 6. 解决方案

### 6.1 推荐方向

明确每类 Browser 局部状态的会话所有权。会话切换时，不能属于新会话的瞬态错误、元素引用和覆盖层必须清理；需要跨切换保留的状态应从对应会话真实快照恢复，而不是复用上一会话内存值。修复不得用全局清空破坏切回旧会话的合法展示。

### 6.2 方案比较与决策

| 方案                                      | 收益                   | 成本与风险                                       | 验证结果 | 决策       |
| ----------------------------------------- | ---------------------- | ------------------------------------------------ | -------- | ---------- |
| 按 sessionId 重置瞬态并从目标会话快照恢复 | 隔离清晰，符合投影模型 | 需要逐字段分类和切回验证                         | 待验证   | 待方案审核 |
| 切换会话时强制重挂载 BrowserPanel         | 可清除全部局部状态     | 可能丢失合法草稿、任务和切回状态，掩盖所有权问题 | 风险较高 | 不首选     |
| 仅隐藏旧元素文本                          | 表面减少串话           | 错误和其他状态仍残留，引用仍可能进入新会话       | 不完整   | 放弃       |

### 6.3 实施范围

- 需要修改：BrowserPanel 会话状态生命周期及测试；必要时的宿主投影读取。
- 明确不修改：MCP 会话身份、iCode、原生权限模型和无关模块。
- 需要同步：测试设计、交叉面、真实 A/B 截图和实施记录。
- 需要人类执行或决策：审核字段保留/清理矩阵，最终关闭问题。
