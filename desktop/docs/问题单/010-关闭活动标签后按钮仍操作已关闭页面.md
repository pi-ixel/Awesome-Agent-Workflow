## 1. 问题现象

### 1.1 实际结果与预期结果

- 实际结果：Kimi 页面仍在右侧显示，标签栏也显示 `https://www.kimi.com/`，但地址栏显示 `about:blank`。点击“拾取”和“证据”没有可见结果，原生命令分别返回 `TAB_NOT_FOUND`。
- 预期结果：关闭活动标签后，AAW 应选择仍存活的标签或进入真实空态；地址栏和所有按钮只能作用于当前 ready 标签，不能继续操作 closed 标签。
- 出现频率：当前 Kimi 与 DeepSeek 双标签场景中实测复现。
- 首次及最近复现版本：当前开发工作树。

### 1.2 复现步骤

1. 会话中保留 ready 的 `tab-1=https://www.kimi.com/`。
2. 创建并关闭 `tab-2=about:blank`，使界面此前活动的 tab-2 进入 closed。
3. 观察标签栏仍显示 Kimi，但地址栏为 `about:blank`。
4. 点击“拾取”或“证据”。
5. 原生命令日志分别记录 `browser_pick_start` 和 `browser_screenshot` 失败，错误均为 `TAB_NOT_FOUND`。

### 1.3 影响与风险

- 拾取和证据核心功能在合法页面仍存在时完全不可用，用户只看到“没有反应”。
- 地址、页面和按钮目标互相矛盾，可能使其他标签操作也指向错误页面。
- 当前可见 Kimi 页面未被误改；风险是错误目标、功能阻断和未来动作误归属。

## 2. 问题根因

### 2.1 直接原因

`BrowserPanel` 的 `activeTabId` 仍指向已关闭的 `tab-2`。`activeTab` 计算没有排除 `lifecycle=closed`，所以地址栏和按钮继续从 closed 对象读取 URL 和 tabId。

### 2.2 机制层根因

`refresh` 只有在快照中完全找不到当前 `activeTabId` 时才回退到第一个标签，判断条件没有排除 closed。由于运行时快照保留 closed 记录，当前 ID 永远被视为“仍存在”，不会切换到 ready 的 tab-1。标签栏渲染另行过滤 closed，因此出现“标签栏显示 tab-1、状态操作 tab-2”的投影分裂。

### 2.3 证据与排除项

| 结论 | 支撑证据 | 已排除的其他解释 |
|---|---|---|
| 两按钮真实调用失败 | 当前 `browser_pick_start` 和 `browser_screenshot` 日志均返回 `TAB_NOT_FOUND` | 不是功能未接线或仅遮挡成功结果 |
| 当前存活页面是 tab-1 | 公开 `browser_snapshot` 返回 tab-1 ready、URL 为 Kimi | 不是 Kimi 页面已关闭 |
| 按钮目标是 closed 的 tab-2 | 同一快照中 tab-2 closed、URL 为 about:blank，界面地址栏也显示 about:blank | 不是标签 ID 猜测，和 UI 证据一致 |
| activeTab 未排除 closed | `BrowserPanel.tsx:76-85` 直接按 ID 查找，refresh 只检查 ID 是否存在 | 不是原生关闭能力缺失 |

### 2.4 未确认事项

- 其他依赖 activeTab 的缩放、布局、对话框和下载操作是否全部受影响，需要整改后逐项回归。
- 005 的 browser_open 复用 closed 标签是触发该状态的途径之一，但本单在 UI 选择逻辑上独立成立，不能靠修 005 自动证明关闭路径正确。

## 6. 解决方案

### 6.1 推荐方向

建立统一的活动标签有效性约束：只有非 closed 标签可成为 activeTab。关闭当前标签、刷新快照、切换会话或收到迟到事件时，选择当前仍 ready 的合法标签；没有合法标签时进入真实空态并禁用依赖页面的按钮。不得仅隐藏 closed 标签而保留其操作能力。

### 6.2 方案比较与决策

| 方案 | 收益 | 成本与风险 | 验证结果 | 决策 |
|---|---|---|---|---|
| 统一活动标签过滤和回退规则 | 地址、按钮和标签栏使用同一真实目标 | 需要覆盖关闭、迟到事件、多标签和空态 | 待验证 | 推荐，待审核 |
| 仅在拾取和证据前检查 closed | 可消除两个错误 | 地址栏和其他操作仍错误，根因未解决 | 不完整 | 放弃 |
| 从运行时删除所有 closed 记录 | UI 判断变简单 | 破坏生命周期历史和迟到事件防护 | 不可接受 | 放弃 |

### 6.3 实施范围

- 修改 BrowserPanel 活动标签选择及相关测试；必要时提取公开纯函数。
- 不改变运行时 closed 历史、MCP 会话身份和 iCode。
- 005、003、008、011 分别验证，不顺手合并。
