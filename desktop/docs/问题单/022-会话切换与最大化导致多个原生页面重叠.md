## 1. 问题现象

1. 普通窗口下只看到当前百度页面，旧“AAW 内嵌浏览器实盘验证”页面不可见。
2. 窗口最大化后，旧测试页面在原位置重新出现，百度页面位于新的右侧视口，两个页面同时显示并重叠到主窗口内容中。
3. 标签条只看到百度，没有旧测试页标签。
4. 还原窗口后旧测试页又被百度区域遮住，形成“最小化/还原没问题”的假象，实际旧原生页面并未正确隐藏。

证据：

- `audit/shots/022-normal-current-only-baidu.png`：普通窗口只显示百度。
- `audit/shots/022-maximized-overlap-reproduced.png`：Agent 使用 Win+Up 真实最大化后复现旧测试页与百度同时显示。
- 复现后已使用 Win+Down 还原用户窗口。

## 2. 当前实例与代码版本核查

### 2.1 当前实例确实是复用的旧运行实例

- 当前进程为 `desktop.exe`，PID 22236，运行路径为当前仓库的 `desktop/src-tauri/target/debug/desktop.exe`。
- 用户要求“打开 AAW”时，Agent 检测到窗口已运行，只执行了置前，没有重启进程。
- 当前主页面 `timeOrigin=1794800905708.5`，不是为本轮新启动的页面。
- 实际加载的 `BrowserPanel` 函数仍包含旧版会话内 effect 重置结构，不包含当前源码中的 `BrowserPanelSession` 键控边界。

因此，**当前手工验收没有严格运行在最新前端代码上**。这是验收环境控制失误，必须记录，不能用旧实例结果代表最新代码验收。

### 2.2 但最新源码仍然存在本单缺陷

当前源码的显隐 effect 只对新活动标签调用 `setVisible(sessionId, activeTab.tabId, visible)`，没有隐藏旧标签；会话面板卸载也没有对应原生隐藏清理。原生 `browser_set_visible` 只控制被指定的一个 WebView。

所以这不是“只要重启到最新代码就会消失”的问题。最新代码仍需要整改，重启只能消除版本混杂，不能替代修复。

## 4. 问题根因

### 4.1 旧标签和旧会话没有隐藏

- `BrowserPanel` 在活动标签变化时只显示当前活动标签，证据为 `desktop/src/plugins/browser/ui/BrowserPanel.tsx:423-449`。
- 用户点击标签只改变 `activeTabId` 和地址草稿，证据为 `BrowserPanel.tsx:764-803`。
- MCP `browser_select_tab` 只发送选择事件，没有直接同步所有原生标签显隐，证据为 `desktop/src-tauri/src/browser/mcp.rs:486-506`。
- 原生 `browser_set_visible` 只对指定标签执行 show/hide，证据为 `desktop/src-tauri/src/browser/host.rs:531-546`。
- 会话切换后面板可以 keepMounted；按会话重挂载时也没有卸载清理去隐藏上一会话的原生页面。

结果是：显示新页面并不隐式隐藏旧页面，多个原生 WebView 可以同时保持可见。

### 4.2 最大化暴露了旧页面，而不是创建旧页面

- ResizeObserver 只把当前活动占位元素的最新边界同步给当前活动标签。
- 百度页面在最大化后获得新的右侧视口边界。
- 旧会话页面没有参与当前布局，也没有被隐藏，仍保留旧位置与尺寸。
- 普通窗口下新页面可能恰好覆盖旧页面；最大化改变几何后两个可见原生页面分离，形成用户看到的重叠/并排现象。

### 4.3 机制结论

**当前缺少“每个主窗口最多只有一个前台原生页面”的统一显隐不变量。** 前端局部 effect 和原生单页 show/hide 无法共同保证该不变量，会话切换、标签切换和窗口布局之间没有统一投影。

## 6. 测试设计与验收流程缺口

### 6.1 自动化缺口

- BrowserPanel 测试存在 `setVisible` Mock，但没有断言旧标签或旧会话收到隐藏调用。
- 现有用例没有覆盖“同会话两个标签切换 × 最大化”。
- 现有用例没有覆盖“会话 A 页面 × 切到会话 B × 最大化/还原”。
- 017 的离屏截图、009 的首屏显隐和面板 visible 都是其他显隐写入者，必须进入交叉面清单。
- 原生综合套件主要验证单个测试会话，没有通过真实像素证明其他会话的原生页面未显示。

### 6.2 验收环境缺口

- 打开应用时复用旧进程，没有校验前端模块和原生二进制是否为当前交付代码。
- 多个测试会话的页面保留是合理需求，但验收没有先证明后台页面已隐藏。
- 此前“实盘通过”只证明目标工具链可用，不能证明多会话视觉隔离通过。总实施状态中的相关表述需要在本单完成后重新核对。

### 6.3 关于是否修改代码或断言

- 本单分析期间没有修改任何产品代码或测试。
- 019 曾在用户批准后修正“title 与 H1 混用”的错误断言；020 曾在批准后补齐 Space 前置。这些修改不改变浏览器显隐逻辑，也不能证明本单场景通过。
- 当前缺陷有真实截图、会话快照和源码证据，不能通过修改断言、隐藏截图或重启应用来消除。

## 7. 推荐整改方案（待审核）

### 7.1 建立窗口级前台页面唯一投影

建议由原生 BrowserHost 提供统一的“同步前台页面”能力，而不是让每个 React effect 自由控制单页：

1. 输入当前窗口、当前会话、当前标签、面板可见性和最新边界。
2. 隐藏该窗口内所有非目标原生页面，包括其他会话和其他标签。
3. 任一旧页面隐藏失败时显式报错，不得继续显示新页面形成重叠。
4. 先同步目标页面最新边界，再显示目标页面，避免旧坐标闪现。
5. 后台页面只隐藏，不关闭、不销毁、不清理数据、不改变控制权。
6. 每次投影携带当前代次或归属，迟到回调不得重新显示旧会话页面。

### 7.2 必须接入的场景

- 同会话标签选择、新建、关闭和活动标签回退。
- 会话切换、面板卸载、右栏关闭、后台会话显隐命令。
- 窗口最大化、还原、最小化、尺寸调整、DPI 和右栏布局变化。
- 017 离屏截图临时显示与恢复。
- 崩溃恢复、页面重载和会话销毁。
- 021 全局弹框出现后暂停前台原生页面；021 与 022 共用显隐规则，但不合并问题根因。

### 7.3 验收环境整改

- 最终手工验收前重新启动当前交付实例，不复用旧进程冒充最新版本。
- 记录进程启动时间、前端实际模块结构和原生测试证据。
- 在真实 AAW + 百度同会话双标签、A/B 双会话、最大化/还原下分别截图。
- 不仅断言快照标签数量，还必须验证屏幕中只有一个当前原生页面且输入只落在当前页面。

## 8. 方案边界

- 不把其他会话标签并入当前会话标签条。
- 不为通过测试而关闭后台历史页面；隐藏与销毁必须分离。
- 不仅给当前 effect 再补一个零散隐藏调用就宣称系统完成；必须审查所有显隐写入者和竞态。
- 不通过重启、清数据或修改截图断言规避。
- 不修改 iCode。

## 12. SDD 整改与最终验证（2026-11-16）

### 12.1 实施结果

- 复用既有 `browser_set_visible` 作为原生显隐入口；显示目标前隐藏同窗口其他已登记页面，隐藏失败时不显示目标。
- BrowserPanel 在标签或会话退出时隐藏旧页面，并使用稳定标签 ID 避免无关对象刷新导致额外显隐抖动。
- 未新增公共协议，未销毁后台页面，未修改 iCode、017 算法或 021。

### 12.2 SDD 证据

- P1：U01/U02 精确红于缺少旧页面隐藏；真实 B01 中 A、B1、B2 全部错误保持 visible；既有 13 条面板测试绿色。
- P2：公开入口、直接断言、五要素和交叉面全部核对，无测试放宽。
- P3：第一轮实现后，面板 15/15、Rust 145 通过 1 ignored、Projection 黑盒 5 项通过。
- 最终全量：201 文件、1707 条全部通过；一次架构扫描间歇超时已保留并按原命令复跑转绿，没有提高阈值。
- 原生 24、控制 17、数据 22、证据 8、UI Agent 7、直连 Agent 11 均通过；类型检查、生产构建、0 错误 lint 和格式检查通过。

### 12.3 最新实例真实验收

- 重新启动当前 Rust/前端交付实例，实际 BrowserPanel 包含最新键控边界；没有复用旧进程。
- 同一会话真实保留 AAW 本地页和百度两个存活标签，标签切换正确。
- A/B/A 后 A 有两个存活标签，B 有一个存活标签，历史页面未销毁。
