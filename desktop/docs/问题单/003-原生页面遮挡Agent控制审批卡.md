## 1. 问题现象

### 1.1 用户可观察现象

- 实际结果：用户接管页面后，Agent 调用 `browser_request_control` 返回 `APPROVAL_REQUIRED:approval-1`，但 Browser 面板没有可见的审批卡、“拒绝”或“批准一次”按钮。用户无法通过真实界面完成授权。
- 预期结果：审批等待期间，用户能在当前 Browser 面板看到并操作审批卡；批准前页面保持人工控制且不执行 Agent 点击，批准后指定动作可按契约继续。
- 出现频率：本次真实链路首次执行即出现；其他审批类型尚未逐一复现。
- 首次及最近复现版本：当前开发工作树。

### 1.2 复现步骤

1. 开启“Agent 浏览器控制”，新建真实 iCode 会话。
2. Agent 打开本地验证页并执行 30 秒 `browser_wait`。
3. 用户直接点击网页“点击验证”；页面显示 `CLICK_OK`，等待返回 `CANCELLED`，状态变为“人工控制”。
4. Agent 请求重新控制 `tab-1`，得到 `APPROVAL_REQUIRED:approval-1`。
5. 观察 Browser 面板：仍只显示网页和“人工控制”，没有审批卡。

### 1.3 影响与风险

- 用户接管后无法在界面中重新授权，正常的人机交替控制链路中断。
- 审批实际处于未决状态而界面不可见，用户不能明确拒绝或批准，形成权限流程可用性阻断。
- 当前未发现绕过审批或越权执行：Agent 直接点击返回 `CONTROL_NOT_GRANTED`，语义按钮保持 `WAITING`。

## 2. 问题根因

### 2.1 直接原因

审批卡是主窗口 React DOM 中的绝对定位元素，原生子 WebView 覆盖同一区域。Windows 原生子窗口的层级不受主页面 CSS `z-index` 控制，因此审批卡虽然已在 DOM 中创建并处于可见样式，仍被原生页面遮挡。

### 2.2 机制层根因

`BrowserPanel.tsx` 使用 `viewportRef` 区域设置原生子 WebView 边界；审批卡位于该原生区域上方的主 WebView DOM 中，仅以 `absolute ... bottom-10 z-20` 参与主 WebView 内部层叠。实现把“主页面 DOM 内层级更高”误当成“也能覆盖原生子窗口”，没有为审批交互保留不被原生页面覆盖的界面区域或独立原生层。

### 2.3 证据与排除项

| 结论                             | 支撑证据                                                                                                        | 已排除的其他解释                          |
| -------------------------------- | --------------------------------------------------------------------------------------------------------------- | ----------------------------------------- |

## 6. 解决方案

### 6.1 推荐方向

审批交互必须位于真实可见且可点击的界面层，不能依赖主 WebView CSS 层级覆盖原生子窗口。整改应保持现有审批契约、页面代次绑定、一次性消费和 fail-closed 行为，不通过自动批准或绕过控制校验规避遮挡。

具体布局方案及是否影响其他原生覆盖层须在实施前按 SDD 流程审批，本单未授权修改代码。

### 6.2 方案比较与决策

| 方案                                                  | 收益                                                | 成本与风险                                       | 验证结果 | 决策         |
| ----------------------------------------------------- | --------------------------------------------------- | ------------------------------------------------ | -------- | ------------ |
| 在主 WebView 内为审批保留独立、不被原生页面覆盖的区域 | 复用现有 React 审批组件和公共宿主端口，布局边界清晰 | 需要处理页面尺寸、自适应及所有覆盖层一致性       | 待验证   | 待方案审核   |
| 使用独立原生窗口承载审批                              | 可跨原生页面显示                                    | 增加窗口生命周期、焦点、归属和关闭竞态，复杂度高 | 待验证   | 暂不作为首选 |
| 自动批准或由 Agent 自批                               | 表面消除阻塞                                        | 直接破坏用户授权与安全边界                       | 不可接受 | 放弃         |

### 6.3 实施范围

- 需要修改：Browser 面板布局及真实可见性测试；具体文件由获批方案冻结。
- 明确不修改：iCode、Agent 配置、权限契约、审批自动通过逻辑和无关模块。
- 需要同步：相关测试设计、交叉面清单、真实手工证据和实施状态。
- 需要人类执行或决策：审核整改方案；验证证据齐全后闭环，无需额外人工关闭。
