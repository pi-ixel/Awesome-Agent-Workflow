# 【编号】问题简述

> 填写说明：本模板用于记录可追踪、可验证、可闭环的问题。标题应直接描述用户可观察的问题或设计缺陷，不使用“若干问题”“异常优化”等模糊表述。正文中的示例提示在正式提交前替换为实际内容。

## 模板使用规则

1. 文件名为 `编号-问题简述.md`；编号不得复用，模板使用 `000`，正式问题不得使用该编号。
2. 每个问题只描述一个可独立闭环的根因或一组具有共同根因的现象；相邻但独立的问题另立问题单。
3. 根因、穿刺和验收结论必须附证据；没有证据的内容放入“未确认事项”。
4. 方案变更必须记录原因、影响和测试变化，不得通过降低断言或删除场景掩盖缺陷。
5. 状态只能依据实际进度更新；文档修订完成不等于代码整改完成，测试通过也不等于真实场景已验收。
6. 涉及凭证、个人数据或企业内部信息时，证据必须脱敏；问题单不得保存完整令牌、密钥或敏感载荷。
