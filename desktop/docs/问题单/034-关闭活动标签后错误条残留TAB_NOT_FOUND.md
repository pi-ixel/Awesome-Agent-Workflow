## 1. 问题现象

### 1.1 用户可观察现象

用户在内嵌浏览器中新建标签页，再关闭该活动标签后，浏览器工具栏下方出现红色错误条，内容为内部错误码 `TAB_NOT_FOUND`。原百度标签已成功回退并继续可用，但错误条持续存在。

- 实际结果：活动标签关闭成功，剩余标签正常显示，同时出现 `TAB_NOT_FOUND` 错误条。
- 预期结果：关闭活动标签属于正常用户操作，不得显示内部错误；只有真实失败才显示可理解、可处理的错误。
- 出现频率：必现；当前会话实测一次。
- 首次发现版本：`feat/embedded-browser`，提交 `115eacd1`。
- 最近复现版本：同上。

### 1.2 复现步骤

1. 在内嵌浏览器已有正常页面的情况下新建一个标签，并使其成为活动标签。
2. 点击该标签右侧的关闭按钮 `X`。
3. 观察标签栏、页面回退结果和工具栏下方错误区。
4. 再执行普通刷新、切换标签或页面点击，观察错误条是否自行消失。

### 1.3 影响与风险

- 用户会误以为页面关闭失败或浏览数据损坏，实际页面与数据未受影响。
- 内部错误码直接暴露，降低可诊断性。
- 错误条不会因普通刷新或标签切换自动清除，可能掩盖后续真实错误。
- 未发现数据丢失、权限越权、跨会话数据污染或不可逆副作用。

## 2. 问题根因

### 2.1 直接原因

关闭活动标签后，`BrowserPanel` 的可见性 effect 在 cleanup 中继续使用旧标签 ID 调用原生 `browser_set_visible(..., false)`。旧标签的 WebView 已被销毁，原生 `find_webview` 返回 `TAB_NOT_FOUND`，该错误被 cleanup 的 `catch` 写入用户可见错误状态。

### 2.2 机制层根因

1. 用户点击 `X` 触发 `host.closeTab`，见 `desktop/src/plugins/browser/ui/BrowserPanel.tsx:1010`。
2. 后端 `close_tab_impl` 关闭 WebView、从标签映射中移除并标记标签为关闭，见 `desktop/src-tauri/src/browser/host.rs:589-609`。
3. 关闭成功后的 `refresh` 发现原活动标签已关闭，选择仍存活的标签作为回退，见 `BrowserPanel.tsx:160-176`。
4. `nativeTabId` 变化，可见性 effect 的 cleanup 使用闭包中的旧标签 ID 执行隐藏，见 `BrowserPanel.tsx:661-672`。
5. `browser_set_visible` 在读取 `visible` 参数前先调用 `find_webview`，见 `host.rs:679-686`；旧 WebView 不存在，因此直接返回 `TAB_NOT_FOUND`。
6. cleanup 的 `catch` 将该内部错误原样写入错误条，见 `BrowserPanel.tsx:1021`。
7. 普通刷新、标签切换和页面点击不会清空该局部错误，只有少数显式成功路径会清理，因此错误条持续残留。

## 6. 解决方案

### 6.1 推荐方案

在 `BrowserPanel` 的可见性 cleanup 中区分“隐藏已不存在的标签”和真实显隐失败：

- 仅当隐藏旧标签返回严格的 `TAB_NOT_FOUND` 时，将其视为关闭竞态已达成预期结果，不写入用户可见错误。
- 其他错误以及显示页面时的 `TAB_NOT_FOUND` 继续按真实错误处理，不得一概吞掉。
- 不修改原生 `browser_set_visible` 公共契约，不把“显示已关闭页面”改成静默成功。
- 不扩大为全局错误码翻译；其他内部错误码的友好映射另立问题处理。
- 保留标签回退、地址同步、拾取与证据目标切换等既有行为。

### 6.2 方案比较与决策

| 方案                                                        | 收益                                             | 成本与风险                                                   | 验证结果 | 决策 |
| ----------------------------------------------------------- | ------------------------------------------------ | ------------------------------------------------------------ | -------- | ---- |

## 10. 闭环结论

问题已闭环。根因是活动标签关闭后，可见性 cleanup 对已销毁 WebView 再发隐藏命令，原生返回 `TAB_NOT_FOUND` 并被当作真实错误显示。整改在 cleanup 中只隔离该严格错误，其他显隐失败仍保留，原生契约未改变。定向用例 23/23、全量 301 个文件 2241 条、类型检查、Lint、构建和真实桌面关闭活动标签场景均通过。遗留的其他内部错误码裸显问题不属于本单范围，需另行处理。
