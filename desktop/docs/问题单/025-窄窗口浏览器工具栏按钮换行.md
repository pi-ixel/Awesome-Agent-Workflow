## 1. 问题现象

在右栏较窄时，后退、前进、刷新、地址栏、缩放和拾取位于第一行，而保存证据、停止、数据管理和新建标签被挤到第二行。控件分组失去一致性，用户会误以为它们是另一组无关功能。

用户明确要求：所有按钮必须处于同一工具行，不得一部分在上、一部分在下。

## 2. 问题根因

### 2.1 直接机制

- `desktop/src/plugins/browser/ui/BrowserPanel.tsx:690` 的工具栏容器使用 `flex-wrap`，明确允许子项换行。
- 同文件 `:750` 的地址栏表单使用 `min-w-60 flex-1`，最小宽度为 240px。
- 当右栏无法同时容纳地址栏最小宽度、缩放文本和全部图标时，Flex 按现有规则将后续按钮换到第二行。

### 2.2 设计缺口

004 的测试把“允许工具换行”当成正确行为，但没有覆盖全部工具必须在同一工具行的产品要求；008 增加图标按钮后，既有测试仍只检查图标和动效，没有检查控件最终落点与单行布局。

## 3. 问题引入轨迹

1. 004 为窄窗口引入 `flex-wrap` 与地址栏 `min-w-60`，并用 TD-004 固化了换行行为。
2. 008 将拾取、证据、停止、数据管理改为图标并保留新增标签按钮，增加了单行工具数量。
3. 023 的滑动开关占用空间进一步放大了换行概率；024 已移除该开关，但通用换行机制仍存在。
4. 因此这是既有布局策略与当前产品要求不一致，不是原生 WebView 或 024 权限状态机导致。

## 5. 解决方案（已批准并完成两轮验证）

采用“全部工具位于同一行”的统一布局：

1. 工具栏容器禁止换行，所有导航、功能和新建按钮保持在同一工具行。
2. 地址栏由固定最小宽度改为可收缩的弹性区域，优先保留全部图标按钮的可点击面积。
3. 图标、缩放文本和功能按钮不得被压缩成不可识别或不可点击状态；地址栏文字允许在自身区域内截断。
4. 不改变按钮顺序、图标、权限禁用状态、键盘操作、024 玻璃和原生页面边界。
5. 不通过隐藏按钮、移到第二行或改动窗口宽度来伪造通过。
