## 1. 问题现象

### 1.1 用户可观察现象

- 内嵌浏览器保持打开时，点击会话顶部的“断开并重连”，出现“确认重连？”弹框。
- 弹框右侧被内嵌浏览器覆盖，遮罩也没有覆盖浏览器区域。
- “确认重连”按钮部分被遮挡，用户无法看到完整按钮，遮挡区域也不能按主页面弹框的语义接收输入。
- 预期：任何全局模态出现后，其遮罩、说明和所有操作按钮都完整位于最上层；原生页面不能破坏模态的视觉与输入闭环。

### 1.2 真实证据

- 截图：`audit/shots/021-reconnect-modal-occluded.png`。
- 重连弹框经 React Portal 挂载到 `document.body`，不是会话容器内局部定位。
- 主页面实测：弹框右缘为 1216，原生浏览器视口左缘为 1178，横向重叠 38px。
- “确认重连”按钮右缘为 1195，其中 17px 落入原生视口。
- 弹框遮罩实测覆盖整个主页面，CSS position 为 fixed，z-index 为 50；因此不是遮罩尺寸不足或 Portal 未生效。

## 2. 问题根因

### 2.1 机制层根因

1. `ReconnectButton` 使用 Portal 和 `ModalShell` 展示全局弹框，证据为 `desktop/src/plugins/project/conversation/ui/ReconnectButton.tsx:73-131`。
2. `ModalShell` 使用全窗口固定定位、遮罩和 `z-50`，证据为 `desktop/src/shared/ui/ModalShell.tsx:32-49`。
3. 内嵌浏览器不是主页面中的普通 DOM，而是通过 `window.add_child` 添加到主窗口的原生子 WebView，证据为 `desktop/src-tauri/src/browser/host.rs:264-363`。
4. 浏览器通过原生 `set_bounds` 和 `set_visible` 控制几何与可见性，证据为 `desktop/src-tauri/src/browser/host.rs:508-546`；前端只测量占位元素并同步位置，证据为 `desktop/src/plugins/browser/ui/BrowserPanel.tsx:423-449`。

**原生 WebView 与主页面 CSS 不属于同一个层叠上下文。主页面的 z-index 无论提高到 50、100 或更大，都不能插入操作系统原生子窗口之下。** 当前只有面板 visible 属性控制浏览器显隐，没有“全局模态/浮层出现时暂停原生页面显示”的仲裁，因此原生页面实际压过全部主页面浮层。

### 2.2 不是这些原因

| 候选解释 | 排除证据 |
|---|---|
| 弹框没有 Portal 到 body | 实测 `bodyPortal=true`，且源码明确使用 createPortal |
| z-50 数值太低 | 原生层不参与 CSS z-index 比较，z-100 同样会被遮挡 |
| 弹框宽度或居中计算异常 | 遮罩已覆盖全窗口；弹框按 max-w-lg 正常居中，重叠来自原生视口 |
| 003 修复回退 | 003 的浏览器内部卡片已改为文档流；本单是不同的全局模态链路 |

## 4. 完整图层优先级清单

### 4.1 先区分三个不能直接用 z-index 比较的世界

| 实际层级 | 组成 | 当前优先级与边界 |
|---|---|---|
| 操作系统独立窗口 | 诊断窗口、SSO 登录窗口、安装器窗口、系统文件选择器和系统对话框 | 由 Windows 的前台、拥有关系和置顶规则决定；与主页面 z-index 无关 |
| 主窗口原生子层 | 每个内嵌浏览器标签的原生 WebView；数据清理临时 WebView | **在其实际显示区域内高于主窗口所有 CSS 层**；清理临时 WebView 通常隐藏，不应产生视觉效果 |
| 主窗口 Web 层 | 会话、侧栏、设置、弹框、菜单、提示、右栏和终端等 DOM | 按 CSS 层叠上下文、z-index 和文档顺序排列；不能覆盖上述原生页面 |

网站内部的 z-index 只影响该网站自身，不影响 AAW 主窗口，也不纳入下表。

### 4.2 主窗口 CSS 声明层级：从高到低

下表是当前源码中已声明的层级全集分类。嵌套层叠上下文中仍须遵守父级边界，不能只看数字判断任意两个元素的最终顺序。

| 声明层级 | 组件或用途 | 当前语义与风险 |
|---|---|---|
| z-100 | 退出遮罩；Markdown 文档对话框；表格放大预览；图表预览；文档批注编辑；会话批注摘要 | 产品设计上的最高 Web 浮层，但仍低于原生浏览器实际合成层 |
| z-60 | 全局上下文菜单；HintTooltip；标签总览；更新发布说明；输入状态弹层；诊断 ACP 原始报文 | 菜单和提示层；与原生视口相交时同样会被遮挡 |
| z-50 | ModalShell 全部消费者，包括重连、移除项目、Desktop 更新、Agent 设置和关闭确认；Agent 权限审批；Markdown 图片预览；Toast；会话导航浮层；状态菜单和任务进度；拖动中的面板标签；诊断日志详情 | 全局模态与通知层；本单重连即属于此层 |
| z-40 | WorkspaceGate 阻断页；完整/浮动会话宿主；Agent 待答问题通知；通用下拉框；添加项目面板；归档提示；项目树局部浮层 | 工作区阻断和较大局部浮层；同样不能覆盖原生页面 |
| z-30 | 右栏覆盖模式面板；浏览器页面对话框卡片；工作流时间线展开区；输入框补全与菜单；会话查找；会话状态菜单 | 较大局部操作层；若与原生页面相交仍受原生遮挡 |
| z-20 | 右栏遮罩；工作流时间线根；会话状态浮层；浏览器证据、数据、下载和高风险审批卡片 | 局部辅助与交互层；浏览器内部卡片当前主要按文档流展示 |
| z-10 | 设置态 ContextBar；浏览器崩溃占位；元素选择结果；时间线渐变；表格和文件树 sticky 层；Git 分组头；草稿品牌文字；右栏分隔条；完整视图悬浮按钮 | 局部内容增强层，低于全局操作层 |
| z-1 | Git diff 行号 sticky 列 | 只解决局部表格内部顺序 |
| auto / 0 | 普通页面、侧栏、会话正文、工具栏、输入区、终端、文档流中的浏览器内部卡片 | 基础内容层；同级时主要按文档顺序绘制 |
| z--1 | body::before 氛围背景 | 装饰背景，不参与交互 |

### 4.3 BrowserPanel 内部的真实顺序

| 顺序 | 内容 | 当前行为 |
|---|---|---|
| 实际最高 | 原生页面视口 | 只要几何重叠，就高于 BrowserPanel 内任何 CSS 卡片 |
| 较高 | 页面对话框、审批、下载、数据、证据等交互卡片 | 003 后主要位于文档流独立区域；部分残留 z 声明在非定位元素上不生效 |
| 中部 | 崩溃占位和元素拾取结果 | 只在自身布局区域有效 |
| 基础 | 标签条、导航工具栏、错误、停止结果、空态、页脚 | 普通文档流，不应靠提高 z 与原生页面争抢 |

### 4.4 结论

**名义最高 Web 层是 z-100；实际视觉最高是显示中的原生浏览器子层。** 当前所有 z-40、z-50、z-60、z-100 浮层，只要与原生浏览器几何相交，都存在同类遮挡风险，而不是只有“确认重连”一个弹框有问题。

## 5. 举一反三：受影响场景矩阵

| 场景 | 风险 | 必须满足的验收结果 |
|---|---|---|
| 重连、移除项目、关闭确认、Desktop 更新 | 文字和主要按钮被遮挡 | 弹框及遮罩完整覆盖，按钮可点击 |
| Agent 权限审批 | 危险操作说明或拒绝按钮被遮挡 | 审批内容完整，默认安全操作可见可用 |
| 退出遮罩 | 原生页面仍亮着，破坏“正在退出”感知 | 退出反馈完整覆盖原生区域 |
| 图片、表格、图表和文档预览 | 预览右侧或按钮被遮挡 | 预览完整，Esc 和关闭动作可靠 |
| 上下文菜单、标签总览、提示和更新说明 | 菜单项或说明被裁掉 | 与浏览器相交时仍完整可见 |
| 工作区认证/阻断页 | 原生页面越过阻断层 | 阻断期间原生页面不可见且不可交互 |
| 完整视图、浮动会话和右栏覆盖模式 | 几何变化后原生页面遮住新浮层 | 原生边界和显隐与新布局一致 |
| 嵌套弹框或连续弹框 | 关闭一个弹框就错误恢复原生页面 | 最后一个阻断层关闭后才恢复 |
| 弹框期间切换会话或关闭浏览器 | 旧页面恢复、串会话或永久隐藏 | 恢复目标属于当前会话，状态不残留 |
| 弹框期间调整窗口和右栏大小 | 恢复后位置错误或首帧黑框 | 先同步最新边界，再恢复显示，无错位和闪烁 |

## 6. 解决方案比较

| 方案 | 做法 | 收益 | 成本与风险 | 结论 |
|---|---|---|---|---|
| A. 全局原生遮挡仲裁 | 阻断层出现时暂停相关原生页面显示；最后一个阻断层关闭后按当前会话和最新边界恢复；局部浮层按实际相交关系处理 | 保留现有全部 Web 弹框，统一解决同类问题，符合原生嵌入常见做法 | 需要集中管理嵌套、切换、恢复和异常路径 | 推荐，需详设 |
| B. 全局弹框改为独立原生顶层窗口 | 每个模态使用独立 Tauri 窗口 | 不必隐藏浏览器 | 大量迁移，焦点、拖动、主题、关闭和多窗口安全复杂 | 不推荐作为本次最小系统整改 |
| C. 继续提高 z-index 或 Portal | 改为更高数值或其他 DOM 容器 | 无 | 无法跨越原生合成层，已证伪 | 放弃 |
| D. 把弹框限制在会话左栏 | 修改布局避开浏览器 | 局部实现简单 | 破坏全局模态语义；窄窗口和完整视图仍会重叠 | 放弃 |

### 推荐整改边界

- 建立一个统一的原生可见性仲裁入口，不在每个弹框里分别拼接显隐逻辑。
- 全局阻断层应具有明确的模态优先级；最后一个阻断层消失前不得恢复原生页面。
- 局部菜单、提示和浮层需要处理与原生视口的相交，不得只验收全屏 Modal。
- 仲裁只改变显示和输入，不销毁标签、不改变会话、不丢失控制权、不清理站点数据。
- 异常、卸载和会话切换必须释放持有关系，不能造成浏览器永久隐藏。
- 003 的文档流成果保持，不退回原生视口上方覆盖卡片。
