## 1. 问题现象与根因

1. 后退/前进可用性来自 BrowserPanel 的 `navigation.index/entries`，不是原生 WebView 历史。Agent 导航、页面重定向和新标签不会可靠进入这套记录。
2. `BrowserPanel.tsx:699-707` 与 `:724-732` 在 Host 异步操作尚未成功时就更新本地历史；失败只设置错误，不回滚 index。
3. `BrowserPanel.tsx:592-608` 导航成功后用用户输入的 target.url 写历史，而不是 Host 返回的实际 committedUrl。
4. 所有标签共享一份 navigation 和 draft；`BrowserPanel.tsx:857-860` 切换标签直接用 committedUrl 覆盖草稿，未提交输入不能按标签保留。
5. onPage 只刷新快照和 loading，没有把原生历史、实际 URL 与当前编辑焦点合并到界面投影。

因此纯函数 `applyBrowserNavigation` 测试即使通过，也不能证明真实按钮和地址栏正确。

## 2. 引入轨迹与测试遗漏

- 初始实现用前端历史模型驱动按钮，原生历史快照契约没有同步建立。
- TD-02-M07/B06/I08 和 TD-08-M09/B07/I07/U09 虽在文档中存在，实际测试主要落在模型状态转换和简单按钮存在性。
- 010/022 的标签测试没有交叉未提交草稿和每标签历史，后续全量绿色未能暴露问题。

## 3. 推荐整改方向（待审核）

原生运行时提供每标签实际历史与已提交 URL 投影；界面按 session/tab/generation 保存编辑草稿。只有真实导航结果才能改变已提交历史，失败保留草稿和原历史。Agent、重定向、后退/前进与恢复共用同一事实来源。
