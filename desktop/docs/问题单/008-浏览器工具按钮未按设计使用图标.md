## 1. 问题现象

### 1.1 实际结果与预期结果

- 实际结果：“拾取”“证据”“停止”“数据”使用文字按钮，与导航按钮的图标语言不一致，并占用更多工具栏横向空间。
- 预期结果：按高保真与界面设计使用统一 SVG 图标；拾取入口采用鼠标指针图形，停止 Agent 和数据管理具有明确图形表达及可访问名称。
- 出现频率：固定存在。
- 首次及最近复现版本：当前开发工作树。

### 1.2 复现步骤

1. 进入会话并打开 Browser。
2. 对比工具栏中的后退、前进、刷新与四个文字按钮。
3. 对照高保真稿和 `04界面交互与证据展示设计.md:31-44`。

### 1.3 影响与风险

- 设计实现不一致，降低工具识别效率和视觉统一性。
- 文字按钮占用额外空间，加剧 004 的窄窗布局压力。
- “停止”不能清楚表达停止 Agent，存在与停止页面加载混淆的风险。

## 2. 问题根因

### 2.1 直接原因

`BrowserPanel.tsx` 直接使用文字节点渲染四个按钮，没有复用统一图标集；统一图标集中也缺少本次需要的鼠标指针、相机、停止方块和数据库图标。

### 2.2 机制层根因

实现只满足了按钮功能入口，没有把高保真和统一图标约束转化为组件验收条件。功能测试关注调用行为，缺少对视觉语言、可访问名称和统一图标组件使用的检查。

### 2.3 证据与排除项

| 结论             | 支撑证据                                       | 已排除的其他解释                 |
| ---------------- | ---------------------------------------------- | -------------------------------- |
| 当前确为文字按钮 | 实际 Browser 截图和 `BrowserPanel.tsx:616-660` | 不是字体或缩放导致图标显示成文字 |
| 设计包含图标表达 | 高保真稿及界面设计中的鼠标指针和标准导航方案   | 不是用户临时新增的产品方向       |
| 功能逻辑无需改变 | 四个按钮已有公共宿主入口和 aria-label          | 本单不是新增浏览器能力或权限变更 |

### 2.4 未确认事项

- 无。图标形状已经用户评审确认；实施与测试仍按 SDD 审核。

## 6. 解决方案

### 6.1 推荐方案

在统一图标集中增加 MousePointer2、Camera、Square、Database，并替换四个文字按钮。保持原公共功能入口、权限和状态不变；按钮保留完整 `aria-label` 并补充 `title`。

- MousePointer2：拾取元素，普通前景色。
- Camera：保存证据，普通前景色。
- Square：停止 Agent 浏览器操作，危险色，不使用大面积红底。
- Database：浏览器数据管理，普通前景色。
- `100%` 缩放比例保留文字；新建标签页继续使用现有 PlusIcon。

### 6.2 方案比较与决策

| 方案                          | 收益                           | 成本与风险                     | 验证结果       | 决策             |

| 引入第三方图标库              | 图标丰富                       | 新依赖和风格一致性成本，不必要 | 已排除         | 放弃             |
| 保留文字按钮                  | 无开发成本                     | 持续不符合设计并占用空间       | 已证伪         | 放弃             |

## 附录 C：工具栏按钮缺少悬浮与按压反馈

### C.1 根因

Browser 工具栏按钮当前只声明 `hover:bg-hover`，没有接入项目已有的 `press` 按压反馈、颜色过渡和清晰的按下状态。项目的 `desktop/src/shared/styles/index.css:739-760` 已定义统一微动效及 `prefers-reduced-motion` 适配，但 Browser 未复用。

因此这是与图标同一界面的交互实现缺陷，归入 008，不与 010 的真实功能失败或 011 的结果反馈缺失混淆。

### C.2 整改补充

- 工具栏按钮复用项目统一的 `press` 和颜色过渡，不另造一套动画。
- 悬浮时提供可辨认的背景或前景变化，按下时提供统一按压反馈。
- 禁用按钮不得出现误导性的悬浮或按压动效。
- 键盘焦点保持清晰可见，不以动效替代焦点语义。
- `prefers-reduced-motion` 下遵循项目既有减少动态效果规则，不能强制播放动画。
- 停止按钮在动效和颜色变化中仍保持危险操作语义。

### C.3 测试补充

| 场景           | 验证方式                                    | 可验证预期结果                                              |
| -------------- | ------------------------------------------- | ----------------------------------------------------------- |
| 鼠标悬浮       | Computer Use 将鼠标移动到按钮并保持，再移出 | 悬浮出现可辨认反馈，移出后恢复；无布局跳动                  |
| 鼠标按下与释放 | Computer Use 分别执行按下、释放和移出取消   | 按下反馈与项目 `press` 一致，释放后恢复，不错误触发其他按钮 |
| 禁用状态       | 页面不可用或动作不可用时悬浮、点击          | 无误导动效，功能不被调用，禁用样式可辨认                    |
| 键盘焦点       | 纯键盘遍历工具栏                            | 焦点清晰，动效不遮挡焦点环，无焦点陷阱                      |
| 减少动态效果   | 启用系统减少动态效果偏好后重复悬浮和点击    | 遵循项目减少动态效果规则，功能与状态文本仍完整              |
| 组件与样式回归 | 前端测试检查公开按钮状态和统一样式接入      | 四个图标按钮与导航按钮使用一致的交互规则，禁用时不触发功能  |

动效验收需要保留悬浮、按下和释放的过程证据，不能只截一张静态图就判定通过。
