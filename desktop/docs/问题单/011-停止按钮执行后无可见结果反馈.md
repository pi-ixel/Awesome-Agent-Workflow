## 1. 问题现象

### 1.1 实际结果与预期结果

- 实际结果：点击“停止”后，原生 `browser_cancel_requests` 返回成功，但用户界面没有可感知变化。没有未决 Agent 动作时按钮同样可点击，仍没有任何说明。
- 预期结果：停止后应显示真实取消结果和当前状态；没有可停止动作时，应禁用按钮或明确说明“当前没有执行中的 Agent 动作”，不能让用户反复点击猜测。
- 出现频率：固定交互缺陷；是否有未决动作只影响后台结果，不改善反馈。
- 首次及最近复现版本：当前开发工作树。

### 1.2 复现步骤

1. 打开 Browser，保持当前没有可见的未决 Agent 动作。
2. 点击“停止”。
3. 原生日志记录 `browser_cancel_requests` 成功。
4. 观察界面，没有成功提示、取消数量、状态变化或禁用反馈。

### 1.3 影响与风险

- 用户无法区分“功能没做”“按钮没点中”“已经停止”或“没有任务可停止”。
- 即使后台安全取消已经生效，用户仍可能重复点击或误以为 Agent 仍在执行。
- 当前没有证据表明取消命令失败；本单是结果可见性和状态反馈问题。

## 2. 问题根因

### 2.1 直接原因

`browser_cancel_requests` 返回被取消的请求 ID 列表，但 BrowserPanel 调用后没有读取返回值，只执行 `setError(null)`。按钮的禁用条件也只有 `!activeTab`，没有考虑未决请求或 Agent 活动状态。

### 2.2 机制层根因

公共入口提供了可投影的真实结果，但 UI 没有把“执行成功、取消了哪些请求、当前无可停止动作”映射到任何状态或文案。功能调用与结果反馈脱节，导致用户看到的界面与未点击前完全相同。

### 2.3 证据与排除项

| 结论 | 支撑证据 | 已排除的其他解释 |
|---|---|---|
| 停止命令实际执行 | 原生日志多次记录 `browser_cancel_requests stage:success` | 不是按钮未接线或原生功能未实现 |
| UI 忽略真实结果 | `BrowserPanel.tsx:640-651` 不接收返回列表，仅清除错误 | 不是后端没有返回取消信息 |
| 无任务时仍可点击 | 按钮只以 `!activeTab` 禁用 | 不是页面不存在导致的统一禁用 |
| 可见反馈缺失 | 点击前后截图无状态变化 | 不是单纯 003 遮挡一个已存在的成功提示；源码中没有该提示 |

### 2.4 未确认事项

- 设计写“停止 Agent 默认作用于当前标签”，当前公共入口为 `cancelRequests(sessionId)`，作用范围是否应调整为当前标签，需要在控制方案评审时单独确认；本单不擅自改变范围。
- 有未决动作时是否已有其他全局状态可间接反馈，需要在真实长动作场景复核，但不能替代本按钮的直接结果。

## 6. 解决方案

### 6.1 推荐方向

将公共入口的真实取消结果投影到界面，明确显示取消是否发生以及当前是否还有执行中的动作。无未决动作时采用可理解的禁用状态或明确提示，具体文案与按钮状态在测试设计阶段冻结。不得伪造成功，也不得只通过颜色变化表达。

### 6.2 方案比较与决策

| 方案 | 收益 | 成本与风险 | 验证结果 | 决策 |
|---|---|---|---|---|
| 使用真实取消结果更新状态并反馈 | 用户能确认停止结果，测试有直接出处 | 需要覆盖空列表、部分取消和迟到事件 | 待验证 | 推荐，待审核 |
| 无任务时禁用，有任务时显示结果 | 避免无意义点击 | 需要可靠的活动请求投影，避免误禁用 | 待验证 | 可组合评审 |
| 保持仅清除错误 | 无开发成本 | 用户始终无法确认结果 | 已证伪 | 放弃 |

### 6.3 实施范围

- 修改 BrowserPanel 停止结果投影、按钮状态和相关测试。
- 不改变取消范围、权限、控制模型或 iCode；范围问题另行评审。
- 008 手工验收必须覆盖有任务和无任务两条路径。

### 6.4 测试与验收标准

| 验收项 | 可验证预期结果 | 证据要求 |
|---|---|---|
| 有未决动作 | 点击停止后真实请求取消，界面显示取消结果，无后续自动动作 | 请求状态、截图和页面结果 |
| 无未决动作 | 按钮禁用或明确提示无可停止动作 | 按钮状态和可见文案 |
| 重复点击 | 不伪造新增取消，界面保持真实空态 | 两次返回和状态 |
| 部分取消与迟到结果 | 不显示全部成功，迟到结果不复活动作 | 请求清单和实际页面 |
| 作用范围 | 当前标签、会话和其他会话符合获批范围 | A/B 请求状态 |
| 键盘与提示 | aria-label、title、焦点和禁用状态正确 | 可访问性证据 |
