## 1. 问题现象

### 1.1 用户可观察现象

开启元素拾取后，用户单击一个元素，拾取持有状态立即被取消，无法继续框选下一个元素。

- 实际结果：单击即退出拾取，按钮回到未拾取状态。
- 预期结果：单击只把当前元素加入会话引用，拾取保持激活；只有再次点击拾取按钮、Esc、显式取消或页面导航才退出。
- 出现频率：必现。
- 首次发现版本：当前主线。
- 最近复现版本：同上。

### 1.2 复现步骤

1. 打开内嵌浏览器并点击「拾取元素」。
2. 移动鼠标到任意元素并单击。
3. 观察拾取按钮与底部「正在拾取」提示是否消失。

### 1.3 影响与风险

- 多元素连续采集被迫反复开启拾取，操作路径变长。
- 不改变元素引用内容与权限模型；修复后仍需阻止单击触发页面业务动作。

## 2. 问题根因

### 2.1 直接原因

拾取脚本的 `select` 在 `post(selected)` 之后调用 `cleanup()`，同时 BrowserPanel 的 `onElement` 监听把 `picking` 置为 false，两层共同导致单击即退出。

### 2.2 机制层根因

1. `src-tauri/src/browser/enhancements.rs` 的 `select`：`event.preventDefault()` 与 `stopImmediatePropagation()` 后执行 `post(selected); cleanup();`。
2. `cleanup()` 移除全部监听、观察器、高亮与光标样式，并把 `state.status` 置为 `inactive`。
3. `src/plugins/browser/ui/BrowserPanel.tsx` 的 `onElement` 在收到元素事件时 `pickingRef.current=false; setPicking(false)`。
4. 037 只调整更新调度，没有修改 `select` 或 `onElement`；`git show HEAD` 证实单击清理在性能整改前已存在。

### 2.3 证据与排除项

| 结论                     | 支撑证据                                            | 已排除的其他解释       |
| ------------------------ | --------------------------------------------------- | ---------------------- |
| 单击退出不是 037 引入    | HEAD 的 `select` 同样包含 `cleanup()`               | 不是帧合并导致状态丢失 |
| 脚本与前端同时退出       | `cleanup()` 与 `onElement` 置 false 两处证据        | 不是单纯按钮文案问题   |
| 单击仍应阻止页面业务动作 | 既有 `preventDefault` 与 `stopImmediatePropagation` | 不需要放开页面默认行为 |

### 2.4 未确认事项

无。用户已明确期望连续拾取行为。

## 6. 解决方案

### 6.1 推荐方案

- `select` 继续 `preventDefault` 与 `stopImmediatePropagation`，继续 `post(selected)`，但不再调用 `cleanup()`。
- 单击后清空当前悬停目标与高亮，保留拾取监听、光标样式和 `status=active`，等待下一次框选。
- BrowserPanel `onElement` 不再把 `picking` 置 false；拾取按钮保持激活，只有再次点击按钮、Esc、显式取消、页面导航或会话切换才退出。
- pick 事件载荷、引用落库与会话消息流程不变。

### 6.2 方案比较与决策

| 方案                              | 收益             | 成本与风险                       | 决策 |
| --------------------------------- | ---------------- | -------------------------------- | ---- |
| A. 单击后保持拾取                 | 符合连续框选预期 | 需要同步脚本与前端两处状态       | 采用 |
| B. 保持单击退出                   | 不改代码         | 与用户明确预期冲突               | 放弃 |
| C. 单击后由前端重新调用 pickStart | 看似保持         | 重复注入与状态闪烁，增加原生调用 | 放弃 |

### 6.3 实施范围

- 需要修改：拾取脚本 `select`、BrowserPanel `onElement`。
- 明确不修改：037 调度实现、pick 事件契约、取消与导航清理路径。
- 需要同步的文档与测试：本问题单、`039实施状态.md`、拾取脚本行为用例、面板 picking 用例。
- 需要人类执行或决策的事项：无，用户已明确期望。
