# CodeAgent 压缩历史验收（Issue #336）

## 行为

- 仅 CodeAgent 适配器启用历史证据读取；ICode 归档、其他 Agent 和实时用户输入保持原有语义。
- 使用实际启动 cwd 定位 `~/.cac/projects/<Unicode slug>/<sessionId>.jsonl`。首行必须匹配会话 ID 和路径身份；直接路径不可用时只扫描根目录的直接子目录，扫描不完整或候选不唯一时保留原文。
- 原生端只读 JSONL，返回用户文本的 SHA-256、UTF-8 字节数、来源标识和压缩标记，不返回或记录消息正文。
- 同时考虑普通用户文本和摘要文本；只有全文指纹唯一、来源标识唯一的纯文本摘要才可转换。同文真实用户消息、重复摘要、带附件条目均保留原文。
- ACP 回放必须有 messageId、分片连续且加载成功；无 ID、交错分片或开始了实时轮次时不转换。加载前后源文件版本变化时，本轮不转换。
- 历史校验期间继续展示原快照，避免显示尚未验证的压缩摘要；完成后统一替换。加载失败、关闭或连接恢复不能把半截历史覆盖为有效快照。
- “上下文已压缩”是独立的可持久化条目，不计用户轮次、不折叠进其他轮次的工作过程。普通系统错误提示仍不进入历史。
- 本地旧快照、图片记录和轮次元数据分别匹配，不共享位置计数。旧快照须与源日志的连续用户记录唯一对应，并有普通用户消息作为锚点（或覆盖完整源记录）；孤立片段不转换。匹配不明确时保留原记录，不把图片或用量迁到其他用户消息。
- 旧累计轮数只有在完整用户序列与 JSONL 一致、且原轮数也与该序列一致时才修正；不重算时长、Token 或截断快照的累计值。
- 收养工作流会话只处理恢复的本地快照，不对常驻的实时消息监听执行摘要过滤。重连保留已验证历史。

## 资源与降级

- 原生端：文件最多 64 MiB、单行最多 2 MiB、候选首行最多 16 KiB、最多 20,000 条用户记录；反查最多 512 个目录项、3 秒预算，整个读取过程 5 秒预算。
- 前端宿主等待上限 6 秒；回放识别的文本总量最多 16 Mi 个 UTF-16 代码单元，单条最多 2 Mi 个代码单元；旧快照序列对齐最多比较 200,000 次，超出即保留原文。
- 缺文件、无权限、格式变化、尾行未写完、超限、歧义、指纹计算不可用均保留原文，不阻断普通 ACP 历史加载。
- 这些上限是保守降级阈值，不代表 CodeAgent 会话本身的限制。未读取真实用户会话日志；自动化使用合成夹具。

## 自动化回归

- `src-tauri/src/codeagent_history.rs`：Unicode 路径、路径身份校验、反查歧义、损坏/半行、文件与单行限额、未知内容格式、附件、版本变化和只读保证。
- `tests/plugins/project/conversation/historyCompaction.test.ts`：多次压缩、相同前缀、全文重复、附件、无 ID、分片交错、实时轮次、持久化、独立呈现、保守修正累计轮数及指纹不可用。
- `tests/plugins/project/conversation/SessionFactory.compaction.test.ts`：实际加载接入、图片恢复、旧快照预处理、重复加载、源文件变化、读取失败、加载失败、并发加载、关闭/恢复失效、校验期间实时更新和其他 Agent 隔离。
- 同时运行 conversation、realRuntime、projectSession 和 architecture 回归，检查已有会话行为与插件边界。
