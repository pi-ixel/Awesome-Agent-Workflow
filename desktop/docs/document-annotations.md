# 文档批注

在文件预览中选中文本，点击「批注」，填写意见后「添加到会话」。意见可留空，作为原文引用。代码和纯文本还可从行号开始拖选行范围。

支持 Markdown 渲染预览、代码和纯文本；不支持图片、PDF 或图表中的图形选区。Markdown 不宣称精确源码行号。

## 使用与恢复

- 引用卡片进入文档所在项目的当前会话；没有当前会话时进入项目新会话草稿。
- 卡片可修改意见、删除，点击文件名回到原文；文档中的待发送标记也可点击编辑。
- 草稿按项目与会话隔离，保存在本机。会话切换、应用重启后可恢复；原文件不会被改写。
- 添加时固定原文快照。回跳会重新读取文件，使用文本及前后文匹配；原文被删除或匹配不唯一时提示，不替换旧快照。
- 提交被本地发送流程接受后，移除输入框卡片和文档标记。待确认消息的快照暂存在同一草稿记录中，ACP 请求完成后清除。
- 发送失败、队列取消或应用重启导致状态未确认时，可手动「取回输入框」。先核实会话是否已执行，程序不会自动重发这些消息。
- 历史消息显示引用卡片；「填回输入框」会恢复原文和批注意见。

每条消息最多 20 条批注，单个选区最多 10000 字、意见最多 2000 字，序列化引用合计不超过 100000 字符。超限或保存失败会提示并保留当前编辑内容。

## 实现约定

- `core/documentAnnotations.ts`：引用数据、文本锚点和 ACP 文本封装。引用通过普通 `session/prompt` 文本传输，不要求 Agent 支持批注私有协议；历史回放与队列沿用原文本通道。
- `stores/annotationDraftStore.ts`：使用现有草稿 scope 派生的存储键，维护未发送引用及待确认提交；新会话转正时显式迁移。
- `ui/right-panel/FileAnnotations.tsx`：原生选区、编辑浮层与独立 CSS Highlight；不插入 `<mark>`、不重建 Markdown DOM。文档搜索命中高亮优先。
- 文本定位依赖当前渲染文本及上下文；源码使用逻辑行号，长文件先展开目标行再滚动。DOM Range 不写入持久化数据。
- 历史引用的定位高亮为短暂提示，不作为当前会话的待发送标记。

## 验证

自动化用例覆盖 ACP 文本往返、无正文发送、草稿隔离与恢复、存储失败、提交失败与重试、新会话迁移、历史卡片回填，以及 Markdown/代码文本索引。

浏览器验证覆盖跨行内样式选区、编辑过程中切换会话、重载恢复、删除高亮、代码行范围、千行以后的定位和深浅主题。
