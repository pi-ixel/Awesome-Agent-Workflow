# Desktop Cordis 插件架构与职责边界

日期：2026-11-09。

状态：本轮 Cordis 迁移已验收。公开接口见各插件的 `service.ts`，验证依据见[项目移除与服务验收](../history/cordis-plugin-migration.md#项目移除与服务验收)。

保留现有 Cordis、连接池、工厂和运行时重构成果，按职责逐步归位，不因插件改名重写已有机制。本文定义目标边界；[现有 ACP 运行时设计](../history/acp-runtime-design.md)用于核对当前实现和迁移进度。

## 1. 架构原则

- Cordis 是 Desktop 前端内核。有状态、有副作用、有生命周期的能力由插件承载，Rust 保持宿主实现。
- 插件内部可以有多个功能模块。组件、算法和纯类型不必分别成为插件。
- 状态只有一个所有者，其他插件通过公开服务调用或订阅，不直接修改内部 store。
- 业务服务独立于 UI 装配。UI 部分向工作台注册，不加载工作台时核心服务仍能运行。
- 必需依赖通过 Cordis 注入，可选能力通过注册契约接入，禁止跨插件导入内部实现。
- 资源由创建者释放。工作台协调应用退出，各插件完成自己的业务收尾和资源释放。
- 公共操作契约需明确失败结果、完成通知、取消和释放行为。

核心依赖方向：

```text
project → acpRuntime → acpConnection → host → Rust
```

`agents` 从侧面提供启动描述与增强实现。通用运行时不直接导入厂商增强目录。

## 2. 插件与目录

共 15 个插件。以下为目标目录，保留讨论确定的 `acpConnection`、`acpRuntime` 命名；迁移时需同步更新工程约定中的目录规则。

```text
src/
  bootstrap/                  # 创建 Cordis 根上下文、装配插件
  contracts/                  # 窄公共协议契约，领域契约随迁移归各插件
  plugins/
    host/
    configuration/
    diagnostics/
    agents/
      enhancements/
        icode/
        codeagent/
    acpConnection/
    acpRuntime/
    project/
    documents/
    git/
    terminal/
    workflow/
    skills/
    account/
    updates/
    workbench/
  shared/                     # 通用工具、展示组件、无状态日志接口
```

每个插件的根目录必须有 `index.ts` 和 `service.ts`，按需提供 `types.ts`、`events.ts`、`config.ts`。业务实现按职责放入子目录，功能专属 UI 随所属模块放置。入口装配服务与 effect，`service.ts` 声明该插件在 Cordis 上下文中的服务名，并按实际调用方定义服务契约。

插件向外提供的运行时能力统一由根目录的 `service.ts` 和 `events.ts` 暴露。其他模块可以用 `import type` 引用 `types.ts` 的公开类型。`config.ts` 和业务子目录由所属插件直接访问。Bootstrap 通过 `index.ts` 装配插件。

主窗口启动层通过各插件 `index.ts` 的 `installWorkbench` 按序安装 UI Fiber。Workbench 自己注册设置页和通用设置，Agents 的入口同时装配关于页贡献与 Agent 设置。独立诊断窗口从 Diagnostics 的公开入口加载视图，仅装载基础服务。

目录迁移和服务边界的实施记录见[迁移记录](../history/cordis-plugin-migration.md)。

configuration 负责配置存取，不承载全部业务数据。会话历史、草稿、文档内容等由对应插件管理。

启动装配在安装 Host 前创建本根日志缓冲，安装 Diagnostics 时传入同一缓冲，保留先到的宿主日志。浏览器异常监听归主窗口采集 Fiber，原文使用独立队列和原生读写入口。独立诊断窗口持有自己的日志状态，通过原生查询查看主窗口已落盘记录。

Windows 进程资源采样由原生宿主持有，采样线程与应用进程同寿命，缓存最近 15 分钟汇总。Agent 进程登记和 Job Object 标识由 Host 的 ACP 进程生命周期提供。acpRuntime 在握手成功后根据协商能力为连接配置只读测速方案，acpConnection 负责空闲准入、计时、超时取消和结果快照。Project 通过运行时通道传入规范化项目键，Bootstrap 将快照组合到诊断采集中。独立诊断窗口通过宿主读取采样和快照，并经有界请求队列要求主窗口测速。

旧版 Desktop 设置继续使用 `aaw-desktop.settings.v1`。多个插件可以在同一记录登记各自的字段，登记冲突会失败，写入时保留其他字段。Workbench 持有主题、语言和字号，在自己的 Fiber 中订阅并应用到主窗口根元素，卸载时撤销绑定。Project 持有审批策略、自动应答、会话宽度、任务步骤显示和自动归档偏好。会话回调和 Project 注册的界面都读取当前 Project 实例。Skills 持有技能来源路径。项目健康检查和工作流查询通过可选接入读取该路径，只有未显式配置工作流脚本时才用它推导脚本路径。

### 3.1 诊断存储页

Diagnostics 在主窗口接收所属插件登记的存储分类。独立诊断窗口通过 Host 的同源窗口请求通道查询统计、请求清理预览及提交已确认的清理。视图持有筛选条件和操作结果。主窗口注册表持有短期确认凭据及其对应的记录版本。插件卸载时撤销分类并使相关确认失效。

Project 统计会话快照、队列、草稿、图片和输入历史，并在删除时核对记录版本和会话状态。图片删除与该存储的保存操作串行执行。图片草稿编辑器持有整份草稿映射，编辑器挂载期间保护全部图片草稿。会话标题、置顶与归档目前只展示占用。Configuration 负责配置写入与保存重试。Project 与 Workbench 分别定义自己的默认值。Workbench 的外观能力由启动层装配到 Diagnostics。Agent 配置当前展示占用和保存异常。登录状态、Agent 原始会话及项目文件不属于清理范围。

日志文件统计与删除由 Rust 实现，并与写入共用锁。文件在确认后变化时跳过。清理日志不改变既有的保留期限与容量策略。

### 4.1 增强隔离

- agents 是一个插件，ICode 和 CodeAgent 增强是内部隔离模块。
- 通用管理不解释厂商私有字段，两种增强互不依赖。
- acpRuntime 通过公开接口获取增强，不直接导入具体增强目录。
- project 只消费统一模型，不识别厂商私有报文。
- 不注册某个增强时，其他增强与普通 ACP Agent 仍可运行。
- 会话启动、连接测试和协议自检统一经 acpConnection 申请传输。acpRuntime 注册隔离探查会话工厂，并随 Fiber 装卸启用或撤销。路径探测和启动校验使用 Agents 从 Host 注入的命令端口。

### 4.2 协议与产品边界

| 场景 | project 的产品职责 | acpRuntime 的协议职责 | acpConnection 的连接职责 |
| --- | --- | --- | --- |
| 创建会话 | 项目/Agent 归属、草稿转正式会话、列表更新 | 创建协议会话并返回身份与能力 | 分配连接、完成请求收发 |
| 发送消息 | 内容、附件、能力检查、排队、消息展示 | 执行 prompt，处理响应和增量事件 | 调度请求、传输报文 |
| 审批/表单 | UI、自动应答策略、用户选择、待办状态 | 解析请求、关联应答、处理协议取消和失效 | 请求关联与响应收发 |
| 恢复会话 | 恢复目标、提示/重试策略、历史展示 | 执行 load、恢复协议绑定、报告结果 | 提供可用连接 |
| 关闭项目 | 处理运行任务、未发送及未保存内容等关闭规则 | 结束关联协议操作、释放会话绑定 | 释放租约，按策略回收连接与进程 |

Project 的 `ProjectFactory` 和 `ProjectContext` 管理项目归属、历史目录快照和预热。`acpRuntime` 通过公开端口提供远端目录分页、协议会话及恢复。`acpConnection` 管理物理通道、连接池和请求调度，通过 Host 的公开端口和类型使用进程与传输。标准 ACP 线协议继续独立于插件实现。

## 7. 状态所有权

| 数据或状态 | 唯一所有者 | 其他插件如何使用 |
| --- | --- | --- |
| 当前默认 Agent | agents | project 创建/迁移草稿时读取，正式会话保留自身绑定 |
| 会话所属项目与 Agent | project | 传给运行时建立绑定，不随全局 Agent 选择变化 |
| 物理连接存活状态 | acpConnection | acpRuntime 订阅并转换为协议会话状态 |
| ACP 执行状态 | acpRuntime | project 投影为 UI 状态，不维护独立的执行真相 |
| 草稿、消息流、待审批项 | project | UI 读取，用户操作调用公开命令 |
| 反向请求是否可应答 | acpRuntime | project 据失效事件结束待办，回答时运行时再次检查 |
| 文档未保存内容 | documents | 项目关闭与应用退出通过检查接口询问 |
| 活动页面、面板和布局 | workbench | 功能插件通过导航与视图接口操作 |

## 8. UI 装配与协作

- Project 注册项目树、总览、会话页、标题区、连接失败横幅和退出确认的待办详情。Workbench 装配侧栏容器、标题栏、底部菜单、会话完整视图和退出弹窗外壳。
- Project UI Fiber 持有项目树展开、会话分页、列表视角与新建面板。Workbench 保存侧栏容器的尺寸和收起态，并在视图成功打开时通知 Project 收起新建面板。
- Account 注册登录表单，Workbench 提供全屏登录容器和窗控。各插件装配界面时注入所需的业务能力，Workbench 提供界面注册、通用导航和布局订阅。
- 页面注册方声明默认页和完整视图。Project 注册总览及会话页，Workbench 根据注册信息选择页面、标题和完整视图宿主。Documents 从批注打开会话，Workflow 查询或打开会话页，两者都使用 Project 的会话能力。
- Workbench 通过 `Window` 提供主窗口视图，内部组装登录门槛、工作区、弹层和退出确认。启动层挂载当前 Workbench 实例，替换实例时重建视图。
- Documents 从 Project 获取批注编辑目标、只读批注列表和写入命令。Project 管理目标与草稿存储键的映射，普通会话切换保留编辑目标，草稿转正时发布目标替换。
- 外壳按位置装配帮助菜单项、顶栏指示和弹层。诊断插件提供帮助项，更新插件提供完整和紧凑指示。窗口弹层始终挂载，工作区弹层受登录门槛控制。
- Documents 登记路径解析与未保存检查，由 Documents 决定文件或目录标签及其定位数据。Workbench 检查项目和注册是否仍有效，再打开返回的通用标签。Project 会话视图直接接入文件候选、批注跳转和查找快捷键，文档视图通过 Project 注入接入批注草稿和会话命令。
- 设置页由 Workbench 组合，各插件提供自己的设置项、UI 和重置范围，Configuration 负责存取。恢复默认的确认内容随注册加入或撤销。
- Project 工具设置页通过可选的 Skills UI 服务挂载源目录与安装器。会话装配直接传入打开诊断和归档设置的命令，编辑工具卡使用 Project 已接入的 Git 审查能力。
- 设置词条由实际使用的插件维护，共享国际化只提供语言类型和翻译回退。
- 文件、Git、终端、工作流拥有自己的状态和 UI，通过项目标识、路径和公开接口关联项目。
- Documents、Git、Terminal、Workflow 在自己的 UI 注册中声明启动入口。Workbench 按注册项装配新标签页和底部面板开关，只持有打开的面板 ID，向底部面板传入可见性和关闭命令。
- 右栏标签由注册插件提供标题、图标、搜索字段和可选徽标。Workbench 管理标签引用、顺序、激活、最近关闭和布局比例。启动层将 Documents、Git、Workflow 的历史布局规则交给 Workbench，旧版标签载荷保持平铺，其他标签使用独立载荷。
- Workflow 持有时间线抽屉的开合与持久化偏好。Project 通过可选的 Workflow UI 服务取得总览、时间线和抽屉状态查询，抽屉展开时会话的 Esc 停止让位。
- 有明确结果的操作使用 service 调用；已发生事实使用事件通知；可选能力和视图使用扩展注册。
- 跨插件的先后操作须有明确编排负责人。切换 Agent 时的草稿迁移、新会话准备和发送状态变更由 project 协调，不能依靠多个监听器碰巧按正确顺序执行。
- 插件注册视图时传入所需的命令和只读状态。Project 视图使用自身的导航快照，文件树和本地文件链接由 Documents 的导航服务打开。业务视图通过 Workbench 读取全局界面语言。共享分隔线处理拖拽和键盘操作，Workbench 保存侧栏宽度，Git 保存审查导航宽度。
- 布局、前台会话和工作流快照分别归 Workbench、Project 和 Workflow。界面订阅快照并调用公开命令。回放、审批回调和工作流数据源绑定由各自的插件管理。

## 9. 关闭与释放

### 9.1 关闭或移除项目

总览的「关闭项目」退出前台工作区，已打开的工作会话继续运行。项目树的「从列表移除」确认后由 Project 检查目标项目的未保存内容，收尾该项目的会话、终端和文档资源。检查通过且收尾完成后才移除列表项。取消、检查撤销或收尾失败时保留列表项。

### 9.2 退出应用

退出协调属于 workbench 的内部模块，不单设 lifecycle 插件。

1. 关闭窗口、菜单退出、更新安装统一进入请求退出接口。
2. 收集各插件的退出检查，在资源销毁前完成用户确认；取消退出时保持应用可用。
3. 确认后进入退出状态，停止接收新业务操作，执行各插件收尾。
4. 先结束业务执行，再释放协议会话、连接和宿主资源，最终关闭窗口或交接安装。

各插件负责撤销自己的注册项、监听、定时器和 UI。未完成操作应得到明确的取消或失败结果，不能留下永远挂起的请求。具体退出超时与失败策略需在接口实现时明确。

## 10. 重构验收约束

- 依赖守卫禁止跨插件内部导入，禁止底层反向依赖业务 UI。
- 公共契约和共享代码不导入插件实现或应用装配代码。
- 通用链路禁止直接导入具体厂商增强，覆盖不注册增强时的标准 ACP 运行场景。
- 状态归属测试覆盖 Agent 切换、草稿迁移、正式会话归属及跨会话隔离。
- 生命周期测试覆盖注册撤销、请求取消、重复关闭、资源释放及未保存检查。
- 服务测试可不加载 workbench，UI 测试通过公开服务或明确替身驱动。
- 迁移逐项记录现有实现位置、目标插件、公开契约及验证结果，不将目录移动视为职责迁移完成。
- 实现阶段同步更新架构说明和工程约定，避免旧目录与旧调用链继续作为当前事实。
