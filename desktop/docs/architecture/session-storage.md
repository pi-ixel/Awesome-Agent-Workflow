# 会话存储与升级迁移

本设计约定 Desktop 自有数据的归属、升级边界和验收条件。Agent 继续管理自己的原始历史。浏览器 MCP 控制开关和发送策略另行讨论。

## 数据布局

```text
<设置中的数据目录>/
  agents/<稳定注册 ID>/projects/<项目名~路径短标识>/
    project.json
    draft/
    sessions-index.json
    sessions/<ACP 会话 ID>/
      identity.json
      titles.json
      messages.json
      queue.json
      composer.json
      attachments/messages.json
      attachments/draft-images.json
      browser/
      turns/
  configuration/
  runtime/
    session-deletions/
    session-recovery/
    turn-workspaces/
    turn-locks/
    workspace-baselines/
  migration/
  statistics/
```

项目目录后缀取规范化完整路径的 SHA-256 前 12 位。普通 ACP 会话 ID 原样用作目录名。磁盘键应能安全表示 Windows 保留名、斜杠和大小写敏感的协议 ID。元数据保存原始身份。Agent 更新可执行路径后仍使用原注册 ID；项目移动到新路径后按新项目管理。同名项目按完整路径区分。草稿按 Agent 和项目隔离，正式建立会话后交接给对应会话。升级丢弃旧版项目级未发送新会话草稿，包括图片，保留已有会话的草稿和附件。

会话目录承载本地消息快照、队列、输入历史、附件、手动标题、浏览器恢复数据、Diff 摘要和撤销数据。Git 工作树属于项目。归档只更改索引状态；设置页清理仅处理选中的可清理数据。彻底删除遵循 Agent 原始历史核验与本地收尾流程，独立用量统计继续保留。调整存储位置必须覆盖会话目录、索引和外置恢复日志。

项目名称和关联目录随现有 工作区配置保存，键为归一后的主目录。会话创建、历史载入和项目目录变更使用该配置。已生效的目录与历史目录引用保存在正式会话的 `composer.json`，按主项目、稳定 Agent ID 和会话 ID 归属。已有会话在本轮结束后用原会话 ID 重载，新范围生效前暂停发送。关联目录的 CodeAgent 日志 Diff 沿用主会话 `turns/<工作目录键>/` 的目录布局。

## 启动迁移与结果

升级后的主窗口在启动业务读写前显示迁移弹窗，占住工作台并自动执行。按会话列举源记录并确定稳定 Agent ID、项目路径、ACP sessionId。手动标题能唯一匹配时迁入，未能归属时保留旧记录。迁移写入临时目标、校验并发布；中断重启从已确认的位置继续。盘点、归档、会话列表和删除必须使用同一归属规则。

| 条件                                                                 | 处理                                                                                                                                                                                       |
| -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 不同旧 Agent 启动配置归属同一会话且均有有效消息快照                  | 以快照内的保存时间选择工作副本。另一份原文按 SHA-256 校验后保存在该会话的 `snapshot-versions/`。同一会话有多份图片历史或待发队列时，选择与工作快照配置键一致的版本，另一个版本也完整保留。 |
| 某条会话的一项旧历史确认损坏                                         | 在目录外持久化三个身份字段与清理状态，读回核验，再清理该会话全部 Desktop 旧历史及已迁入部分，保留会话记录。                                                                                |
| 无法确认身份、写日志失败、权限不足、磁盘满、目标离线、新副本校验失败 | 保留源数据，显示原因与重试入口。                                                                                                                                                           |
| 清理过程中退出                                                       | 重新核验外置日志，继续清理该会话，完成后记录实际结果。                                                                                                                                     |

旧的无 Agent 快照在会话索引、恢复记录、用量和本地项目引用中均无匹配，且项目仍可访问时删除，并列出删除的条目。无法判断时保留副本。原生锁与协作索引归入 `runtime/`，旧数据回读标记归入 `migration/`。兼容旧版唤起协议的进程锁和通知转发地址仍位于原固定位置。

迁移结果分别报告已完整迁移、已清理本地历史但仍保留会话记录、等待重试的条目。保留记录在侧栏正常显示。首次打开才通过原 Agent 的 ACP 加载并重建本地目录。只有明确的会话不存在或已确认不支持恢复才删除 Desktop 记录；Agent 未安装、断连、启动失败、超时等保留记录。

每个已归属的浏览器恢复记录保存在会话的 `browser/` 下。全局清单保存版本、修订记录的文件引用和手动浏览窗口。Diff 原文、摘要和撤销数据保存在会话的 `turns/<工作目录键>/` 下。工作区索引按实际工作目录查找同时修改同一批文件的会话。迁移保留旧目录哈希对应的原始路径关系，不能唯一归属的记录保留在原位置并报告。

Windows 上同时核对旧版原生路径哈希与当前规范化路径哈希。工作目录和 Agent 会话均匹配后，将旧 Diff 发布到当前读取入口对应的目录。

恢复日志独立于会话目录。原生历史清理结束后，主窗口还会清理属于该会话的 WebView 备份，再开放工作台。ACP 临时失败保留入口。成功回放后须等消息快照写入完成才结束恢复。可在 Windows 的 `desktop` 目录运行 `npm run test:recovery:native` 复测真实 WebView2 与本地 ACP 测试进程；`node scripts/test-update-command-ipc.mjs --isolated-session-absent` 验证 Agent 明确返回会话不存在的分支。

## 验收

Windows 上在 `desktop` 目录执行 `npm run test:migration:crash`。用例在写清理日志前、会话目录删除后和原生清理完成后三次强退同一隔离实例，随后启动工作台并验证 ACP 恢复。

`npm run test:migration:lifecycle` 在同一批旧会话上验证逐项报告、真实迁盘重启、项目归档、按修订号清理队列、任务引用阻止删除、CodeAgent 源文件和本地目录删除、迟到写入受阻及独立统计保留。源文件位于测试程序专用的模拟用户目录。

运行同一命令时设置 `AAW_ARCHIVE_DELETE_BENCH=1`，从 Windows Desktop 的删除确认按钮点击计时，直到归档列表清空。基准覆盖 20 次普通单条、10 条和 100 条批量，以及约 51 MiB 的旧历史。设置 `AAW_ARCHIVE_DELETE_VERIFY_MISSING=1` 可在生命周期用例中追加源文件缺失和已开始条目重启恢复的验证。

项目索引保存原始 ACP 会话 ID。索引变更原子发布，在索引发布期间异常退出，下一次写入根据会话身份重建索引。盘点直接读取已发布的索引。彻底删除后，外置删除标记阻止迟到写入重新创建目录。

CodeAgent 归档删除按项目和会话 ID 定位源历史，直接通过文件系统删除。源文件已缺失时继续清理本地归档。每条会话独立记录删除进度，批量逐条执行，重启时只恢复已开始的条目。

本地删除按会话目录与已知旧键收尾。先提交外置删除标记，再把目录原子移出 `sessions`，从项目索引移除对应 ID。项目锁内更新目录位置与索引，释放锁后递归清理移出的目录。索引缺失、损坏或发布中断时才重新盘点该项目。

- 两个项目及多个 Agent 的草稿、队列、附件和标题互相隔离；升级可执行文件后仍可找到原会话。
- 在确认日志前、清理中、清理后分别强制退出，重启后只处理原目标，报告与磁盘结果相符。
- 在 100 MiB 旧历史夹具上验证迁移、磁盘故障重试、单会话损坏及其他会话完整性。
- 验证迁盘、归档、按类别清理、彻底删除、任务引用和独立统计。
- 进入工作台后，已连接会话通过输入框提交至测试 Agent 的 stdin 收到 session/prompt，每次不超过 500 毫秒。
