### 批次 1 落点

- `src/contracts/host.ts` 定义 ACP 进程端口。`src/plugins/host/` 封装现有原生命令和事件。根上下文先装配 `host`，既有 ACP 底座通过 Cordis 注入端口。
- 正式会话从既有连接工厂进入宿主服务。设置页的独立探测使用同一个 Tauri 适配实现，后续随 `agents` 迁入服务入口。
- 传输保留先订阅再启动、早期输出回放及按句柄过滤。部分订阅或启动失败时撤销监听。连接关闭等待句柄释放，重复释放合并为一次。
- 新增部分订阅失败回滚、Cordis 宿主注入及等待释放两个用例。原有 CodeAgent 路径与探查断言随工厂签名适配。

### 批次 2 落点

- `configuration` 从 `host` 获取存储，按键注册、读取、合并写入及订阅。旧设置 store 的生产写入接入 Cordis 注册，保留 `aaw-desktop.settings.v1`、旧值迁移及未知字段。旧 store 的同步启动和业务规则随对应所有者后续迁移。
- `diagnostics` 持有主窗口的日志批量写入、ACP 原文、性能采样和异常心跳。卸载时停止定时器、撤销监听，并在预算内排空，迟到的 IPC 响应不能发起下一次写入。
- 独立诊断窗口只装配 `host`、`configuration`、`diagnostics`，经读取服务完成查询、快照、原文与导出。现有 UI 的窗口打开入口保留，待 `workbench` 统一装配。
- `force_close` 与 `update_install` 保持落盘优先。采集器已停止时，退出命令可通过诊断钩子补写自己的开始记录。
- 新增用例覆盖配置注册和释放、独立窗口读取旧主题、卸载前后落盘、IPC 卡住时的退出，以及两个原生退出命令的调用顺序。

### 批次 3 落点

- `src/plugins/agents` 负责注册表、默认选择、自定义配置、扫描与探测。Agent 配置规则归插件，迁移期继续使用原设置 store 作为状态容器，并通过既有配置作用域持久化。
- 正式会话从 `AgentsService` 获取适配器和启动描述，设置页通过服务扫描、测试连接和运行协议自检。三条生产路径共用已注入的原生传输工厂，协议自检的隔离传输由 `agents` 负责释放。
- ICode 和 CodeAgent 位于独立增强目录。公开适配契约位于 `src/contracts/agentAdapter.ts`，厂商实现只经内置注册入口装配。依赖守卫覆盖通用链路和两个增强之间的隔离，禁载增强用例通过真实 Cordis 注册路径检查标准 Agent。
- 默认 Agent 切换仍由原运行时协调。会话继续持有创建时的适配器及启动描述。本批保留现有 ACP 类与探查协议调用，协议与产品边界在下一批收口。
- 草稿与目录的 Agent 身份由同一套启动描述规则纯计算，侧栏、归档和右键菜单在服务就绪前仍可读取目录。实际建立连接使用 `AgentsService`。

### 批次 4a 落点

- 主窗口按 `acpConnection`、`acpRuntime`、`project` 注册服务。`project` 接管项目登记、目录预热订阅、聚焦和重命名入口，打开、关闭及恢复会话委托 `acpRuntime`。
- `project/catalog.ts` 和 `project/catalogStore.ts` 持有 Agent 目录缓存、标题和条目合并、状态更新。按 Agent 隔离缓存，保留项目路径归一化和本地已知会话。迟到的旧 Agent 目录或错误状态不会覆盖当前目录。
- `acpRuntime/catalogHistory.ts` 负责远端目录分页、请求超时及重复游标检查，`ProjectContext` 继续隔离不同项目的运行资源。`acpConnection` 继续使用现有物理连接、调度器和连接池实现。
- 应用退出时先关闭 `project` 入口并撤销预热订阅，再关闭协议会话、独立探测和物理连接。现有运行时组装桥继续承接底层会话创建、恢复和关闭。草稿转正、消息、队列、审批、表单与相关视图状态留待 4b。

### 批次 6b 落点

- `git` 持有每项目状态查询、缓存、刷新及监听，统一右栏 Git、差异页与会话状态条的状态读取。Git 状态与差异请求经 `host.git` 调用宿主。审阅解析和差异缓存归 Git 目录。
- Git 插件注册两个右栏视图。文件树从主窗口接收可选的 Git 状态读取函数，文档核心服务可独立加载。独立诊断窗口不装配 Git。
- 移除最后一个订阅时停止刷新与监听，插件卸载时主动释放仍在使用的查询。迟到的监听注册不会复活已停止的查询。

### 批次 6c 落点

- 每个终端服务持有自己的 PTY 路由、启动缓冲、连接和页签状态。原生监听及 PTY 调用走 `host.terminal`，保留单次订阅、早到输出回放及页签重挂接管。
- 底栏与退出检查由终端插件注册。关闭项目只收尾对应项目创建的页签，窗口关闭与更新安装等待终端收尾，卸载释放监听并清理迟到启动的进程。

### 批次 6d 落点

- 工作流插件持有项目快照、查询代际、自动刷新和入口命令提交。CLI 经 `host.process` 执行，状态读取保留 `next --peek`，换项目和释放时作废旧结果并清理节流计时器。
- 工作流通过项目服务订阅前台活动并检查项目归属。提交和排队由项目服务按明确会话目标执行。
- 右栏、总览、会话时间线及工作流绑定由插件注册，原有挂载和向导草稿行为保留。

### 批次 6e 落点

- 技能服务持有扫描代际、安装任务、进度与结果。安装器通过 Agent 服务查找能力，厂商专属路径与安装规则保留在增强。卸载等待已开始的安装，并忽略迟到的进度。
- 设置中的安装器由插件注册。聊天候选使用技能服务筛选 Agent 已提供的调用项，标准 ACP 命令仍由会话能力提供。

### 9d Host 后端与开发桥资源
