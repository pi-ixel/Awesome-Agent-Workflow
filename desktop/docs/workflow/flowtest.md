# 工作流快速复测

改完工作流相关代码（引擎、节点会话、面板、工作流条……）后，用专门的复测工作流「AAW 快速复测」把各个环节走一遍。它每一步的活都很小（几行文字文件），一轮几分钟；每个检查点都能稳定触发，不靠运气。

- 源码：`workflow-engine-rs/testdata/aaw-flowtest/`（不随应用发布）
- 基线测试：`workflow-engine-rs/tests/flowtest_definition.rs`——编译 0 条提醒，两个起点按设计走完。改格式或引擎后它先得通过。
- 产出文件只写在项目的 `trial/flowtest/` 下，每次运行覆盖。

## 准备

1. 用独立的测试实例，不碰自己日常用的应用（端口 1420、`%APPDATA%\com.aaw.desktop`）：identifier `com.aaw.desktop.flowtest`，前端端口 1430，调试端口 9334。
2. 装复测工作流（改过 `testdata/aaw-flowtest` 后重装）：

   ```bash
   node scripts/flowtest-install.mjs
   ```

3. 第一次装、或检查脚本改过后：工作流 →「我的」→ AAW 快速复测 → 查看脚本后点「我已查看，信任这些脚本」。
4. 换引擎时先放好新文件再结束旧进程（应用会自动拉起，拉起时用的是磁盘上的文件）。

## 完整复测（起点「完整复测」）

在一个项目的新会话里输入 `/`，选「AAW 快速复测 · 完整复测」，写一个主题（如「水果」）回车。

| 环节 | 怎么触发 | 看什么 |
|---|---|---|
| 开场白 | 每一步开始 | 折叠的「工作流给 Agent 的说明」里：工作流 / 阶段说明、这一步、必读清单（只列 `reads` 写的名字）、要交的结果字段；**没有**整个运行的变量清单 |
| 等你回复 | 「确认标题」在会话里问标题 | 会话、工作流条、侧栏、面板卡片都说「等你回复」；等待时长随时间走 |
| 等你确认 | 回复标题后，去向「开始制作」要确认 | 面板横幅「…之前需要你确认」，运行列表「等你确认」；放行后继续 |
| 并行子流程 | 「制作卡片」两张并行 | 两个实例各一个会话；画布子流程卡片「已完成 n / 2」 |
| 换工位共用会话 | 「整改清单」与「汇总清单」同一角色 | 整改在汇总的会话里进行，收到的是整改这一步的新工单 |
| 同一工位再次触发 | 「评审清单」第一次必判整改（清单故意没有 END 行），整改后回到评审 | 复核在评审员原来的会话里进行，只收到一句返工提示（第 2 次），Agent 用 `get_workflow_step` 查工单 |
| 脚本节点 | 「检查清单格式」 | 结果显示合格、行数 |
| 工作流条 | 打开任一节点会话 | 只说本步骤：名字、轮次、它自己的状态（做完就是「已完成」），不替整个运行说话，没有阶段胶囊 |
| 完成 | 「交接」 | 运行「已完成」，总结里有交接说明 |

## 阻塞复测（起点「阻塞复测」）

选「AAW 快速复测 · 阻塞复测」，随便写个运行标题回车（这个起点没有输入，但要标题才能开始）。唯一的一步会要求停下。

| 看什么 |
|---|
| 运行列表、侧栏分组、会话状态卡都说「已阻塞」（不是「失败」） |
| 面板横幅：「在「阻塞演练」之后停下：演练要求停下」，下一行是处理办法 |
| 画布上「阻塞演练」卡片是「已完成」，卡片下写「之后停下：演练要求停下」 |
| 这一步会话里的工作流条说「已完成」，不提运行阻塞 |
| 窗口不在前台时有系统通知「工作流停下了，等你处理」 |

## 运行停着与引擎重启

在完整复测停在「等你回复」时做：

| 操作 | 看什么 |
|---|---|
| 结束测试实例的引擎进程（只结束路径属于测试实例的那个） | 面板出现「工作流服务意外退出」，引擎自动拉起后约 1 秒内自己收起 |
| 停止运行，过几分钟再继续 | 停着的那段不算进「等你」的时长；停着时卡片显示「用时」并停在停下那一刻 |

## 改了复测工作流之后

1. `workflow_service check workflow-engine-rs/testdata/aaw-flowtest` 0 条提醒；
2. `cargo test --test flowtest_definition`；
3. 重装（见「准备」），脚本变了要重新信任；
4. 这份清单跟着更新。
