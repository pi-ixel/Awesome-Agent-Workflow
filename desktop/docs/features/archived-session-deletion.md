# 归档会话彻底删除

仅支持 CodeAgent 已归档会话。归档管理页可以单条删除或进入「批量选择」。确认后删除 CodeAgent 历史及附属数据，并清理 AAW 对应的会话快照、图片、草稿、批注、待发队列、标题、归档与侧栏状态。独立的历史用量统计保留。

「全选当前筛选结果」包括折叠项目里的匹配会话。更改搜索或项目筛选会清空当前选择。确认框列出会话数量及项目路径，后续加入归档的会话需重新选择。批量任务由 Project 会话服务逐项处理，关掉设置页后继续。归档管理页展示进度及成功、失败数量，失败条目保留原因和重试入口。

## 能力边界

UI 调用 Project 会话服务。批量入口逐条复用单条删除。Project 负责状态核验、关闭空闲运行时与本地数据清理。Agents 通过可选的 `deleteSession` 能力处理厂商差异，Host 适配层调用原生命令。

仍被定时任务或工作流引用的会话拒绝删除。运行、恢复、打开过程中或存在待审批、待发消息时拒绝删除；已打开且空闲的会话自动关闭并等待写入收尾。

## 执行与恢复

删除记录依次进入 `prepared → source → local → done`，在执行相应阶段前持久化。删除失败保留阶段和错误，可在归档页重试。本地清理阶段从该阶段重试。启动时在任务引用注册之后恢复没有错误的已开始操作。已失败操作等待用户重试，重启前未开始的批量条目需要重新确认。

所有阶段的持久化记录均阻止重新打开、取消归档以及迟到目录响应重新发布该会话。原生会话数据还写入永久删除标记，拒绝迟到写入和旧版历史迁移。

CodeAgent 删除直接调用核验后的原生文件清理入口。首次找不到历史时保留归档及会话数据。已有有效原生删除记录时，可以核验并清理计划中的残留。

原生层从固定的 `~/.cac/projects` 根目录定位目标，优先以首条 `system/init` 记录的会话 ID 与工作区核验归属。缺少 `init` 时，删除流程要求项目目录名匹配 CodeAgent 的工作区 slug，并逐行核验完整 JSONL。至少一条 `user`、`last-prompt` 或 `queue-operation` 记录须通过顶层 `sessionId` 匹配目标。文件内出现的顶层 `sessionId` 和 `cwd` 也都须匹配。该兼容规则仅用于永久删除。

删除流程持久化文件及附属目录身份，供中断后重试。歧义目标、变化后的历史、符号链接、Windows 重解析点与仍被外部进程使用的会话均拒绝删除。文件操作仅限已核验的会话历史及同名附属目录。

## 验证

- 架构测试约束批量复用单条服务、原生调用边界及零 CLI 启动。
- 协调器测试覆盖批量顺序、部分失败、恢复范围、并发合并、持久化失败、任务归属、空闲收尾、配置别名及迟到目录响应。
- 原生临时目录测试覆盖首次缺失、目录联接、活跃进程与陈旧 PID、身份变化及部分删除重试。
- 浏览器测试覆盖单条与批量确认、项目范围、进度、失败保留及重试。

## 无需 CodeAgent 的界面演示

运行 `npm run dev` 后访问 `/tests/visual/sessionDeletionDemo.html`。演示使用真实设置页和归档组件，模拟两个项目的五条会话；存储仅在内存中，不连接 Agent 或操作真实会话文件。

「统一 Desktop 字体与图标缩放」可正常删除；「修复归档会话的标题丢失」首次模拟文件占用；「清理旧版图片会话缓存」首次模拟本地清理失败；「每晚接口巡检的历史会话」模拟仍被定时任务引用。失败后再次删除可体验重试，刷新页面或点击「重置演示」恢复初始数据。`?theme=light` 可直接打开浅色主题。
