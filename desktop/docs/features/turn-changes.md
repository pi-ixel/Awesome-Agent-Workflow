# 会话整轮工作区变更

会话按用户消息划分统计段：打开本地项目时后台建立工作目录索引，发送时记录当前版本，在轮次结束、引导消息切段或会话中断时采集结束状态。面板比较两次内容，展示整轮净 diff；本轮开始前已有的未提交修改和未跟踪文件属于基线，不会被当作本轮新增修改。

## 使用与界面

Diff 卡位于所属轮次回复末尾，仅在该轮结束且存在已确认的净变更后呈现；无最终文字回复的中断轮次也可显示。执行中、准备基线和采集收尾不显示卡片或「正在计算」状态；无变更、净变化归零、无可核实变化和无快照的旧会话不显示空框。

每个会话只显示最近一张非零 Diff 卡。用户提交下一条消息即永久锁定旧卡的「撤销」与「恢复」，不判断 Agent 是否接收，也不因发送失败解锁。新一轮结束且产生真实净 Diff 后，旧卡消失；新一轮纯聊天或净变化为零时，旧卡保留在原回复下，只供查看。首版不提供历史选择或历史入口。

普通消息和引导消息均以发送边界分段。引导消息提交后，原生层用同一份采样封存上段，并作为下段基线，撤销下段会保留引导前的改动。排队本身不新建统计段。上一轮采集在后台收尾，队列可以发起下一轮。

已连接、可以立即发送的会话，以输入框提交到写出 ACP `session/prompt` 不超过 500 毫秒为回归门槛。快照流程从提交计时，锁定旧卡和准备基线共用前 400 毫秒，确认发送边界最晚可等到第 475 毫秒。首次准备期间可以输入。准备完成后启用发送；建立基线失败会保留错误并允许重试。发送边界无法安全落盘时提示重试。首条消息仍需等待 Agent 返回 `session/new`，结束当前执行后才发送的队列消息从实际出队时计时。

原生只接纳与实际发送边界对应的基线。新消息的工作区写入可能已经开始时，前一轮仍保留执行结局，同时将无法确认的 Diff 标为不可用。

卡片采用 16px 圆角的轻量成果样式，摘要突出文件数，增删统计置于下一行，操作在右侧成组；文件列表以选中底色区分当前项，减少重复分隔线。默认收起，可以展开为文件列表与差异视图，也可以放大审阅。宽度跟随回复正文，内嵌内容区固定 390px；字体、按钮和行高复用 Desktop 语义尺寸，不按容器缩放。双栏横向滚动独立、纵向同步，换行时对应行高度一致。切换统一视图与双栏时保持在同一处差异。内嵌和放大视图保留文件、对比视角、换行与阅读位置。

记录保存到 Desktop 应用数据目录，按工作目录、Agent 与会话隔离。删除会话时一并清理对应记录。历史列表使用独立摘要，展开或放大卡片时读取该轮 Diff 正文。缺少摘要的旧记录保留在磁盘，并从 Diff 卡列表略过。历史列表和发送前准备均不回填旧摘要。重启时，发送标记仍可定位最后一次确认发送的轮次，用于恢复中断的快照。历史回放只在提问对应关系明确时保留本地身份，重复文本无法对齐时不会猜测关联。

## 覆盖范围与不完整结果

采集普通工作区文件，不依赖 Git HEAD、Git 状态或工具事件。标准 ACP diff、编辑工具位置、子代理工具和显式移动信息补充证据；仅在删除旧路径与新增新路径同时得到确认时采用可靠的移动关系，不做相似度猜测。

同一工作目录的会话共用一份文件索引。先监听再扫描，发送与轮末通过目录事件确认此前的写入已到达，按变更路径更新索引；文件夹移动时核对整个子目录。轮次记录保存版本号，结束时只取两个版本之间变化过的文件。单文件原文上限 256 KiB。大文件流式校验限时 250 毫秒。二进制、非 UTF-8、大文件和链接仅提供可确认的状态。采集期间变化、读取失败和达到预算会记录采集缺口。行级比较中段超过 1,200 行时不宣称精确增删行数。长差异只渲染可见行和相邻缓冲行，可直接滚动到末尾。未修改的上下文默认折叠，可手动展开。

默认跳过 `.git`、`node_modules`、`target`、`dist`、`build`、`.venv`、`venv`、`__pycache__`、`.next` 和 `coverage`。工具报告项目外或跳过目录中的编辑时，保存采集缺口。卡片不显示全局「不完整」徽标和概括提示，具体文件的查看与撤销限制就地说明。统计不完整不能等同于零变更；总行数只累计可比较的部分。

采集记录各目录的枚举范围。其他子目录超限时，仍能确认已完整枚举目录中的新增、修改和删除。某文件只出现在一次采集中，且另一侧未完成枚举，不能证明它发生了变化：这类采集缺口仅保留诊断信息，不进入文件列表或变更总数。旧记录中此前混入的未知采集项也不再显示为变更。

只有本轮明确的编辑、写入、删除、移动和标准 ACP diff 才补充写入证据，读取或搜索的位置不是写入证据。有写入证据但前后内容不全的路径单独保存在 `unverified`，通过「待核实」查看，不计入「全部」及净变更文件数。已还原到原内容或本轮创建后又删除的文件，两者均不计入。缺少基线且没有已确认净变更时不显示 Diff 卡；与真实变更并存的待核实项只中性展示已保存内容，不生成绿色新增 diff。

同目录任务可以并行执行，但结果只能归于采集时间窗口，可能包含其他任务或用户的修改。重叠任务会标记归因不确定，但不阻止还原。

## 撤销与恢复

首版提供按文件和全部「撤销」，将文件恢复到本轮开始时的实际内容：删除本轮新增文件、重建本轮删除文件，可靠重命名同时校验两个路径。不提供逐块操作或接受变更。「恢复」是撤销的反向动作，将最近一次撤销的文件恢复为 Agent 修改后的状态。

撤销复用 Desktop 危险操作确认框，默认焦点为取消。写入前检查整批文件是否仍等于最终采集版本，发现后续修改就整批拒绝；每次实际写入重新校验，Windows 通过文件句柄共享模式阻止其他写入和删除。新消息后的锁定在界面、服务与原生层同时执行；其他会话的消息不锁定当前会话，但文件版本冲突仍会拒绝覆盖。

多文件写入并非文件系统事务。中途异常会停止后续写入，持续提示已完成、失败和未执行的文件，并保留安全部分的恢复入口。操作前先保存恢复日志，异常退出后重新核对实际内容，保留无法安全确认的备份，拒绝覆盖未知版本。

每轮只保留最近一次实际撤销的恢复记录，跨重启保留。全部撤销成功后自动收起同款卡片，显示已撤销并保留「恢复」及查看 Diff；历史 Diff 内容不因工作区归零而消失。关闭成功提示也不会移除恢复按钮。异常提示复用 `Callout`，详情包含文件结果，支持查看当前文件和重新检查版本；重新检查不会写入工作区。

## 实现与验证入口

业务由 `project/conversation/changes` 持有，通过 `host.turnChanges` 调用 `src-tauri/src/turn_changes.rs`。请求契约位于 `src/contracts/turnChanges/`。采样和记录写入按工作区串行，不同工作区独立执行。提交和发送边界使用短锁，只有可能写入项目文件的路径持有相同的保护锁。诊断的 `turn_changes` 模块记录原生请求排队及操作耗时。

- 原生测试覆盖脏基线、净零变化、局部采集缺口与单个 Hello World、可靠移动、版本冲突、部分失败和操作恢复；新增引导切段只采样一次、撤销下段保留上段、纯聊天及发送失败的永久锁定、断联和重启补算后冻结历史。
- 会话测试覆盖发送前基线、连续任务、引导切段、同步锁定、消息身份绑定的收尾、断联封存、采样失败，以及仅轮末非零 Diff 替换展示位。
- 浏览器测试挂载真实回复组件及前台投影，覆盖卡片位置、空框隐藏、执行及采集过程隐藏、只读旧卡保留和轮末替换、撤销后收起及恢复、三态审阅、独立横向滚动、尺寸稳定和采集缺口不混入统计。
- 开发模式下访问 `/tests/visual/turnChanges.html` 可查看真实组件的不同状态。该页面使用隔离演示数据；正常会话使用原生快照与真实文件操作。
- Windows 下在 `desktop` 运行 `npm run test:prompt:native`。用例启动隔离的 Desktop、WebView2 和本地测试 Agent，启用内置浏览器，先建立一轮会话，再分别通过发送按钮和 Enter 提交。计时从输入框提交事件开始，到子进程从 stdin 读到对应的 `session/prompt` 为止；两个入口各自超过 500 毫秒即失败。首轮耗时单独输出。
