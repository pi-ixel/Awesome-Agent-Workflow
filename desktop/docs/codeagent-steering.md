# 主对话框引导

## 范围与入口

只有 CodeAgent 适配器声明 `supportsSteer`；收养的工作流会话、外部独立会话均不开放。
“会话与审批 → 交互行为”按当前 Agent 的能力显示，提供与信息流设置相同的动画预览卡片。
偏好按 Agent ID 在本机保存，默认排队，切换 Agent 不删除偏好。输入框直接使用设置中的交互行为。

选择引导后，按回车或点击发送即可提交。设置页说明当前执行可能被中断，输入框只显示处理进度。审批或表单挂起、会话未建立、连接恢复期间保留草稿。

## 投递与恢复

1. 将文本与附件暂存在原会话。引导记录不进入普通排队列表，持久化失败时不发送取消通知。
2. 请求标准取消，等待当前 prompt 真正结束。收到 `cancelled` 后延迟 1 秒；收到 `end_turn` 则直接进入补发。
3. 补发之前将持久化投递状态写为 `unknown`，随后正常开启新 prompt，并在用户消息上显示“补充”。
4. 收到正常结束且有助手正文或工具活动时，清除该投递记录。切回排队模式后，由用户继续原有队列。

等待期间的新引导合并文本及附件，只取消一次；补发已经开始后，新引导启动下一次取消流程。普通排队消息不能在补发间隙抢先发送。

操作使用独立身份以及 binding、session ID、存储 scope 校验；切换前台会话、断线恢复、审批插入、手动停止、强制停止通知都会撤销自动补发。
最多等待取消 30 秒后保留消息并停止自动引导。底层现有的 CodeAgent 取消宽限及强制停止机制继续有效，可能更早结束等待。

空响应、连接失败或不确定的执行结果不会自动重试。可通过单独的「取回草稿」恢复文本和附件。执行结果不确定时先确认，再自行发送。
这实现的是取消后跟进，不是原生 ACP 实时注入，也不回滚已经执行的命令。

## 验证

- `tests/plugins/project/conversation/steering.test.ts`：持久化先于取消、自然完成竞态、延迟补发、附件合并、多次引导、审批、断线、强停竞态、重启、空响应与手动停止。
- 会话输入、设置页及队列持久化测试覆盖直接提交、Agent 隔离、旧队列暂停、取回草稿与禁止自动重放。
- `tests/visual/interaction.pw.ts`：浅色/深色、900px/390px、减少动态效果与预览卡选择。

当前开发环境的 PATH 未找到 CodeAgent；真实模型及长命令中断仍需在安装了 CodeAgent 的环境验收。
