# 主对话框引导

## 范围与入口

只有 CodeAgent 适配器声明 `supportsSteer`；收养的工作流会话、外部独立会话均不开放。
“会话与审批 → 交互行为”按当前 Agent 的能力显示，提供与信息流设置相同的动画预览卡片。
偏好按 Agent ID 在本机保存，默认排队，切换 Agent 不删除偏好。输入框直接使用设置中的交互行为。

选择引导后，按回车或点击发送即可提交。设置页并排演示排队和引导时的输入框。保存、等待取消及补发在后台完成。审批或表单挂起期间保留草稿。

## 投递与恢复

1. 将文本与附件暂存在原会话。等待首次回传的引导在输入框上方显示，可取回文字和附件进行编辑、删除或停止等待，持久化失败时不发送取消通知。
2. 当前轮取得发送名额且收到同一会话首个非空正文、思考或工具调用后，才请求标准取消。等待首次回传期间继续排队。当前轮先自然结束则跳过取消。取消发出后才开始 30 秒计时。收到 `cancelled` 后延迟 1 秒；收到 `end_turn` 则直接进入补发。
3. 补发之前将持久化投递状态写为 `unknown`，随后正常开启新 prompt，并在用户消息上显示“补充”。
4. 收到 ACP 最终回合响应时，清除该投递记录。轮次结束原因照常显示。切回排队模式后，由用户继续原有队列。

首条消息独立发送。建连和首次发送期间按回车提交的补充，按提交顺序在待发队列暂存，文本和附件合并为一次引导。同一首轮开始收到 Agent 正文、思考或工具调用后才发取消。如果首轮先自然结束，直接发送补充。审批或表单介入时只把补充放回输入框。首条尚未确认开始处理就建连失败或断线时，首条和补充按原顺序放回输入框，由用户重发。

等待期间的新引导合并文本及附件，只取消一次；补发已经开始后，新引导启动下一次取消流程。普通排队消息不能在补发间隙抢先发送。

操作使用独立身份以及 binding、session ID、存储 scope 校验。切换前台会话、审批插入、手动停止或收到强制停止通知时撤销自动补发。断线则按当前投递状态恢复。
最多等待取消 30 秒后保留消息并停止自动引导。底层现有的 CodeAgent 取消宽限及强制停止机制继续有效，可能更早结束等待。

在首次有效回传前断线或失败时，补充消息保留在待发队列供手动处理。取消已经发出后的断线继续按既有投递状态恢复。已尝试发送且结果未知，或重启后发现未完成的引导时，客户端把原文及附件追加到当前草稿之后，并在输入框内提示。由用户决定是否发送。Agent 已返回 `cancelled` 时，照常发送补充，上一条可在信息流手动重发。
这实现的是取消后跟进，不是原生 ACP 实时注入，也不回滚已经执行的命令。

## 验证

- `tests/plugins/project/conversation/steering.test.ts`：持久化先于取消、自然完成竞态、延迟补发、附件合并、多次引导、审批、断线、强停竞态、重启、空响应与手动停止。
- 会话输入、设置页及队列持久化测试覆盖直接提交、Agent 隔离、旧队列暂停、取回草稿与禁止自动重放。
- `tests/visual/interaction.pw.ts`：浅色/深色、900px/390px、减少动态效果与预览卡选择。

当前开发环境的 PATH 未找到 CodeAgent；真实模型及长命令中断仍需在安装了 CodeAgent 的环境验收。
