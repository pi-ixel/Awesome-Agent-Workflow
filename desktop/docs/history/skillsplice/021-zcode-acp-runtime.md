# 021 ZCode 工作流引擎移植与验证

## 当前结果

已在隔离目录中移植 ZCode 的工作流编译、调度、运行宿主与 SQLite 记录，并接入 AAW Desktop 现有 ACP 会话实现。现在可以从 TypeScript 工作流脚本启动运行，在独立进程中执行流程，通过 ACP 调用 Agent，并把节点状态及结果写入数据库。入口和来源见 [实验目录](../../poc/zcode-acp-engine/README.md)。

这是运行引擎的移植验证，不代表已经接入 Desktop，也不代表 AAW dev 工作流已在新引擎上完成迁移。当前不涉及旧的阅读副本和 UI 呈现。

```text
工作流脚本 + 输入
       ↓ 静态分析、编译
独立运行进程 → ZCode 调度器 → ACP Agent（支持提问回调）
                         ↘ 宿主提供的脚本执行器
       ↓
SQLite：运行、节点、事件、Agent 会话
```

## 已实现的运行边界

- 流程脚本可表达顺序、条件、有界循环和并行；调用 Agent 或由宿主授权的命令。宿主命令执行器使用可执行文件白名单并直接传参，不经 shell。流程进程隔离不是操作系统安全沙箱。
- ACP 交互复用 AAW 的会话与传输；iCode 提问交给宿主回调回答。带类型的 Agent 返回值按工作流推导出的 JSON Schema 校验，校验失败不会当作成功。角色 `system` 内容目前作为首条用户提示的前缀传入，不是 ACP 系统角色。
- SQLite 保存流程脚本、输入快照、执行节点、事件和会话标识；恢复时检查脚本、输入和运行配置是否一致。已完成节点可重放；支持 `session/load` 的 Agent 可恢复原会话，加载失败不会悄悄创建新会话。
- 同一运行使用数据库租约防止并发执行。宿主进程异常退出后，需确认租约持有进程已退出并记录原因，才能解除租约；运行中的 Agent 或命令动作仍会被标记为结果不明并阻止续跑。只有在调用方独立核验完成结果和证据后，才可登记结果、留痕并继续；程序不会验证证据真实性，也尚未提供确认“未执行”后重试的操作。
- 脚本及输入参数会写入数据库，并用于生成临时运行入口；正常退出清理入口文件，进程崩溃可能遗留。不要把凭据放进脚本或运行参数。数据库还可能包含提示词和 Agent 输出，需要按实际敏感程度管理。

运行配置目前只通过调用参数传入。该实验依赖本机 Node 的 `node:sqlite`，尚无面向 Desktop 的数据库迁移、版本管理与完整生命周期管理；恢复租约的进程检查仅适用于同一台机器，也受到 PID 复用影响。

## 验证证据

1. [真实 iCode 运行](../../poc/zcode-acp-engine/evidence/runtime-real/result.json)：脚本经编译及独立进程调度，真实 ACP Agent 完成一次提问、两轮结构化检查和修正，命令节点运行模拟 CodeCheck；节点记录写入 SQLite。问题回答和检查结论均为预设测试数据，不是实际业务评审。
2. [真实会话恢复](../../poc/zcode-acp-engine/evidence/runtime-resume/result.json)：一次运行停止后重新打开记录并启动 ACP 进程，加载同一个 iCode 会话，获得中断前记录的测试暗号。两次运行在同一 Node 宿主进程内发起，不能据此证明所有 Agent 的跨进程恢复能力。
3. 14 项受控测试通过，覆盖顺序、并行、分支、循环、结构化输出、真实命令、取消恢复、进程被杀后的租约恢复及结果核验、命令超时和无效输入。测试用例与运行命令见实验目录；其中 ACP 故障测试使用受控替身。相关 TypeScript 入口和测试通过类型检查。
