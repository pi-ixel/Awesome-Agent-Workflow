# 020 ZCode 调度核心与 ACP 移植验证

> 状态：隔离验证通过。ZCode 调度核心可通过 AAW ACP 会话驱动一段受控流程；尚未形成通用工作流引擎或接入 Desktop 页面。

> 后续进展：编译器、运行宿主和 SQLite 记录的移植及验证见 [021](021-zcode-acp-runtime.md)。本文保留当时的实验范围。

## 验证范围

从 ZCode 本地仓库提交 `a60ba6a7e5a06742270ca605f5d2cc2766afa7e1` 复制调度核心及必要依赖，在 [实验目录](../../poc/zcode-acp-engine/README.md) 中接入 AAW Desktop 的 `AcpSession`。以脚本显式调用引擎，执行以下通信测试：

```text
设计 Agent（ACP 提问并收到测试答案）
    ↓
检查 Agent → revise
    ↓
设计 Agent 修正
    ↓
原检查 Agent → pass
    ↓
受控模拟 CodeCheck 子进程 → 完成
```

检查结论按轮次预置，问题答案是测试数据。该流程用于验证引擎接线，不评价真实设计或扫描能力。

## 验证结果

| 项目 | 结果和证据 |
|---|---|
| 核心移植 | 调度核心源码副本在 AAW Desktop 的 Node/TypeScript 环境中运行；没有调用 ZCode 产品服务。 |
| ACP Agent | 真实 iCode 0.26.0 经 Desktop 的 ACP 客户端完成设计、检查和修正动作。 |
| 用户问答 | 真实 iCode 发出一次 ACP 提问，测试驱动提供预置答案后继续。取消提问不会被实验驱动视为成功，另有受控测试。 |
| 会话复用 | 同一次运行中设计和修正共用设计会话，两次检查共用检查会话；通过事件中的 session id 与节点 actor 序号核对。 |
| 并行 | 两个受控 ACP Agent 同时等待各自答案，随后分别完成；这是受控 ACP 测试，非两路真实模型并发测试。 |
| 流程事件 | 引擎产生节点派发和结束事件，并通过 driver 回调向宿主输出。尚未连接 Desktop UI。 |
| 脚本节点 | 引擎的 `world-run` 调用实际启动受控 Node 子进程，返回模拟 CodeCheck 结果；不是正式 CodeCheck。 |
| 中断 | 受控实验确认：原引擎对中断时仍是 `running` 的动作会重新派发。实验性恢复检查在重新构造引擎前发现该状态并拒绝继续；尚未接入持久化恢复入口。 |

[真实 iCode 运行记录](../../poc/zcode-acp-engine/evidence/real-icode/result.json)保存节点、会话和精简事件。验证使用内存 journal；运行结束后的 JSON 是证据导出，不是可供引擎恢复的持久化数据库。

受控测试四项通过：完整通信和有界循环、并行问答、取消问答、在飞动作中断。实验源码与测试通过 TypeScript 静态检查。

## 仍需完成的工作

1. **流程定义与图形表示**：当前流程和分支写在实验脚本中，调用的是引擎低层 API。尚未移植 ZCode 的脚本编译器、harness，也没有实现 AAW 可编辑模板、嵌套关系或流程图映射。
2. **持久化与恢复**：尚未实现 SQLite journal、进程重启后恢复、ACP 原会话加载和完整的结果不明核验。当前 guard 只在受控测试中调用，不是通用恢复方案。
3. **ACP 与权限**：目前的结构化问答使用 iCode 的 ACP 方言；权限请求在实验里一律取消。不同 ACP Agent 的能力协商、权限回传和工具配置仍待接线。
4. **AAW 业务接入**：尚未在本实验连接问题池 MCP、设计知识、产物引用、真实 CodeCheck 或完整 dev 流程。`mcpServers` 可以传给 ACP 会话，但未验证业务 MCP 调用。
5. **输出契约与隔离**：实验只处理文本回复，按受控 JSON 识别检查结果；尚无通用结构校验、可信的动作边界或生产级资源清理保证。

## 判断

ZCode 核心与 ACP 的接口方向可行，可以继续作为 AAW 工作流引擎的移植候选。正式选择仍取决于：流程定义能否自然映射到可编辑图形、恢复机制能否满足 AAW 的副作用边界，以及抽取编译与存储等依赖后的维护成本。
