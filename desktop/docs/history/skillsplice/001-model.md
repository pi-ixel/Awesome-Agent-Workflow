# 001 SkillSplice 核心模型

本文承接[概览](000-overview.md)，定义架构基线中的核心概念及其关系。

## 核心模型

| 概念 | 定义 | 职责 |
|---|---|---|
| **Unit** | 自包含、可复用的能力定义。 | 将流程、知识与对外契约封装为一个整体。 |
| **Call** | 组合流程中对一个 Unit 的一次引用和使用。 | 表达调用位置，以及本次调用需要的配置和绑定。 |
| **Link** | Call 之间的关系。 | 表达执行依赖、条件及必要的交接约束。 |
| **Port** | 显式声明的数据接口。 | 在需要时描述输入、输出及类型约束。 |
| **Resource** | Unit 使用的知识资源或逻辑工作资源。 | 描述执行所需的知识和工作环境。 |
| **Verification** | Unit 的完成条件和验收方式。 | 判断 Unit 能否被认定为成功，并关联验收依据。 |

Unit 可以是原子的，也可以通过 Call 和 Link 组合其他 Unit；组合结果仍然是 Unit，可以继续被上层引用。原子 Unit 不要求继续拆分，内部可以由 Agent、程序、工具或人工完成工作。

理解这一模型时，可以将 Unit 类比为带知识和契约的函数、Call 类比为函数调用。Unit 可以读取或修改共享工作资源，也可能产生外部副作用；这种类比不要求 Unit 是纯函数。

### 定义、调用与执行

| 层次 | 含义 |
|---|---|
| Unit 定义 | 能力是什么，包括流程、知识和契约。 |
| Call | 某个组合流程在哪里使用一个 Unit。 |
| Call 执行 | 某次运行中，一个 Call 的实际执行及其结果。 |
| 执行尝试 | 一次 Call 执行中的某次尝试；失败后可能根据规则产生新的尝试。 |

同一个 Unit 可以被多个 Call 引用，一个 Call 也可能在不同运行或动态展开中产生多个执行。Agent Session 结束、某次尝试结束和 Unit 验收成功是不同事实。执行与尝试是运行时概念，不增加同层级的定义原语。

## 定义、模板与资源

### 不可变 Unit

一个 Unit ID 对应一份确定的定义。其流程、执行指导、知识、对外契约和内部 Unit 引用共同构成能力内容；这些内容变化时，产生新的 Unit ID。内部引用和属于 Unit 定义的知识必须指向确定版本，不能因被引用内容更新而使已有定义悄然变化。

修改已确定的 Unit 采用复制并形成新定义的方式。用户决定哪些引用使用新定义，其他模板和引用不自动更新。如果内部 Unit 的引用发生变化，包含该引用的上层 Unit 定义也需要形成新的身份。

固定定义只保证定义及其固定依赖不漂移，不保证不同模型、外部资料或工作环境下得到相同结果。

### 模板与运行实例

模板是可复用的流程定义；运行实例是基于某个确定定义启动的一次执行，拥有自己的资源绑定、状态和记录。

v0.1 承诺支持模板修改：修改后的定义可由用户选择用于后续创建的运行实例。已经启动的实例不会因模板修改而自动改变。**运行中修改、迁移或将既有实例切换到新定义，不作为 v0.1 的对外功能承诺。**

### 知识与工作资源

必需知识受控加载；参考知识按需获取。属于 Unit 定义的知识固定版本，更新知识后只有显式形成并采用新定义才会影响该能力。运行时获取的外部资料属于执行上下文，其使用及必要引用应可追溯。

Unit 声明逻辑工作资源需求，由运行实例绑定实际资源。例如，代码开发 Unit 声明需要工作区；实例启动时绑定具体仓库和目录。仓库内容变化不要求创建新 Unit。资源需求与实际绑定应可检查和记录。

知识、输入和上下文不自动扩大执行授权。任务范围和权限由用户与执行宿主确定；执行者读取一份资料，不意味着资料可以自行修改这些边界。

### Port 与共享上下文

Link 负责执行关系；Port 在需要显式交换数据时定义接口；Resource 提供知识和工作环境。多个 Unit 可以共享工作区或其他已绑定资源协作，不强制通过 Port 传递全部工作数据。需要明确交接的数据，应通过相应接口和绑定表达。
