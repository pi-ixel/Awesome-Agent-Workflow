当前代码只将大于 `len(input)` 的光标限制到上界，随后使用 `input[:cursor]`。依据代码，负数光标会触发 Go 切片越界 panic；这是代码分析结论，本方案尚未单独运行负数输入的复现程序。

## 2. 需求

### 目标

为命令补全服务处理非法的负数光标位置，避免请求触发 panic，并保持现有正常位置和上界处理行为。

### 行为契约

1. 对任意负数 `Cursor`，按 `Cursor = 0` 处理；返回结果应与相同输入、零光标的结果等价。
2. 对大于 `len(Input)` 的 `Cursor`，继续按 `len(Input)` 处理。
3. 对 `0 ≤ Cursor ≤ len(Input)` 的输入，保持原有补全行为。
4. 对上述情况，返回的替换区间满足 `0 ≤ ReplaceFrom ≤ ReplaceTo ≤ len(Input)`；不改变 `CompletionRequest`、`CompletionResponse` 的字段或方法签名。

这里沿用当前 Go 服务以字符串字节长度处理位置的现有约定。Unicode 字节位置与前端字符位置的一致性不在本次修改范围内，不能将本次测试解释为已解决该问题。测试用例使用 ASCII 输入，以隔离光标上下界行为。

本任务不改变命令数据库、补全排序、选项匹配规则、前端 UI 或 Wails 接口。结果等价比较应忽略建议项顺序，按建议项内容的多重集合比较，以避免将非稳定顺序误判为下界错误。

## 4. 功能测试用例

各用例创建有效命令数据库和补全服务；比较建议项时按第 2 节约定忽略顺序。每次调用应正常返回、不发生 panic；响应区间均满足第 2 节约束。

| ID | 输入和步骤 | 预期 |
|---|---|---|
| TD-01 | `Input="tar -c"`，分别以 `Cursor=-1` 和 `Cursor=0` 调用。 | 两个结果的替换区间和建议项多重集合等价；`ReplaceFrom=0`、`ReplaceTo=0`。 |
| TD-02 | `Input=""`，分别以 `Cursor=-1` 和 `Cursor=0` 调用。 | 两个结果等价，替换区间为 `[0,0]`。 |
| TD-03 | `Input="tar -c"`，分别以 `Cursor=100` 和 `Cursor=len(Input)` 调用。 | 两个结果等价，替换区间和建议项保持现有上界行为。 |
| TD-04 | `Input="tar -c"`，`Cursor=len(Input)`。 | 返回的建议包含 `-cxvf`，替换区间为 `[4,6]`。 |
| TD-05 | `Input="zgrep "`，`Cursor=len(Input)`。 | 返回的建议包含 ` -rni`，替换区间为 `[6,6]`。 |
| TD-06 | `Input="tar -c"`，`Cursor=0`，并分别检查输入中间和末尾的有效位置。 | 每次正常返回，替换区间有效；对有效位置的结果与修改前同一位置行为一致，不因新增下界处理改变。 |

TD-04、TD-05 基于现有组合补全测试扩展替换区间断言；TD-06 的修改前对照应在隔离基线副本上记录，或用能独立表达原有语义的固定断言，不能以修改后结果作为自己的预期。
