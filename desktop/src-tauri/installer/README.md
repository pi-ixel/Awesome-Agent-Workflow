# AAW Windows 安装与更新界面

`installer.nsi` 基于 Tauri **tauri-cli-v2.12.3** 官方 NSIS 模板，保留原始许可（MIT / Apache-2.0）。升级 `@tauri-apps/cli` 时需对照该版本的模板检查参数、注册表和安装行为，不能直接替换为上游 dev 分支模板。

## 共用流程

- 手动安装：品牌首页 → 安装位置（可更改）→ 安装进度 → 完成并可选启动。“更多选项”包含桌面快捷方式。
- 自动更新：已验证的同一个 setup 以 `/P /UPDATE /D=原目录` 启动，跳过交互页面，直接显示品牌进度。
- **当前 Tauri 模板的 `/UPDATE` 是覆盖更新，不先卸载旧版。** 保留其快捷方式与应用数据处理；不要增加独立卸载步骤。
- 界面显示由 NSIS 写入的真实阶段与活动进度条；没有模拟百分比或固定展示时长。
- 安装执行期间禁用关闭、取消；安装前可退出，失败后可关闭或重试。
- 深色渐变背景、自绘拖动/最小化/关闭区域，复用应用图标。首次安装可点击路径框打开系统目录选择器；更新固定原路径。

## 界面与安装内核

`ui/` 是生产界面，`prototype/` 是独立视觉演示。生产界面复用原型样式，但不加载其模拟进度脚本。

NSIS 在运行时已存在的机器上提取同包 `desktop.exe` 到临时目录，以 `--installer-ui` 启动独立 Tauri 界面。该模式只注册安装命令，不启动 Desktop 服务或 Agent。无 WebView2 时先运行原生引导下载/安装运行时，然后打开同一界面。引导需要联网。

界面启动同一个 setup 的 `/S /AAW-INNER` 安装内核，后者通过进程专属状态文件报告阶段，退出码决定成功或失败。内核检测到占用中的应用会报错，不强制结束进程。安装繁忙时前端和原生关闭处理都禁止退出。更新保留旧版 `/R` 的启动语义；新版助手不传 `/R`，由助手独立启动。

## 更新交接与失败

原生客户端验证签名和安装包后，启动安装目录外的 `update_handoff.ps1`。助手确认就绪，等待旧进程退出，再次核对 SHA256，然后启动 setup 并等待退出码。成功后启动 Desktop，等待 GUI 进程响应；不会因为仅创建了进程就记录成功。启动重试复用仍在启动中的进程，不重复安装。

自动更新失败时显示品牌中文对话框，提供“重试 / 查看日志 / 关闭”。手动 setup 失败时显示同样的恢复操作。失败不能保证恢复为旧版本：原有覆盖更新并非事务式安装，不承诺自动回滚。

日志：`%LOCALAPPDATA%\com.aaw.desktop\updates\last-install.log`（助手）、`setup-shell.log`（生产安装界面、阶段与退出码）、`setup-last.log`（原生引导）。日志不包含私钥或访问令牌。

## 验证

- `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/test-update-handoff.ps1`：就绪确认、退出等待、带空格路径、失败重试、校验失败不执行安装。
- `node scripts/test-installer-ui.mjs`：目录选择/取消、路径传递、安装关闭保护、错误文本转义、重试选项、最小化桥接。
- NSIS 模板变更必须用 Tauri bundler 生成真实安装包，并检查首页/进度页/失败页。
- 安装冒烟测试使用独立产品名、注册表项和 `target` 下的安装目录；不使用日常安装目录验证错误路径。
- `header.bmp` 由现有 `icons/icon.ico` 转换而来；图标更新时同步生成。
