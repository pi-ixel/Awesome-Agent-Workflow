# CodeAgent 增强：阶段 1 / 2 / 3

内置 ID 为 `codeagent`，启动命令为 `codeagent acp`。只在 `agents/builtins.ts` 注册；与 ICode 的路径配置、技能安装、历史读取和私有协议实现互不依赖。

- 设置页 Agent 列表可选择 CodeAgent，并编辑可执行路径；留空始终使用 `codeagent acp` 经 PATH 启动。自动初始化和“重新检测路径”只展示结果，用户点击“使用检测路径”后才保存绝对路径，不猜测安装目录。
- Windows 扫描不将无扩展名 sh shim 当作原生程序：只识别 `.exe/.cmd/.bat`，旧的无扩展名路径仅检查同目录这些入口；无法确认时提示选择正确文件或清空使用 PATH。Linux 保留无扩展名程序。显式路径每次启动前复检，失效时保留用户配置并报错，不静默切到其他安装。连接测试、协议自检、正常会话和恢复流程共用可选启动校验；规则只由 CodeAgent 模块解释。
- 路径检测检查存在性和支持的入口类型，不代表文件本身或 ACP 协议可用。现有“测试连接”实际启动 ACP 并握手，不以 `--version` 成功代替协议可用。
- 文本、图片、列表、历史加载均使用通用 ACP；图片由握手能力决定，load 使用标准 `sessionId`。历史回放使用现有 messageId、图片附件和 replay 作用域处理。
- 取消先发送标准 `session/cancel` 通知。CodeAgent 适配器声明 5000ms 的等待期，若原 prompt 仍未结束，通用会话层警告后终止当前连接的进程树；不会影响其他连接。正常结束、关闭或退出会撤销计时器。
- 强制停止表示进程终止，不代表工具操作回滚。现有 store 保留用户取消意图，恢复流程不自动重发该 prompt。
- 自定义命令保持纯标准 ACP，不会仅因程序名相同而自动启用内置取消策略；未填写参数时，界面根据已注册适配器提供 `acp` 默认参数。

## 阶段 2

- `dialect.ts` 是 `_meta.codeAgentCLI.toolName`、`_subagent/update` 及已知配置 ID 的唯一解释入口。只根据 Agent/Task/spawn_agent/spawnAgent 的真实工具名识别父子代理；Read、Bash、TodoWrite、AskUserQuestion 不因 kind/title 而误识别。
- 子进度按连接实例、会话和 taskId 隔离，通过明确的父 toolCallId 关联。父卡未到时暂存，历史 rawOutput.agentId 可恢复缺失关联；没有明确证据就不猜父任务。
- 展开父卡可看文字、思考与工具输入输出，失败工具明确标记。重复/乱序进度合并；父工具终态不被子进度改回运行态；完整历史参数与最终结果用于补齐空的实时 rawInput。
- 子进度缓存有界（最多 1024 个任务、每任务 500 次更新、总签名约 4M 字符）；超限保留最近展示数据并提示可到诊断查原文，不伪造 token 统计。
- 仅为已知 `model` / `mode` select 配置补充缺失的 category/name；其他配置继续按标准解析。
- 模型和模式只能选择 Agent 公布的条目，优先 set_config_option；仅在 -32601 时回退旧 set_model/set_mode。要求响应中的配置或相应通知确认目标值，空响应不算成功。响应后默认最多等 2 秒确认，断线/换会话取消等待，旧响应不能污染新会话。
- 输入区模型显示“正在确认模型”，新增通用“会话模式选择”，只展示 Agent 提供的模式；会话模式与客户端审批默认方式独立，不自动启用 bypass。
- 复用标准权限审批及表单。仅对 CodeAgent 缺省 mode、带 requestedSchema 且没有 URL 的旧表单请求补 `mode: form`；URL 和非法表单继续拒绝，跨会话表单取消。握手保持标准 `elicitation.form: {}`，未根据 issue 的文字描述擅自改为布尔值。
- 普通自定义 Agent 不启用这些私有解析；ICode 增强不被引用。标准层新增的是通用配置归一化/确认契约、子代理消息展示和会话模式操作。

## 工具输入展示

主工具和子工具在输入缺失、null、空对象或空白字符串时，由 CodeAgent 增强提供 title 展示兜底；输入区标注“操作描述（Agent 未提供输入参数）”。没有标题时显示“Agent 未提供输入参数”。兜底与原始输入分开保存，不参与 TodoWrite 等参数解析，ACP 原文日志不变。后续有效输入替换兜底，已收到的有效参数不被空更新覆盖；0、false、数组保留原值。普通 ACP Agent 不启用此策略。

## 子工具双流归属与展示

当 `_subagent/update` 明确提供子工具 ID、父 toolCallId，且父工具已确认为 Agent/Task 时，增强按连接、会话、工具 ID 将同 ID 的标准流副本并入该子工具；返回通用 absorbedToolCallIds 展示指令撤下已出现的顶层副本。标准流后续提供的参数、输出也更新子工具，不丢弃结果。父通知迟到时先保留顶层记录，确认后再撤下；只有名称相同、没有明确归属的工具继续作为主工具显示。普通 ACP 不启用此策略。缓存受现有任务和工具数量限制。

子代理详情保留消息与工具记录折叠入口，内部复用主消息流的 AssistantMessage、ThoughtBlock 和 OrdinaryToolCallCard。标准 kind/content/locations 随子工具归一化和快照保存，支持 Markdown、复制、终端输出、标准差异和文件位置；未知字段保留原始展示，不从工具名称猜种类。不虚构每条子消息的流式状态或耗时。
